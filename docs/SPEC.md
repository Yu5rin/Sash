# Sash 仕様書 v0.1 — Excelリボンエディタ

2026-11-22

## 1. 概要・目的

xlsm / xlam のカスタムリボン（customUI）を、見たまま組み立てて手で直せる単体デスクトップツールを作る。AI連携は対象外で、リボンの追加と手動編集を快適にすることだけに集中する。Graftとは独立したアプリとする。

解決したいのは、現状のリボン開発にある三つの手間である。XMLをテキストで書くしかなく構造が見えないこと、反映のたびにExcelを閉じて開き直す往復が発生すること、XMLとVBAコールバックの不整合やアイコンの用意に気づきにくいことの三つだ。

対象ユーザーは、VBAで業務ツールやアドインを作るExcelユーザー。まずは作者自身と社内での利用を想定する。対象ファイルは .xlsm / .xlam を必須とし、.xltm / .xlsb は第2弾以降に検討する。

## 2. 既存ツールとの差別化

VBA向けのリボンを現代的なビジュアルエディタで作れるツールは、まだ存在しない。既存のツールはどれも、XMLをテキストで編集するものか、VSTO専用のものだ。本ツールは、キャンバスでの編集、Excelとの即時連携、アイコンの作成で差を付ける。

| ツール | 編集方式 | VBA（xlsm/xlam） | 現状 | 足りないもの |
| --- | --- | --- | --- | --- |
| [Office RibbonX Editor](https://github.com/fernandreu/office-ribbonx-editor) | XMLテキスト（ScintillaNET）＋ツリー | 対応 | WPF / .NETで開発が継続中 | ビジュアル編集、Excel連携、アイコンの加工 |
| [Custom UI Editor（OfficeDev）](https://github.com/OfficeDev/office-custom-ui-editor) | XMLテキスト | 対応 | 2024年6月にアーカイブ済み | 保守。スキーマは2010まで |
| [VS Ribbon Designer](https://learn.microsoft.com/en-us/visualstudio/vsto/ribbon-overview?view=vs-2022) | ビジュアル | 非対応（VSTO専用） | Visual Studioに同梱 | VBAで使えない。コールバックを生成しない |
| RibbonX Visual Designer | ツリー＋フォーム | 対応 | Excelアドイン。UIは2007年代のまま | 現代的なUI、高DPI、ダークモード |

本ツールの柱は次の五つ。

1. キャンバス編集。本物のExcelのリボンに近いプレビュー上に、ドラッグで部品を置く。
2. 賢いインスペクタ。使える属性だけを出し、入力中に検証する。
3. Excelとの即時連携。ワンクリックで反映し、コールバックを同期する。
4. アイコンの作成。画像やicoから加工してそのまま設定できる。
5. 現代的な操作性。コマンドパレット、あいまい検索、ダークモード、日本語UIを備える。

## 3. 動作環境・技術構成

C#（.NET 10）をホストにし、UIはすべてWebView2（HTML / CSS / TypeScript）で描く。リボンのプレビュー、Monacoエディタ、SVGアイコン、ダークモードを少ない労力で現代的に作れるためだ。

| 層 | 担当 | 主な技術 |
| --- | --- | --- |
| UI | キャンバス、ツリー、インスペクタ、XMLエディタ、アイコンエディタ | WebView2、TypeScript、Monaco Editor |
| ホスト | ウィンドウ、ファイルダイアログ、UIとのメッセージ交換 | WinForms（外枠のみ）、WebView2 PostMessage |
| コア | OPC（zip）の読み書き、customUIモデル、XSD検証、Lint | System.IO.Packaging、System.Xml.Schema |
| 画像 | 画像/ico/SVGの読み込み、加工、PNG出力 | System.Drawing / WIC、SVGはブラウザ側でラスタライズ |
| Excel連携 | ブックの制御、VBEの読み書き、imageMsoの取得 | Excel COM（遅延バインド） |

動作環境はWindows 10 / 11（64bit）、Excel 2016以降またはMicrosoft 365。配布はself-containedの単一exeで、インストーラーは使わない。WebView2ランタイムはOS標準のものを使う。設定とアイコンライブラリは `%AppData%\Sash` に保存する。

COMは遅延バインドで呼ぶ。Interopアセンブリを同梱しないため、Excelのバージョンに依存しない。Excelが入っていないPCでも、ファイル編集だけは動くようにする。

UIの技術はWebView2で確定した（WPF、WinUI 3と比較のうえ決定）。

## 4. 画面構成

メインウィンドウは一画面で完結させる。左にパレットとツリー、中央にキャンバスとXMLエディタ、右にインスペクタ、下に問題とコールバックのパネルを置く。どのペインで要素を選んでも、他のペインで同じ要素が選択される。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Sash  集計ツール.xlam（Excelで開いています）   [Ctrl+K コマンド] [反映 F5] │
├──────────────┬───────────────────────────────────────┬───────────────────┤
│ パレット     │ キャンバス（リボンのプレビュー）      │ インスペクタ      │
│ button/toggle│  ファイル ホーム 挿入 [集計ツール]    │ 基本              │
│ menu/split   │ ┌──────┬──────────┬──────┬─────────┐  │  id   btnSummary  │
│ dropDown     │ │[集計]│□CSV出力  │[自動]│ ここに  │  │  label 集計する   │
│ editBox      │ │      │□クリア   │      │ドロップ │  │  size  large      │
│ レシピ       │ │      │□設定     │      │         │  │ 表示              │
├──────────────┤ │ 集計            │モード│         │  │  [□] アイコン編集 │
│ ツリー       │ └─────────────────┴──────┴─────────┘  │ 動作              │
│ tab 集計ツール├───────────────────────────────────────┤  onAction 実装済み│
│  group 集計  │ XMLエディタ（Monaco）                 │  getEnabled なし  │
│   btnSummary │ <tab id="tabTools" label="集計ツール">│                   │
│   btnCsv     │   <group id="grpSum" label="集計">    │                   │
│  group モード│     <button id="btnSummary" ...       │                   │
│   tglAuto    │                                       │                   │
├──────────────┴───────────────────────────────────────┴───────────────────┤
│ 問題 2 ・ コールバック 4（未実装 1） ・ アイコン 3 ・ 差分                 │
└──────────────────────────────────────────────────────────────────────────┘
```

各ペインは幅を変えられ、折りたたむこともできる。XMLを主に使う人向けに、キャンバスとXMLの上下を入れ替えるレイアウトも選べるようにする。アイコンエディタとカタログは、メイン画面の上に重なるダイアログとして開く。

## 5. 編集機能

キャンバス、ツリー、XMLの三つのビューは、一つの内部モデル（customUIのツリー）を共有して常に同期する。どのビューで変更しても、Undo / Redoは一つの履歴にまとめて記録する。

### 5.1 ファイル

- .xlsm / .xlam をドラッグ&ドロップ、または「開く」で読み込む。最近使ったファイルをホーム画面に並べる。
- customUI14.xml（2010以降）と customUI.xml（2007）の両方を扱う。新規作成時はcustomUI14を既定にし、.rels へのリレーション登録も自動で行う。
- 両方がある場合は「2010以降のExcelは14を優先する」と警告し、どちらを編集するか切り替えられるようにする。
- 保存のたびに元のファイルを世代つきでバックアップする（既定は10世代）。customUI以外のパーツ（シート、VBAプロジェクト）には一切触れない。
- リボン定義を `.sash.json` として書き出し・読み込みできるようにする。別のブックへの流用と、Gitでの差分管理に使う。

### 5.2 キャンバス

- Excelのリボンに近い見た目で、タブ、グループ、コントロールを描画する。ライトとダークの両方に対応する。
- 左のパレットからドラッグして配置する。配置できない場所ではドロップ先の表示を出さない（例：グループの外にボタンは置けない）。
- クリックで選択、ドラッグで並べ替え、Ctrl+Dで複製、Deleteで削除。グループをまたいだ移動もできる。
- large・normalのサイズ、ラベルの改行、小ボタンの3段積みを、本物に近い形で再現する。
- 組み込みタブ（ホームなど）にグループを足す場合、組み込み部分はグレーのプレースホルダーで示し、自分で足した部分だけを編集対象にする。
- 対象はリボン、クイックアクセスツールバー、コンテキストメニュー、Backstage。Backstageとコンテキストメニューは第2弾で対応する。

### 5.3 ツリー

- customUIの階層をそのまま表示する。キャンバスでは選びにくい要素（menuの中身、dialogBoxLauncher、非表示の要素）はここで操作する。
- 各ノードには、種類のアイコン、ラベル、id、警告バッジを表示する。

### 5.4 インスペクタ

- 選んだコントロールに使える属性だけを、「基本」「表示」「動作（コールバック）」「詳細」に分けて出す。
- 属性の型に合わせた入力欄を使う。列挙値はドロップダウン、真偽値はトグル、imageMso / idMsoは検索つきピッカー、imageはアイコンエディタの呼び出し。
- 「label」と「getLabel」のような静的値と動的コールバックの組は、1行の切り替えスイッチにまとめる。これで排他の矛盾がそもそも起きない。
- 属性名にホバーすると、日本語の説明と指定例を表示する。
- idはラベルから自動で提案する（例：「集計する」→ btnSummary）。

### 5.5 XMLエディタ

- Monacoを使い、XSDに基づく要素・属性の補完、エラーの波線表示、折りたたみ、整形を備える。
- カーソル位置の要素を、キャンバスとツリーでも選択状態にする（逆方向も同じ）。
- XMLの構文が壊れている間は、他のビューを最後に正しかった状態のまま表示し、上部に「同期停止中」と出す。
- コメントと属性の並び順は、キャンバスで編集してもできるだけ保持する。

### 5.6 検証（Lint）

XSDによる検証に加え、次の独自ルールを入力中に常時チェックする。結果は下部の「問題」パネルに一覧表示し、クリックで該当箇所に飛べる。

| ルール | 重大度 |
| --- | --- |
| id / idMso / idQ の重複、または未指定 | エラー |
| 静的属性と get系コールバックの同時指定 | エラー |
| image が参照する画像がファイル内にない | エラー |
| 存在しない idMso / imageMso | 警告 |
| keytip の重複 | 警告 |
| グループ内のコントロールが多すぎる（狭い画面で畳まれる） | 情報 |
| VBAに存在しないコールバック（Excel連携時） | 警告 |

## 6. アイコン作成・設定機能

手元の画像やicoをドロップすると、リボン向けのPNGに加工してファイルに埋め込む。さらに、コントロールの image 属性への設定までを一つの操作で終える。customUI/images への配置や rels への登録を、利用者が意識する必要はない。

### 6.1 取り込めるもの

| 入力 | 扱い |
| --- | --- |
| PNG / JPG / BMP / GIF / WebP | そのまま読み込む。GIFは最初のフレームを使う |
| ICO | 含まれる全サイズを一覧表示する。出力サイズに最も近く、それ以上の大きさのものを自動で選ぶ。手動での選択もできる |
| SVG | 出力サイズでラスタライズするので、どのサイズでも綺麗に出る |
| EXE / DLL | 埋め込みのアイコンを一覧にして選んで取り出す（社内ツールのアイコンを流用する用途） |
| クリップボード | Ctrl+Vで画像を貼り付ける |
| imageMso | 組み込みアイコンをPNGとして書き出し、色替えなどの加工の元にする |

### 6.2 アイコンエディタ（加工）

取り込んだ画像は、下記の操作を非破壊で重ねて加工できる。元画像は保持するので、あとから何度でもやり直せる。

- トリミング：余白の自動カット、正方形への手動切り抜き
- 余白：上下左右のパディング（既定はサイズの8%）
- 背景の透過：スポイトで選んだ色を、許容値つきで透明にする（白背景のJPG対策）
- 色：単色化、任意の色への置き換え、明るさの調整
- 形：角丸、円形マスク、バッジ（右下に小さな印）の重ね合わせ
- シャープ化：縮小後の16pxで線がぼけないように補正する

プレビューでは、16pxのnormalボタンと32pxのlargeボタンの実寸表示を、ライトとダークのリボン背景の上に並べる。実際に置いたときの見え方を、反映する前に確認できる。

### 6.3 出力と設定

- 出力は32×32の透過PNGを既定にする。高DPI向けに64×64も選べる。Excelが表示サイズに合わせて縮小する前提だが、実際の見え方は実機で検証する。
- 保存先は `customUI/images/<名前>.png`。`customUI/_rels/customUI14.xml.rels` に画像リレーションを登録し、そのIdを image 属性に設定する。
- 画像名はコントロールのidから自動で付ける（例：`img_btnSummary`）。あとから変更もできる。
- キャンバス上のボタンに画像ファイルを直接ドロップすると、アイコンエディタが開き、確定でそのボタンに設定される。
- どのコントロールからも参照されていない画像は「未使用」と表示し、一括で削除できる。
- フォルダをドロップすると、中の画像を同じ加工設定で一括して取り込む。

### 6.4 アイコンライブラリ

加工済みのアイコンは `%AppData%\Sash\icons` に、加工設定ごと保存する。保存したアイコンは、別のブックでも検索して使い回せる。タグ付けとお気に入り登録にも対応する。社内で共有したい場合に備えて、ライブラリの場所を共有フォルダに変えられるようにする。

## 7. Excel連携・反映

「反映」ボタン（F5）を押すと、Excelで開いているブックにも、閉じる・書き込む・開き直すを自動で行ってリボンを更新する。編集してからExcelで確認するまでを、数秒に縮めるのが狙いだ。

### 7.1 反映の流れ

1. 対象のブックが開いているかを、実行中のExcelをすべて調べて判定する（フルパスで照合）。
2. 開いていなければ、ファイルに書き込んで終了する。
3. 開いていて未保存の変更があれば、「保存して反映」か「中止」を選ばせる。勝手には保存しない。
4. ブックを保存して閉じる。xlamの場合は、アドインとして読み込まれているかどうかも記録しておく。
5. バックアップを取ってから、customUIパーツと画像を書き込む。
6. 同じExcelインスタンスで開き直す。アドインだったxlamは、アドインとして読み込み直す。開き直したときは、作成したタブをアクティブにする。
7. 成功か失敗かをトーストで表示する。失敗したらバックアップから戻せるようにする。

### 7.2 連携のその他の機能

- リボンエラーの表示：Excelのオプション「アドインのユーザーインターフェイスエラーを表示する」がオフなら、初回の反映時に有効にするよう案内する。設定は勝手には変えない。
- 開いているブックから開く：Excelで開いているxlsm / xlamを一覧から選んで、エディタに読み込める。
- 保護ビューとマクロの無効化：開き直したときにこれらで止まったら、その旨を表示して利用者の操作を待つ。セキュリティ設定には触れない。
- Excelがない環境：連携機能をグレーアウトし、ファイル編集だけを使えるようにする。

## 8. コールバック管理

XMLに書いたコールバック名と、VBA側のSubを突き合わせて一覧にする。そのうえで、足りないSubは正しいシグネチャで生成する。リボンが動かない原因で一番多いのは、名前の不一致とシグネチャの間違いだ。この二つを仕組みとして起きなくする。

### 8.1 シグネチャの生成

コントロールの種類と属性から、正しい引数を自動で決める。主なものは次のとおり。

| 属性（対象） | 生成する引数 |
| --- | --- |
| onLoad（customUI） | ribbon As IRibbonUI |
| onAction（button） | control As IRibbonControl |
| onAction（toggleButton / checkBox） | control As IRibbonControl, pressed As Boolean |
| onAction（dropDown / gallery） | control As IRibbonControl, id As String, index As Integer |
| onChange（editBox / comboBox） | control As IRibbonControl, text As String |
| getLabel / getEnabled / getVisible / getPressed / getImage など | control As IRibbonControl, ByRef returnedVal |
| getItemCount（dropDown / gallery） | control As IRibbonControl, ByRef count |
| getItemLabel / getItemID（dropDown / gallery） | control As IRibbonControl, index As Integer, ByRef returnedVal |
| getContent（dynamicMenu） | control As IRibbonControl, ByRef content |

### 8.2 一覧と同期

- 「コールバック」パネルに、名前、使っているコントロール、VBAでの状態を並べる。状態は「実装済み」「未実装」「引数が不一致」「VBA側にしかない（未使用）」の四つ。
- VBAの読み取りは、Excelでブックを開いているときだけ、VBEのCOM経由で行う。「VBAプロジェクト オブジェクト モデルへのアクセスを信頼する」がオフなら、その旨を表示して一覧は空のままにする。
- 未実装のSubは、「コピー」か「モジュールに挿入」を選んで生成する。挿入先は既定で標準モジュール `modRibbon` とし、なければ作る。既存のコードは書き換えず、末尾に追加するだけにする。
- インスペクタでコールバック名を変えたときは、VBA側のSub名も変えるかを確認する。変える場合は宣言行だけを書き換える。
- 名前は既定で `Ribbon_<id>_<属性>`（例：`Ribbon_btnSummary_onAction`）とし、命名規則は設定で変えられる。複数のコントロールで1つのSubを共有し、`control.id` で振り分ける書き方も選べる。

### 8.3 onLoadとInvalidateの雛形

getEnabled などの動的属性を使うときは、onLoad で受け取った IRibbonUI を保持して Invalidate を呼ぶ必要がある。VBAでエラーが起きて変数がリセットされると、この参照が消える。そこで、参照をセルや名前定義に退避して復元する定番のコードを、雛形として挿入できるようにする。32bit、64bitの両方のOfficeに対応させる（LongPtr、PtrSafe）。

## 9. カタログ・レシピ・操作性

「名前がわからない」「書き方を忘れた」を、ツールの中だけで解決できるようにする。

### 9.1 idMso / imageMso カタログ

- Microsoftが公開しているExcelのコマンドID一覧をもとに、組み込みのタブ・グループ・コマンドのidを内蔵する。日本語の表示名でも検索できるようにする。
- imageMsoは、初回起動時にExcelの GetImageMso で全アイコンを取得してキャッシュする。Excelがない環境では名前だけを表示する。
- ギャラリー表示であいまい検索し、クリックで選択中のコントロールに設定する。最近使ったものとお気に入りを先頭に出す。

### 9.2 レシピ（テンプレート）

XMLとコールバックのVBAをセットにして挿入する。最初に用意するものは次のとおり。

- 独自タブ＋グループ＋ボタン3つ
- ホームタブの末尾に自分のグループを追加
- 状態を保持するトグルボタン（getPressed と Invalidate）
- 条件で有効・無効を切り替えるボタン（getEnabled）
- シート名などから中身を作る dynamicMenu
- 選択肢をVBAで組み立てる dropDown
- 特定のシートでだけ表示するタブ（getVisible）

自分で作った構成を選択して「レシピとして保存」し、あとから使い回せるようにもする。

### 9.3 操作性

- Ctrl+Kのコマンドパレットから、すべての操作を名前で呼べる。
- 主なショートカット：F5 反映、Ctrl+S 保存、Ctrl+Z / Ctrl+Y 元に戻す・やり直し、Ctrl+D 複製、Ctrl+1 / 2 / 3 でキャンバス・ツリー・XMLに移動。
- 保存済みの状態との差分を、XMLの対比表示で確認できる。
- UIはミニマルにして絵文字は使わない。アイコンはSVGで描き、ライトとダークはシステム設定に合わせる（手動での切り替えも可）。高DPIと日本語を既定にし、英語UIも用意する。

## 10. フェーズ計画

第1弾で、編集から反映までの一連の流れとアイコン設定までを完成させる。既存ツールとの差は、この段階でもう十分に出る。日程は第1弾の見積もりを出してから決める。

| フェーズ | 内容 |
| --- | --- |
| 第1弾：編集の強化 | xlsm / xlam の読み書き、キャンバス・ツリー・XMLの同期、インスペクタとLint、Excelへのワンクリック反映、画像 / ico からのアイコン設定、imageMso / idMso の検索。完了条件：実業務のxlamを1本作れる |
| 第2弾：VBAとの連携 | コールバックの一覧と生成、リネームの連動、アイコンエディタの加工機能、レシピとコマンドパレット、コンテキストメニュー |
| 第3弾：仕上げ | Backstage の編集、アイコンライブラリの共有、保存済みとの差分表示、.sash.json の書き出し、英語UI |

第1弾のアイコン設定は、取り込み、リサイズ、余白、背景の透過までとする。色替えやバッジなどの加工は第2弾に回す。
