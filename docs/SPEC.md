# Sash 仕様書 v0.1 — Excelリボンエディタ

2026-11-22

## 1. 概要・目的

xlsm / xlam のカスタムリボン（customUI）を、見たまま組み立てて手で直せる単体デスクトップツールを作る。AI連携は対象外で、リボンの追加と手動編集を快適にすることだけに集中する。Graftとは独立したアプリとする。

解決したいのは、現状のリボン開発にある三つの手間である。XMLをテキストで書くしかなく構造が見えないこと、反映のたびにExcelを閉じて開き直す往復が発生すること、XMLとVBAコールバックの不整合やアイコンの用意に気づきにくいことの三つだ。

対象ユーザーは、VBAで業務ツールやアドインを作るExcelユーザー。まずは作者自身と社内での利用を想定する。対象ファイルは .xlsm / .xlam を必須とし、.xltm / .xlsb は第2弾以降に検討する。

## 2. 既存ツールとの差別化

VBA向けのリボンを現代的なビジュアルエディタで作れるツールは、まだ存在しない。既存のツールはどれも、XMLをテキストで編集するものか、VSTO専用のものだ。本ツールは、キャンバスでの編集、Excelとの即時連携、アイコンの作成で差を付ける。

| ツール | 編集方式 | VBA（xlsm/xlam） | 現状 | 足りないもの |
| --- | --- | --- | --- | --- |
| [Office RibbonX Editor](https://github.com/fernandreu/office-ribbonx-editor) | XMLテキスト（ScintillaNET）＋ツリー | 対応 | WPF / .NETで開発が継続中 | ビジュアル編集、Excel連携、アイコンの加工 |
| [Custom UI Editor（OfficeDev）](https://github.com/OfficeDev/office-custom-ui-editor) | XMLテキスト | 対応 | 2024年6月にアーカイブ済み | 保守。スキーマは2010まで |
| [VS Ribbon Designer](https://learn.microsoft.com/en-us/visualstudio/vsto/ribbon-overview?view=vs-2022) | ビジュアル | 非対応（VSTO専用） | Visual Studioに同梱 | VBAで使えない。コールバックを生成しない |
| RibbonX Visual Designer | ツリー＋フォーム | 対応 | Excelアドイン。UIは2007年代のまま | 現代的なUI、高DPI、ダークモード |

本ツールの柱は次の五つ。

1. キャンバス編集。本物のExcelのリボンに近いプレビュー上に、ドラッグで部品を置く。
2. 賢いインスペクタ。使える属性だけを出し、入力中に検証する。
3. Excelとの即時連携。ワンクリックで反映し、コールバックを同期する。
4. アイコンの作成。画像やicoから加工してそのまま設定できる。
5. 現代的な操作性。コマンドパレット、あいまい検索、ダークモード、日本語UIを備える。

## 3. 動作環境・技術構成

C#（.NET 10）をホストにし、UIはすべてWebView2（HTML / CSS / TypeScript）で描く。リボンのプレビュー、Monacoエディタ、SVGアイコン、ダークモードを少ない労力で現代的に作れるためだ。

| 層 | 担当 | 主な技術 |
| --- | --- | --- |
| UI | キャンバス、ツリー、インスペクタ、XMLエディタ、アイコンエディタ | WebView2、TypeScript、Monaco Editor |
| ホスト | ウィンドウ、ファイルダイアログ、UIとのメッセージ交換 | WinForms（外枠のみ）、WebView2 PostMessage |
| コア | OPC（zip）の読み書き、customUIモデル、XSD検証、Lint | System.IO.Packaging、System.Xml.Schema |
| 画像 | 画像/ico/SVGの読み込み、加工、PNG出力 | System.Drawing / WIC、SVGはブラウザ側でラスタライズ |
| Excel連携 | ブックの制御、VBEの読み書き、imageMsoの取得 | Excel COM（遅延バインド） |

動作環境はWindows 10 / 11（64bit）、Excel 2016以降またはMicrosoft 365。配布はself-containedの単一exeで、インストーラーは使わない。WebView2ランタイムはOS標準のものを使う。設定とアイコンライブラリは `%AppData%\Sash` に保存する。

**対応する WebView2 ランタイムの下限は Chromium 109**（Windows 7 / 8.1 向けの WebView2 の最終版で、企業で版が固定されがちなため）。

- UI の色は `styles.css` の `:root` で `light-dark()` を使ってライト／ダークを 1 か所に書いている。`light-dark()` は Chromium 123 以降、`color-mix()` は 111 以降、CSS の入れ子は 120 以降でしか使えず、古い版では**宣言ごと無効になって背景色・枠線がすべて消える**（v0.1.0 で、版が固定された PC で画面が透明になった）。
- そこで CSS はビルド時に lightningcss で変換する（`ui/vite.config.ts`。`css.transformer` と `build.cssMinify` を `lightningcss` にし、対象を `chrome >= 109` にする）。`light-dark()` は `--lightningcss-light` / `--lightningcss-dark` の変数による代替に、入れ子は展開した形に下がる。ビルド後の `wwwroot/assets/*.css` に `light-dark(`・`color-mix(` が残っていないことは、CI（`ci.yml`）とリリース（`release.yml`）の「CSS の互換性の検査」の段が grep で確かめ、残っていれば失敗させる。
- `color-mix()` は `var()` を含むため変換できない。半透明の色は `--warning-tint-18` のような専用のトークンにし、ライト／ダークそれぞれの `rgba` を書く。
- 新しく使う CSS / JS は Chromium 109 で動くものに限る。未対応でも壊れないもの（`field-sizing`、`scrollbar-width` など）は、使えなくても見た目が少し違うだけで済む使い方にする。JS は target `es2022` で、ES2023 以降の API（`toSorted`・`findLast`・`Object.groupBy`・Set の `union` など）は使わない。
- ホストは起動時に WebView2 の版（`BrowserVersionString`）を `%AppData%\Sash\logs\app.log` に 1 行記録する。主版数が 109 未満なら、起動時に一度だけ「画面が正しく表示されないことがあります」と知らせる（ブロックしない）。版の判定は `Sash.Core.WebView2Runtime`。版は「バージョン情報」にも表示する。

COMは遅延バインドで呼ぶ。Interopアセンブリを同梱しないため、Excelのバージョンに依存しない。Excelが入っていないPCでも、ファイル編集だけは動くようにする。

UIの技術はWebView2で確定した（WPF、WinUI 3と比較のうえ決定）。

## 4. 画面構成

メインウィンドウは一画面で完結させる。左にパレットとツリー、中央にキャンバスとXMLエディタ、右にインスペクタ、下に問題とコールバックのパネルを置く。どのペインで要素を選んでも、他のペインで同じ要素が選択される。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Sash  集計ツール.xlam（Excelで開いています）   [Ctrl+K コマンド] [反映 F5] │
├──────────────┬───────────────────────────────────────┬───────────────────┤
│ パレット     │ キャンバス（リボンのプレビュー）      │ インスペクタ      │
│ button/toggle│  ファイル ホーム 挿入 [集計ツール]    │ 基本              │
│ menu/split   │ ┌──────┬──────────┬──────┬─────────┐  │  id   btnSummary  │
│ dropDown     │ │[集計]│□CSV出力  │[自動]│ ここに  │  │  label 集計する   │
│ editBox      │ │      │□クリア   │      │ドロップ │  │  size  large      │
│ レシピ       │ │      │□設定     │      │         │  │ 表示              │
├──────────────┤ │ 集計            │モード│         │  │  [□] アイコン編集 │
│ ツリー       │ └─────────────────┴──────┴─────────┘  │ 動作              │
│ tab 集計ツール├───────────────────────────────────────┤  onAction 実装済み│
│  group 集計  │ XMLエディタ（Monaco）                 │  getEnabled なし  │
│   btnSummary │ <tab id="tabTools" label="集計ツール">│                   │
│   btnCsv     │   <group id="grpSum" label="集計">    │                   │
│  group モード│     <button id="btnSummary" ...       │                   │
```

## 5. 編集機能

キャンバス、ツリー、XMLの三つのビューは、一つの内部モデル（customUIのツリー）を共有して常に同期する。どのビューで変更しても、Undo / Redoは一つの履歴にまとめて記録する。

### 5.1 ファイル

- .xlsm / .xlam をドラッグ&ドロップ、または「開く」で読み込む。最近使ったファイルをホーム画面に並べる。
- customUI14.xml（2010以降）と customUI.xml（2007）の両方を扱う。新規作成時はcustomUI14を既定にし、.rels へのリレーション登録も自動で行う。
- 両方がある場合は「2010以降のExcelは14を優先する」と警告し、どちらを編集するか切り替えられるようにする。
- 保存のたびに元のファイルを世代つきでバックアップする（既定は10世代）。customUI以外のパーツ（シート、VBAプロジェクト）には一切触れない。
- リボン定義を `.sash.json` として書き出し・読み込みできるようにする。別のブックへの流用と、Gitでの差分管理に使う。

### 5.2 キャンバス

- Excelのリボンに近い見た目で、タブ、グループ、コントロールを描画する。ライトとダークの両方に対応する。
- 左のパレットからドラッグして配置する。配置できない場所ではドロップ先の表示を出さない（例：グループの外にボタンは置けない）。
- クリックで選択、ドラッグで並べ替え、Ctrl+Dで複製、Deleteで削除。グループをまたいだ移動もできる。
- large・normalのサイズ、ラベルの改行、小ボタンの3段積みを、本物に近い形で再現する。
- 組み込みタブ（ホームなど）にグループを足す場合、組み込み部分はグレーのプレースホルダーで示し、自分で足した部分だけを編集対象にする。
- 対象はリボン、クイックアクセスツールバー、コンテキストメニュー、Backstage。Backstageとコンテキストメニューは第2弾で対応する。

### 5.3 ツリー

- customUIの階層をそのまま表示する。キャンバスでは選びにくい要素（menuの中身、dialogBoxLauncher、非表示の要素）はここで操作する。
- 各ノードには、種類のアイコン、ラベル、id、警告バッジを表示する。

### 5.4 インスペクタ

- 選んだコントロールに使える属性だけを、「基本」「表示」「動作（コールバック）」「詳細」に分けて出す。
- 属性の型に合わせた入力欄を使う。列挙値はドロップダウン、真偽値はトグル、imageMso / idMsoは検索つきピッカー、imageはアイコンエディタの呼び出し。
- 「label」と「getLabel」のような静的値と動的コールバックの組は、1行の切り替えスイッチにまとめる。これで排他の矛盾がそもそも起きない。
- 属性名にホバーすると、日本語の説明と指定例を表示する。
- idはラベルから自動で提案する（例：「集計する」→ btnSummary）。
- **分割ボタン（splitButton）のラベルとアイコン**は、分割ボタンを選んだインスペクタの先頭の「ラベル・アイコン・ヒント」の区画で直接編集できる。customUI のスキーマ（CT_SplitButtonRestricted）で、分割ボタン自身には label / screentip / supertip / image / imageMso / getImage / showImage を付けられず、中の先頭の button / toggleButton から受け継ぐ決まりのため、**書き込み先は中のボタン**にする（分割ボタンにスキーマ違反の属性は作らない）。区画の見出しの下に「中のボタン（btnXXX）に設定されます」と書き、「中のボタンを選ぶ」で移れる。中のボタンが無い（壊れた XML）ときは、その旨を出して入力欄は出さない。アイコン行・ラベルからのアイコンの候補・固定／VBA の切り替えは普通のボタンと同じ部品を使い、元に戻すは 1 操作 1 回。詳細は §21。

### 5.5 XMLエディタ

- Monacoを使い、XSDに基づく要素・属性の補完、エラーの波線表示、折りたたみ、整形を備える。
- カーソル位置の要素を、キャンバスとツリーでも選択状態にする（逆方向も同じ）。
- XMLの構文が壊れている間は、他のビューを最後に正しかった状態のまま表示し、上部に「同期停止中」と出す。
- コメントと属性の並び順は、キャンバスで編集してもできるだけ保持する。

### 5.6 検証（Lint）

XSDによる検証に加え、次の独自ルールを入力中に常時チェックする。結果は下部の「問題」パネルに一覧表示し、クリックで該当箇所に飛べる。

| ルール | 重大度 |
| --- | --- |
| id / idMso / idQ の重複、または未指定 | エラー |
| 静的属性と get系コールバックの同時指定 | エラー |
| image が参照する画像がファイル内にない | エラー |
| 存在しない idMso / imageMso | 警告 |
| keytip の重複 | 警告 |
| グループ内のコントロールが多すぎる（狭い画面で畳まれる） | 情報 |
| VBAに存在しないコールバック（Excel連携時） | 警告 |

## 6. アイコン作成・設定機能

手元の画像やicoをドロップすると、リボン向けのPNGに加工してファイルに埋め込む。さらに、コントロールの image 属性への設定までを一つの操作で終える。customUI/images への配置や rels への登録を、利用者が意識する必要はない。

### 6.1 取り込めるもの

| 入力 | 扱い |
| --- | --- |
| PNG / JPG / BMP / GIF / WebP | そのまま読み込む。GIFは最初のフレームを使う |
| ICO | 含まれる全サイズを一覧表示する。出力サイズに最も近く、それ以上の大きさのものを自動で選ぶ。手動での選択もできる |
| SVG | 出力サイズでラスタライズするので、どのサイズでも綺麗に出る |
| EXE / DLL | 埋め込みのアイコンを一覧にして選んで取り出す（社内ツールのアイコンを流用する用途） |
| クリップボード | Ctrl+Vで画像を貼り付ける |
| imageMso | 組み込みアイコンをPNGとして書き出し、色替えなどの加工の元にする |
| アイコン集（Fluent） | 同梱の Fluent UI System Icons（MIT License、24px の線 / 塗り、約2,900個）から、日本語・英語で検索して色を付けて選ぶ。出力サイズで描き直して PNG にし、アイコンエディタで加工できる。Excel は不要 |

### 6.2 アイコンエディタ（加工）

取り込んだ画像は、下記の操作を非破壊で重ねて加工できる。元画像は保持するので、あとから何度でもやり直せる。

- トリミング：余白の自動カット、正方形への手動切り抜き
- 余白：上下左右のパディング（既定はサイズの8%）
- 背景の透過：スポイトで選んだ色を、許容値つきで透明にする（白背景のJPG対策）
- 色：単色化、任意の色への置き換え、明るさの調整
- 形：角丸、円形マスク、バッジ（右下に小さな印）の重ね合わせ
- シャープ化：縮小後の16pxで線がぼけないように補正する

プレビューでは、16pxのnormalボタンと32pxのlargeボタンの実寸表示を、ライトとダークのリボン背景の上に並べる。実際に置いたときの見え方を、反映する前に確認できる。

加工のほかに、鉛筆・塗りつぶし・選択などで絵を直接描く「描いて編集」（ペイント画面）がある。入口はアイコンエディタの［新しく描く］と［描いて編集…］で、描くのは加工の前（描いた絵が新しい元画像になる）。仕様は §25。

### 6.3 出力と設定

- 出力は32×32の透過PNGを既定にする。高DPI向けに64×64も選べる。Excelが表示サイズに合わせて縮小する前提だが、実際の見え方は実機で検証する。
- 保存先は `customUI/images/<名前>.png`。`customUI/_rels/customUI14.xml.rels` に画像リレーションを登録し、そのIdを image 属性に設定する。
- 画像名はコントロールのidから自動で付ける（例：`img_btnSummary`）。あとから変更もできる。
- キャンバス上のボタンに画像ファイルを直接ドロップすると、アイコンエディタが開き、確定でそのボタンに設定される。分割ボタンにドロップしたときは、中のボタンに設定する（§21）。アイコンを設定する入口（インスペクタ・ドロップ・コマンド「選択中のコントロールのアイコンを作る」・imageMso カタログ・ライブラリ）は、すべて同じ「書き込み先の決め方」（`iconTarget.ts`）を通る。
- どのコントロールからも参照されていない画像は「未使用」と表示し、一括で削除できる。
- フォルダをドロップすると、中の画像を同じ加工設定で一括して取り込む。

### 6.4 アイコンライブラリ

加工済みのアイコンは `%AppData%\Sash\icons` に、加工設定ごと保存する。保存したアイコンは、別のブックでも検索して使い回せる。タグ付けとお気に入り登録にも対応する。社内で共有したい場合に備えて、ライブラリの場所を共有フォルダに変えられるようにする。

## 7. Excel連携・反映

「反映」ボタン（F5）を押すと、Excelで開いているブックにも、閉じる・書き込む・開き直すを自動で行ってリボンを更新する。編集してからExcelで確認するまでを、数秒に縮めるのが狙いだ。

### 7.1 反映の流れ

1. 対象のブックが開いているかを、実行中のExcelをすべて調べて判定する（フルパスで照合）。
2. 開いていなければ、ファイルに書き込んで終了する。
3. 開いていて未保存の変更があれば、「保存して反映」か「中止」を選ばせる。勝手には保存しない。
4. ブックを保存して閉じる。xlamの場合は、アドインとして読み込まれているかどうかも記録しておく。
5. バックアップを取ってから、customUIパーツと画像を書き込む。
6. 同じExcelインスタンスで開き直す。アドインだったxlamは、アドインとして読み込み直す。開き直したときは、作成したタブをアクティブにする。
7. 成功か失敗かをトーストで表示する。失敗したらバックアップから戻せるようにする。

### 7.2 連携のその他の機能

- リボンエラーの表示：Excelのオプション「アドインのユーザーインターフェイスエラーを表示する」がオフなら、初回の反映時に有効にするよう案内する。設定は勝手には変えない。
- 開いているブックから開く：Excelで開いているxlsm / xlamを一覧から選んで、エディタに読み込める。
- 保護ビューとマクロの無効化：開き直したときにこれらで止まったら、その旨を表示して利用者の操作を待つ。セキュリティ設定には触れない。
- Excelがない環境：連携機能をグレーアウトし、ファイル編集だけを使えるようにする。

## 8. コールバック管理

XMLに書いたコールバック名と、VBA側のSubを突き合わせて一覧にする。そのうえで、足りないSubは正しいシグネチャで生成する。リボンが動かない原因で一番多いのは、名前の不一致とシグネチャの間違いだ。この二つを仕組みとして起きなくする。

### 8.1 シグネチャの生成

コントロールの種類と属性から、正しい引数を自動で決める。主なものは次のとおり。

| 属性（対象） | 生成する引数 |
| --- | --- |
| onLoad（customUI） | ribbon As IRibbonUI |
| onAction（button） | control As IRibbonControl |
| onAction（toggleButton / checkBox） | control As IRibbonControl, pressed As Boolean |
| onAction（dropDown / gallery） | control As IRibbonControl, id As String, index As Integer |
| onChange（editBox / comboBox） | control As IRibbonControl, text As String |
| getLabel / getEnabled / getVisible / getPressed / getImage など | control As IRibbonControl, ByRef returnedVal |
| getItemCount（dropDown / gallery） | control As IRibbonControl, ByRef count |
| getItemLabel / getItemID（dropDown / gallery） | control As IRibbonControl, index As Integer, ByRef returnedVal |
| getContent（dynamicMenu） | control As IRibbonControl, ByRef content |

### 8.2 一覧と同期

- 「コールバック」パネルに、名前、使っているコントロール、VBAでの状態を並べる。状態は「実装済み」「未実装」「引数が不一致」「VBA側にしかない（未使用）」の四つ。
- VBAの読み取りは、Excelでブックを開いているときだけ、VBEのCOM経由で行う。「VBAプロジェクト オブジェクト モデルへのアクセスを信頼する」がオフなら、その旨を表示して一覧は空のままにする。
- 未実装のSubは、「コピー」か「モジュールに挿入」を選んで生成する。挿入先は既定で標準モジュール `modRibbon` とし、なければ作る。既存のコードは書き換えず、末尾に追加するだけにする。
- インスペクタでコールバック名を変えたときは、VBA側のSub名も変えるかを確認する。変える場合は宣言行だけを書き換える。
- 名前は既定で `Ribbon_<id>_<属性>`（例：`Ribbon_btnSummary_onAction`）とし、命名規則は設定で変えられる。複数のコントロールで1つのSubを共有し、`control.id` で振り分ける書き方も選べる。

### 8.3 onLoadとInvalidateの雛形

getEnabled などの動的属性を使うときは、onLoad で受け取った IRibbonUI を保持して Invalidate を呼ぶ必要がある。VBAでエラーが起きて変数がリセットされると、この参照が消える。そこで、参照をセルや名前定義に退避して復元する定番のコードを、雛形として挿入できるようにする。32bit、64bitの両方のOfficeに対応させる（LongPtr、PtrSafe）。

## 9. カタログ・レシピ・操作性

「名前がわからない」「書き方を忘れた」を、ツールの中だけで解決できるようにする。

### 9.1 idMso / imageMso カタログ

- Microsoftが公開しているExcelのコマンドID一覧をもとに、組み込みのタブ・グループ・コマンドのidを内蔵する。日本語の表示名でも検索できるようにする。
- imageMsoは、初回起動時にExcelの GetImageMso で全アイコンを取得してキャッシュする。Excelがない環境では名前だけを表示する。

### 9.2 レシピ（テンプレート）

XMLとコールバックのVBAをセットにして挿入する。最初に用意するものは次のとおり。

- 独自タブ＋グループ＋ボタン3つ
- ホームタブの末尾に自分のグループを追加
- 状態を保持するトグルボタン（getPressed と Invalidate）
- 条件で有効・無効を切り替えるボタン（getEnabled）
- シート名などから中身を作る dynamicMenu
- 選択肢をVBAで組み立てる dropDown
- 特定のシートでだけ表示するタブ（getVisible）

自分で作った構成を選択して「レシピとして保存」し、あとから使い回せるようにもする。

### 9.3 操作性

- Ctrl+Kのコマンドパレットから、すべての操作を名前で呼べる。
- 主なショートカット：F5 反映、Ctrl+S 保存、Ctrl+Z / Ctrl+Y 元に戻す・やり直し、Ctrl+D 複製、Ctrl+1 / 2 / 3 でキャンバス・ツリー・XMLに移動。

### 13.2 決めたこと

- レシピの VBA の識別子は、id を単語の区切り（英数字以外）で囲む形にそろえる（例：`m_tglAuto`）。id を振り直したときに、変数名や定数名も一緒に置き換わるようにするため。

- 「特定のシートでだけ表示するタブ」と「条件で有効・無効を切り替えるボタン」のレシピは、ThisWorkbook のイベントを使うので xlsm 向け。xlam でほかのブックのシートに反応させるには、アプリケーションイベントのクラスが必要になる。

### 14.2 決めたこと

- Backstage の要素は、tab や group などがリボンと同じ名前で中身が違う。そこでスキーマを別の表で持ち、要素が backstage の中にあるかどうかで引き分ける。インスペクタ、Lint、XML補完、パレットはすべてこの判定に従う。
- アイコンライブラリは、1つのアイコンを「json・png・元画像」の3ファイルで持ち、全体の目録ファイルは作らない。共有フォルダで複数人が同時に追加しても壊れにくくするため。お気に入りは人ごとの設定に持つ。
- 英語UIは、日本語の文言そのものを辞書のキーにする（gettext と同じ方式）。辞書にない文言は日本語のまま表示されるので、訳し漏れがあっても画面が壊れない。言語を切り替えたときは画面を読み込み直し、開いていたファイルを開き直す。
- レシピの XML と VBA の中身（ラベルやメッセージ）は、英語UIでも日本語のまま挿入する。利用者のブックに入る内容なので、画面の言語とは切り離した。

### 17.2 データを守るための決まり

- **XML に構文エラーがある間は、キャンバス・ツリー・インスペクタからの編集を断る。** 書きかけの XML が上書きされて消えないようにするため。断ったことは通知で知らせる。
- **何も変わらない編集は履歴に残さない。** 元に戻すを押しても何も起きない、という状態を作らないため。
- **保存する画像は、ディスク上の状態との差分で決める。** 削除→元に戻す、読み込み→元に戻すなどで画像が失われないようにするため。保存を始めた時点の内容を控えておき、保存中に加えた編集は未保存のまま残す。
- **保存・反映・開くは同時に一つだけ。** 実行中の操作は待ってもらう。
- **子要素の順序と個数を検証する。** customUI（commands → ribbon → backstage → contextMenus）、ribbon（officeMenu → qat → tabs → contextualTabs）、group の dialogBoxLauncher は最後に一つ、splitButton はボタン一つとメニュー一つ、など。挿入・移動・複製・貼り付けも、この規則で置ける位置に収める。
- **id と Sub 名には日本語などの Unicode の文字を使える。**
- **レシピの VBA には、モジュールの先頭に置く宣言を使わない。** 既存のモジュールの末尾に足すとコンパイルエラーになるため。状態は Static 変数を持つ Function で保つ。ThisWorkbook の既存のイベントと名前が重なるときは足さずに、足すべき行を示す。

### 17.3 ファイルとバックアップ

- 保存は一時ファイルに書いてから `File.Replace` で置き換える（置き換えられない環境ではコピーで上書きする。NAS・Samba・WebDAV などで `File.Replace` が IOException になったときもコピーに切り替えるが、共有違反・ロック違反は切り替えずにそのまま失敗として返す）。読み取り専用・暗号化（パスワード付き）・ほかで開かれているファイルは、理由を示して断る。
- バックアップのフォルダは `<ファイル名>_<フルパスの SHA256 の先頭 8 桁>` とし、元のフルパスを `source.txt` に書く。別のフォルダにある同じ名前のブックのバックアップが混ざらないようにするため。中身が最新のバックアップと同じなら新しく作らない。
- **バックアップから復元（ファイル メニュー）。** 一覧（新しい順）から選んで戻す。戻す前に今のファイルもバックアップする。そのブックのバックアップ以外は受け付けず、Excel でブックが開かれているときは断る。以前の形式（`<ファイル名>` だけのフォルダ）のバックアップは一覧に出ない。
- 設定とレシピのファイルが壊れていたら `.bak` に退避して既定に戻す。読めないときは上書きしない。

### 17.4 Excel 連携

- OneDrive / SharePoint 上のブックは、Excel が返す URL を同期フォルダのローカルのパスに直して照合する。
- Excel が忙しくて呼び出しを断ったときは、100ms 間隔で 10 秒までやり直し、それでもだめなら「Excel が応答しない」と知らせる。
- アドインの読み直しは、Installed の切り替えではなく、閉じて開き直す。
- 反映のやり直しでは、バックアップは最初の一回だけ取り、書き込みだけをやり直す。

### 17.5 更新

- GitHub が確認先のときは、「新しい版あり」と知らせる前に照合値ファイルを取得する。取れなければ（リリースが下書きのうちなど）最新として扱う。
- 確認は 30 秒、ダウンロードはデータが 60 秒届かなければ打ち切る。
- 開発用のビルドでは、自分自身の入れ替えをしない。

### 17.6 Windows 実機で確かめていないこと

WebView2 での表示と操作、Excel 連携（COM の呼び出しのやり直し、OneDrive のパスの変換、アドインの読み直し）、VBE へのコード挿入、レシピの VBA と `modRibbonCore` の 32bit / 64bit での動作、OS のクリップボードと IME の実際の入力、バックアップからの復元は、Linux 上のビルドとテスト、ブラウザでの確認までしか行っていない。

### 17.7 Excel の組み込みアイコン（imageMso）の取り込み

Office のアイコンは Microsoft の著作物で、Sash（MIT）には同梱できない。そこで**利用者の PC の Excel から一度だけ取り出し、その PC の中（`%AppData%\Sash\cache\imageMso`）にだけ保存する**。取り込んだ後は、Excel を起動しなくても（Excel がなくなっても）キャッシュから表示する。

| 項目 | 内容 |
| --- | --- |
| 取り出し方 | **Excel の中（同じプロセス）で取り出す。** 取り込み専用の見えない Excel に作業用のブックを開き、その VBProject に一時的な標準モジュール `SashImageMsoExport`（`ImageMsoVbaExport.ModuleSource`）を入れ、`Application.Run "'<ブック名>'!SashImageMsoExport.SashExportImageMso", 一覧のパス, 出力先, 大きさ` を 50 件ずつ呼ぶ。VBA は一覧（ASCII・CRLF、1 行に 1 つ）の n 行目の名前について `Application.CommandBars.GetImageMso` を呼び、`pic.Handle` の HBITMAP を `GetObject`（幅・高さ）と `GetDIBits`（32bpp・BI_RGB・`biHeight = -高さ` で上の行から）で読み、`n.bgra`（幅 4 バイト・高さ 4 バイトのリトルエンディアン、続けて幅×高さ×4 バイトの BGRA）を書く。`Err.Number` が E_INVALIDARG（&H80070057）なら `n.missing`、ほかのエラーは `n.err`（UTF-16LE の「番号 タブ 説明」）。ファイル名を名前ではなく番号にするのは、Windows のファイル名が大文字と小文字を区別しないため。Declare は `#If VBA7 Then`（PtrSafe・LongPtr。64bit / 32bit の Office 2010 以降）と `#Else`（Long）に分け、構造体は使わず Long の配列で受け渡す（64bit の Type の詰め物を気にしないため）。モジュールの変数は持たない。Sash（Sash.Core の `ImageMsoVbaExport`）は .bgra を読み（長さ・大きさが合わなければその名前だけ「画像にできなかった」）、アルファがすべて 0 なら不透明、そうでなければ乗算済みをストレートに戻して PNG にし、読んだファイルを消す。準備の最後に FileSave を試しに取り出して記録する（取れなければ 0.5 秒おきに数回やり直す。「存在しない」と返ったら、存在しないことの見分けが当てにならないので取り込みをやめる。すべての名前を「存在しない」と記録してしまわないため） |
| 一括の取り込み | 初めての起動で、Excel があり未取り込みなら、ホーム画面を出した後に裏で始める（編集は止めない）。カタログ（`excelControls.json`）から画像を持ちうる名前（タブ・タブの組・右クリックメニューを除く）を送り、**32px だけ**を取り出す。キャンバスもアイコンの一覧も 32px の画像を縮めて描く（小さいボタンも 32px を 16px に縮める）ので、16px は使われないため取らない（`sizes` で指定すれば取れる）。利用者の Excel を何千回も呼ばないよう、**取り込み専用の見えない Excel を起動し、終わったら閉じる**。50 件ずつに分けて COM のスレッドに積み、その合間に反映や VBA の操作が割り込めるようにする |
| 取り込み専用の Excel の片付け | 取り込みの最中に利用者がブックをダブルクリックすると、Windows がこの見えない Excel に開かせることがある。まとまりごとに `Workbooks.Count` を見て、ブックがあればその Excel は見えるようにして（`Visible`・`UserControl`・`DisplayAlerts` を戻して）利用者に引き渡し（Quit しない）、新しい見えない Excel で続ける。起動の途中で失敗しても（起動直後の設定で例外など）後片付けは必ず呼び、起動しかけた Excel を残さない。片付けでは、入れた VBA モジュールを `VBComponents.Remove` で取り除き、作業用のブックを保存せずに閉じ（`DisplayAlerts = False` なので確かめは出ない）、ブックがなければ Quit する。Quit が断られたら、最後の手段として **Sash が起動したその Excel のプロセスだけ**を終わらせる（起動直後に `Application.Hwnd` から `GetWindowThreadProcessId` でプロセスの番号と起動時刻を覚えておき、起動前からあった Excel のプロセスなら覚えない。終わらせる前に、名前が EXCEL で起動時刻が同じかを確かめる。利用者の Excel は決して終わらせない）。準備（起動・作業用のブック・モジュール・試しの取り出し）は 30 秒までとし、それを超えるか、1 つの呼び出しが 40 秒たっても戻らなければ（見えないダイアログなどで Excel が呼び出しを断り続けるとき）、そのプロセスを終わらせて失敗にする。片付けも 45 秒まで待ち、アプリの終了時は 10 秒まで待って、戻らなければ同じようにそのプロセスを終わらせる。取り込み専用の Excel を起動し直すのは 1 回の取り込みで 1 回まで（応答しない・ブックが開かれた、のどちらでも数える）。2 回目が要るときは取り込みを失敗にする（起動と失敗を繰り返さないため）。一時フォルダは `%TEMP%\Sash\imagemso\<guid>`（まとまりごとにその下のフォルダ）で、読んだら消し、片付けでフォルダごと消す（消せなくても続ける）。VBA の `Open` は ANSI のパスしか扱えないので、パスに ASCII でない文字があれば短い名前（8.3 形式）を使うアプリを閉じるときは、COM のスレッドに片付けを必ず積んでから閉じ（起動の途中でも後ろに積まれて走る）、終了処理に入った後は新しい Excel を起動しない |
| 進み具合 | 右下の通知に「Excel のアイコンを取り込んでいます… 1,234 / 2,081」と「中止」を出す。書き換えは 500ms に 1 回までにし、書き換えるのは文言だけ（ボタンは作り直さない。押している最中にボタンが入れ替わってクリックにならない・フォーカスや読み上げがやり直しになる、を防ぐため）。× で閉じたら出し直さない。終わったら完了を知らせ、表示中のアイコンを描き直す。中止したら次の起動では自動で始めない（設定から始められる）。取り込み直しを中止すると前の manifest が残って状態は `done` になるので、ホストは `cancelled: true` を添え、UI は中止を先に見て「中止しました」と出す |
| 失敗の記録 | 失敗（Excel を起動できない、100 件続けて画像にできず打ち切った、など）は `prefetch-failed.json`（Excel の版・日時・理由）に残す。次の起動でも、同じ版の Excel なら状態を `failed` として返し、UI は中止したときと同じく自動では始めない（起動のたびに見えない Excel を起動して失敗し、エラーを出し続けないため）。Excel の版が変わっていれば（どちらの版も分かっていて違うとき）記録は当てはまらないとして、もう一度自動で試す。設定画面からの手動の取り込みはいつでもでき、成功したら記録を消す |
| キャッシュ | `<大きさ>\<名前>.png`。0 バイトや PNG の署名で始まらないファイルはキャッシュにないものとして扱い、消して取り直させる（残すと「取り込み済み」とみなされ、二度と取り直されないため）。Excel に存在しない名前は大きさごとの `missing.json` に記録し、Excel がない PC でも「存在しない imageMso」の警告を正しく出す。取り込みを終えたら `manifest.json`（Excel の版、大きさ、件数、日時）を書き、次の起動からは取り込み済みとして Excel を起動しない |
| 取り込み直し | 自動ではしない。Excel の版（`EXCEL.EXE` のファイルの版から Excel を起動せずに読む）が manifest と違えば、設定画面で取り込み直しを勧める。manifest の版（取り込んだ Excel の `Version` と `Build`）とファイルの版は形が違いうるので、どちらも「メジャー.マイナー.ビルド」にそろえて記録し、比べる（取り込み直した後も「Excel が更新されています」が出続けないように） |
| 1 件ずつの取得 | `excel.imageMso` は**キャッシュだけを引き、Excel には触れない**（COM のスレッドの外で引く）。存在しない名前（記録済み）は null、キャッシュにない名前は結果に含めない（UI は 60 秒後に取り直す）。以前はキャッシュにない名前を起動中の Excel から 1 件ずつ取っていたが、Sash（別のプロセス）から呼んだ `GetImageMso` は実機で E_UNEXPECTED を返し、取れなかった。Excel の中で取り出せるのは一括の取り込みだけなので、足りない名前は UI がすでに出している取り込みの状態（未取り込み・失敗なら「アイコンを取り込む」）から取り込んでもらう。取り込みが終わったら UI がすべて取り直す |
| 打ち切り | 100 件続けて 1 件も画像にできなければ、変換の方法がその PC で動いていないとみなして打ち切り、失敗として理由を見せる |
| 記録 | `%AppData%\Sash\logs\app.log` に、起動（版・プロセスの番号）、VBA モジュールを入れられたか（信頼の設定がオフならその旨）、試しの取り出しの結果、VBA が書いた最初の `.err` の中身（`Err.Number` と説明。番号ごとに最初の 1 回だけ）、最初に取れた画像の大きさ、取り込みごとの集計（画像・存在しない・取り出せなかった・起動し直しの数）、片付け（Quit できなかった・プロセスを終わらせた・引き渡した）を書く |
| 信頼の設定 | VBA モジュールを入れるには、Excel の「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」（トラスト センター → マクロの設定）がオンでなければならない。オフなら取り込みを失敗にし、「Excel の「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」をオンにすると、組み込みアイコンを取り込めます」と、オンにしてから設定の「アイコン」で取り込み直すことを案内する（失敗の記録が残るので、同じ版の Excel では自動ではやり直さない。設定画面から取り込めば記録は消える） |
| 画面 | 設定の「アイコン」に状態（取り込み済み・件数・Excel の版・日付）と「取り込む / 取り込み直す」「中止」、アイコンはこの PC の Excel から取り出しこの PC にだけ保存すること（Microsoft の著作物で同梱しないこと）を示す。imageMso のカタログでは、アイコンを出せないときに理由と「アイコンを取り込む」を出す |

ホストとの要求は `icons.prefetchStatus`・`icons.prefetchStart { names, sizes?, force? }`・`icons.prefetchCancel`、進み具合はホストからの知らせ `{ event: 'iconPrefetch', state, done, total, … }`（形は `ui/src/bridge.ts` の `IconPrefetchStatus`）。状態は `none`（未取り込み・中止）・`running`・`done`・`failed`（今回か、同じ版の Excel での前回の失敗）・`unavailable`（Excel がなくキャッシュもない）。直前の取り込みが中止で終わったときは `cancelled: true` を添える。

**Windows 実機で確かめていないこと：** Excel の中（VBA）での取り出し一式（モジュールの挿入と `Application.Run`、VBA がコンパイルできるか、`GetImageMso` が同じプロセスでは画像を返すか、`GetDIBits` で読めるか、存在しない名前の `Err.Number` が本当に &H80070057 か、32bit の Office での動作、マクロの設定が「すべて無効」のときに作業用のブックのマクロを Run できるか）、取り込み専用の Excel の起動と終了（モジュールの取り除き、アプリを閉じたときの片付け、ブックを開かれたときの引き渡し、時間切れでプロセスを終わらせる処理を含む）、所要時間は、Linux 上のビルドと、.bgra の読み込み・VBA の文面などの単体テストまでしか行っていない。

**実機で分かったこと（2026-11-23）**：取り込み専用に起動した Excel（ブックが 1 つもない状態）では、`GetImageMso` が最初から `E_UNEXPECTED`（0x8000FFFF）を返し、取り込みが打ち切られた。利用者の Excel は起動していたが、取り込みは別に起動した見えない Excel で行うため影響しない。そこで次のようにした。

- 取り込み専用の Excel を起動したら、作業用のブックを見えないまま 1 つ開き（終わったら保存せずに閉じる）、`FileSave` が取り出せるまで最大で約 5 秒待ってから取り込みを始める。作業用のブックは「利用者がブックを開いた」の判定に数えない。
- それでも取れなければ、利用者が開いている Excel を借りて取り込む。借りた Excel は終わらせず、表示も変えない。
- 失敗の記録（`prefetch-failed.json`）に取り出し方の版（`Method`）を持たせ、古い取り出し方での失敗は当てはめない。直したあとは、同じ版の Excel でももう一度自動で取り込む。

**実機で分かったこと（2026-11-23、その 2。Excel 16.0.20625、Sash は 64bit）**：上の対策の後も、作業用のブックを開いてやり直しても取り込み専用の Excel で `GetImageMso` は `E_UNEXPECTED`（0x8000FFFF）を返し、利用者が開いている（ブックの入った、見えている）Excel でも同じだった。一度は、取り込み専用の Excel が約 2 分半呼び出しを断り続け（`RPC_E_CALL_REJECTED`、0x80010001）、「応答しないため、起動し直す」となった。**`CommandBars.GetImageMso` は別のプロセスから呼ぶと使えない**と結論し（以前から、別のプロセスの IPictureDisp の HBITMAP は Sash からは読めないことも分かっていた）、次のようにした（`Method` = 3）。

- 取り出しを Excel の中で行う（上の表の「取り出し方」）。作業用のブックの待ち（`FileSave` を別のプロセスから取り出して待つ方法）と、利用者の Excel を借りる方法はやめた（どちらも役に立たず、借りると利用者の作業に触れるおそれがある）。ブックを開かれたときの引き渡しは残す。
- 1 件ずつの取得は、キャッシュだけを引く。
- 準備を 30 秒まで、起動し直しを 1 回までにし、応答しなくなった取り込み専用の Excel はそのプロセスだけを終わらせる。
- 2 までの失敗の記録は当てはめず、同じ版の Excel でももう一度自動で取り込む。
- **この方法も、利用者の PC で確かめるまでは未確認。** app.log の「作業用のブックに VBA モジュールを入れた」「Excel の中（VBA）で FileSave を取り出せた」「Excel の中（VBA）で取り出せなかった … Err.Number=…」「imageMso の取り込みを完了」を見て確かめる。


**実機で分かったこと（2）**：VBA モジュールは入れられたが、`Application.Run("'Book2'!SashImageMsoExport.SashExportImageMso", …)` が 0x800A03EC「マクロを実行できません…」で失敗した。原因が名前の書き方か、マクロの設定か、モジュールのコンパイルかを切り分けるため、次のようにした。

- 作業用のブックを開く前に `AutomationSecurity` を 1（マクロを有効）にする。変えられなければ記録する。
- 確認用の小さな関数（`SashImageMsoPing.SashPing`）を別のモジュールに入れ、名前の書き方を 4 通り（関数名だけ、モジュール.関数、ブック名!モジュール.関数、'ブック名'!モジュール.関数）で順に呼ぶ。呼べた書き方を本体にも使い、呼べなかった書き方と理由をすべて記録する。
- 確認用の関数は呼べたのに本体が呼べなければ、本体のコンパイルの問題として記録する。

**実機で分かったこと（3）**：上の「マクロを実行できません」の原因は、入れたモジュールのコンパイルエラーだった。VBE の「変数の宣言を強制する」がオンだと、モジュールを追加した時点で Excel が先頭に `Option Explicit` を書き、Sash のコードの `Option Explicit` と重なって「Option ステートメントは既に存在します」になる。モジュールを追加したら、Excel が書いた行を消してからコードを入れるようにした（取り出し方の版 5）。

### 17.8 同梱のアイコン集（Fluent UI System Icons・Tabler Icons。0.3.1 で Lucide と Sash のオリジナルを追加：§24）

- Tabler を足した理由：Fluent は画面部品が中心で、ビジネス（グラフ・請求・倉庫・フォークリフト）・食べ物・乗り物・アルファベット（letter-a〜z、number-0〜9 と、丸・四角つきの変種）が薄い。Tabler は検索用のタグとカテゴリを元データに持つので、概念検索の手がかりになる。
- ブランドのロゴを除く理由：ボタンのアイコンには使いにくく、商標の扱いが別になるため。
- 動物は Tabler・Fluent を合わせても約 57 個（cat・dog・fish・horse・pig・deer・rabbit・turtle・paw など）。元のアイコン集に動物が少ないためで、さらに増やすなら別のアイコン集（例：Phosphor）を足す。
- データは `cd ui && npm run fluent-icons` / `npm run tabler-icons` で作り直し、**生成物をコミットする**（ビルドはパッケージを読まない）。パッケージの版を上げたら、`LICENSE-*.txt` の冒頭の版も合わせる。
- Tabler のデータの形：`icons[名前] = [カテゴリ番号, タグ（空白区切り）, 線のパス, 塗りのパス]`。線は stroke-width 2・丸い端で描く線のパスで、線だけのパスは 1 本にまとめる（fill が none なので見た目は変わらず、小さくなる）。線と塗りの両方を使うパスは先頭に `#`、塗りだけは `@` を付けて分けて持つ。塗りはまとめず（逆回りの部分で穴が空くため）配列のまま。パスの数字は読みやすさの空白を詰め、詰める前後で数字の並びが同じことをビルドで確かめる。
- **色の入れ方が違う**：Fluent は塗りのパスなので色は `fill`、Tabler の「線」は輪郭なので色は `stroke`（`fill` に入れると輪郭が塗りつぶされる）。`buildSvg`（`fluent.ts`）が出どころと種類で切り替える。画面に直接置く一覧は `'currentColor'` を渡して描く（暗いテーマでも見えるように）。
- 全体の大きさ：JSON の合計 4.4MB（gzip で約 1MB）。ダイアログを開いたとき、またはラベルから候補を出すときに初めて読み込む（起動を遅くしないため）。ビルドでは `fluentIcons-*.js`・`tablerIcons-*.js` の別チャンクになる。

**3. 検索（概念による絞り込み）**

「お金」「配送」「ねこ」のようなあいまいな日本語で関係するアイコンを絞る。実装は `ui/src/fluent/iconSearch.ts`（検索）・`iconConcepts.ts`（概念の辞書）・`iconCategories.ts`（カテゴリ）。

- **入力の扱い**：全角半角・大文字小文字・ひらがな→カタカナ・長音の揺れを吸収する。空白・読点・中黒と、英数字と日本語の境目（「CSV出力」→ csv / 出力）で語に分ける。変換中（IME の組み立て中）は検索しない。
- **概念の辞書**：685 の概念（見出し 7,124 個〈のべ。重複を除くと 6,941〉、英語の言葉 1,395 種〈重複を除いた種類の数〉。0.3.1 で 418・4,447・1,134 から拡充：§24.3・§24.6）。1 つの概念は「日本語の見出し（読みのひらがなを含む）」と「関係する英語の言葉」の組。例：お金/費用/コスト/売上/経費 → money, cash, coin, currency, wallet, receipt, calculator, chart …。ビジネス・事務（生産計画・在庫・出荷・品番・図面・仕様・工程・納期・稼働・品質・承認・確認 など）、文書・操作、人、動物、乗り物、食べ物、天気・自然、図形・記号・文字を含む。以前からの小さな辞書（`JA_KEYWORDS`）も合わせて使う。
  - 英語の言葉は、代表的なものほど前に書く（前ほど重い）。名前の単語（truck）、Tabler のタグ（delivery）、単語の並び（`building-factory`：名前の中でその順に並ぶものにだけ当たる）が使える。
  - 辞書の見出しの引き方：そのまま一致 > 入力の途中（「はいそ」→配送）> 言い回しの付いた語（「保存する」）> 語の中に見出しを含む（「売上集計」の「売上」）。**そのまま一致する見出しがあれば、それだけを使う**（「ログイン」で、前方が同じ「ログ」＝履歴まで広がらないように）。1 文字の見出し（上・表 など）は、入力がその 1 文字だけのときにしか使わない。
  - 辞書の言葉が検索で 1 つも当たらないものを残さないよう、テストで確かめる（`iconSearch.test.ts`）。
- **点の付け方**：名前が言葉と同じ > 名前の単語が同じ（先頭の単語ならさらに上）> タグが同じ（先頭のタグほど上）> カテゴリ > 前方一致 > 部分一致。広げた言葉の重みを掛ける。1 つの語に当たった言葉が多いアイコンを少しだけ上げる（上げ幅は最高点の 4 分の 1 まで。名前の完全一致が加点で抜かれないように）。
  - 前方一致と部分一致は、利用者が打った英語の言葉だけ。辞書で広げた言葉に使うと、car が card・cart・category に当たるなど、関係のないものまで広がる。
  - 辞書で広げた語は、最高点の 4 分の 1 に満たない末尾を落とす（box のような広く当たる言葉で長い尾が付くため）。
- **複数の語**：すべてに合うもの（AND）を点の合計の順に出す。1 つも残らなければ、いずれかに合うもの（OR）に広げ、画面にその旨を出す（両方に合うものは上に出す）。
- **最長一致**（`conceptsInText`）：ラベルの中で、より長い見出しの範囲に収まる短い見出しは使わない（「ログイン」の中の「ログ」＝履歴が当たらないように）。
- **食べ物の概念は食べ物のカテゴリだけ**：食べ物・飲み物・コーヒー・ビール・肉・野菜・果物・米・ハンバーガー・調味料は、食べ物のカテゴリのアイコンだけに当てる（「ばなな」→ apple のタグが機器 device-imac に当たらないように）。ラベルからの候補（`searchTerms` の `onlyCategory`）も同じ。
- **意味の違う同名の単語を外す**：辞書で広げた `print` は、名前に `paw` を含むアイコン（animal_paw_print）に当てない（「印刷」の上位に動物の足跡が出ないように）。利用者が英語で打った言葉は外さない。
- **近い言葉の案内**（`relatedConcepts`）：2 文字以上のときだけ出す（1 文字は関係のない見出しが並ぶため。1 文字の英数字は letter-a・number-5 に当たるので案内がいらない）。英語の画面では、見出しではなく概念の最初の英語の言葉を出す（押すとそのまま検索できる）。
- **ラベルからの候補の足切り**：インスペクタは、概念の辞書にも当たらない言葉のときは、大きなアイコン集のデータを読み込まない（`hasSuggestTerms`。昔からの小さな辞書だけで判定すると「出荷」「精算する」「猫」で候補が出なくなる）。概念の辞書（`iconSearch.ts`）は動的 import で読み、起動時の読み込みに入れない。
- **1 文字**：`a`・`Ａ` は letter-a（と circle-letter-a など）、`5` は number-5 に絞る。1 文字で単語の前方一致をすると何にでも当たるため。
- **速さ**：アイコンの数が増えても重くならないよう、名前の単語・タグ・カテゴリの索引（単語 → アイコン）を、読み込みの後に 1 度だけ作る（約 8,000 個で 100ms 前後）。前方一致は並べた単語の一覧を二分探索する。8,000 個の検索は、よくある語で 1〜20ms（テストの目安は中央値 30ms 未満）。
- **当たった理由**：一覧の項目の説明（ツールチップ）に、名前と出どころ（Fluent / Tabler）、辞書で広げたときは「お金 → money」のような理由を出す（上位 400 件まで）。
- **合うものがないとき**：辞書の見出しから、文字の並びが近い言葉（2 文字組の重なり）を「近い言葉」として並べ、押すとその言葉で探す。何も近くなければ、よく使う言葉を出す。

**5. ダイアログ（`ui/src/fluent/fluentDialog.ts`）**

- タイトルは「アイコン集から選ぶ」。検索欄・スタイル（線 / 塗り）・出どころ（すべて / Fluent / Tabler / Lucide / Sash）・カテゴリのチップ・色（右の欄のパレット。既定は #424242。§24.4）・一覧・プレビュー（実寸 16 / 32、明暗の背景）。
- 前回のスタイル・色・出どころは、この利用者の手元（localStorage）にだけ覚える。保存できない環境では既定に戻るだけ。
- 一覧は 240 個ずつ描き足す（スクロールで続きを読む）。矢印キー・Home / End・PageUp / PageDown で移れ、Enter で選び、もう一度 Enter（か項目のダブルクリック）で決定する。検索欄で Enter だけ押すと先頭を選ぶ。
- 選んだアイコンは色を付けた SVG にして返す（`FluentPick`：`set` で出どころを持つ。ファイル名は Fluent が `<名前>_<種類>.svg`、Tabler が `tabler-<名前>_<種類>.svg`。同じ名前（home など）が両方にあるため）。PNG にするのはアイコンエディタの役目。
- 色の既定は Excel の明るいリボンになじむ #424242。取り込むときは自動カットを切り、余白を 0% にする（アイコン集は余白込みで大きさをそろえてあるため）。
- 検索の辞書（`JA_KEYWORDS`）は `Object.hasOwn` で引く。索引と概念の辞書は `Map` で持つので、`constructor`・`__proto__` のような語で Object.prototype のものを引いて落ちることはない。

**6. ラベルからの候補（`ui/src/iconSuggest.ts`）**

インスペクタのアイコン欄が、ラベルから「たぶんこれ」を最大 5 個出す。ラベルの中の言葉を概念の辞書で引き、**概念ごとに、その概念が持つ英語の言葉すべてで探す**（「在庫確認」なら在庫の仲間と確認の仲間）。概念の順に 1 つずつ交互に取る。辞書にない英数字の語（Excel・PDF など）はそのまま探す。imageMso の候補は、以前からの小さな辞書（`JA_KEYWORDS`）で探す。
- 候補の一覧（`loadFluentIcons`）はこれまでどおり Fluent だけを返す。Fluent と Tabler の両方から探すには `loadIconSet`（`fluent.ts`）を使い、一覧は `buildSvg(icon, 'regular', 'currentColor', 20)` で描く（Tabler の線は stroke に色を入れるため、`fill="#000000"` を `currentColor` に置き換える今の描き方では、暗いテーマで黒い線になる）。

## 18. 配る前の確かめと幅の確認（2026-11-23 追加）

作ったリボンを配る前に「狭い画面でどう見えるか」「押して動くか」「直し忘れがないか」を、Sash の中で確かめられるようにした。
この章は三つの持ち場で作った。§18.1〜§18.8 はホストと画面の外枠（メニュー・ダイアログ・Excel 連携）、§18.9 はキャンバスの幅のプレビュー、§18.10 はツリー・インスペクタ・Lint の分。

### 18.1 Excel のウィンドウの幅を合わせる（`excel.setWindowWidth`）

| 項目 | 内容 |
| --- | --- |
| 要求 | `excel.setWindowWidth { width, scale, path? }`。width は拡大率をかける前の画面の幅（物理 px。例：1920）、scale は Windows の拡大率（1.5 = 150%。10 以上なら % とみなすので 150 でもよい。プレビューが % で持つため）。応答は `{ points, logicalWidth, workAreaWidth, workbook, actualWidth?, expectedWidth? }`（前の三つは論理 px、後の二つは物理 px）。path が空（サンプル）なら「指定なし」とみなす |
| 換算 | アプリから見える幅（論理 px、96 dpi を 1 倍とする単位）は width / scale。`Application.Width` はポイント（1/72 インチ）で、論理 px は 1/96 インチなので、**拡大率に関係なく 論理 px × 0.75**。拡大率は「1 インチを何物理 px で描くか」を変えるだけで、論理 px とポイントの比は変えないため（例：1920 幅・150% → 1280 論理 px → 960pt） |
| 対象 | path のブックを開いている Excel。普通のブックはそのウィンドウを前にしてから合わせる（Excel 2013 以降はブックごとにウィンドウがあり、`Application.Width` はアクティブなウィンドウに効くため）。アドイン（xlam）はウィンドウを持たないので、その Excel のいま前にあるウィンドウを使う。path がない・開かれていなければ、起動中の最初の Excel |
| 手順 | まず収まるかを確かめ（下の「断るとき」）、収まるときだけブックのウィンドウを前に出す（断るときに利用者のアクティブなブックを変えないため。確かめるモニターは、Excel 2013 以降の `Window.Hwnd` で取ったそのブックのウィンドウのもの）。`WindowState = xlNormal（-4143）` にしてから `Width` を入れる（最大化のままでは効かない）。入れた後に `GetWindowRect` で幅を測り、期待の幅（論理 px × モニターの dpi / 96）と 2px より大きくずれていたら、差の分だけ 1 回だけ `Width` を直す。それでも合わなければ、測った幅を応答（`actualWidth`・`expectedWidth`、物理 px）に入れ、UI は「ただし実際の幅は N px でした」と添える（**要確認**：実機で `Width` と枠の分のずれ方を確かめていない）。最後に、ウィンドウが作業領域からはみ出したら、はみ出した分だけ `Left` を動かす |
| 断るとき | 論理 px にした幅が、Excel のあるモニターの作業領域より広いとき（Windows がウィンドウを縮めてしまい、測りたい幅にならないため）。作業領域は `MonitorFromWindow` と `GetMonitorInfo` の `rcWork`（物理 px）を、`GetDpiForMonitor`（MDT_EFFECTIVE_DPI）で論理 px に直して比べる。座標を物理 px で受け取るよう、呼び出しの間だけ COM のスレッドを Per-Monitor V2 にする（Sash のプロセスは PerMonitorV2）。0.5px までの差は収まるものとみなす。幅は 320〜10000、拡大率は 50%〜500% の外なら断る |
| 計算の置き場 | 換算と判定・ずれの直し方（`ExpectedPhysicalWidth`・`CorrectionPoints`）は `Sash.Core/Excel/ExcelWindowSizing.cs`（COM に触らないので単体テストする）、COM の呼び出しは `Sash.Excel/ExcelService.SetWindowWidthAsync` |
| メニュー | 表示 メニューの「Excel をプレビューの幅にする」（プレビューの幅が「自由」のときは無効）。キャンバスの見出しの「表示 ▾」にも同じ名前で置く。どちらも `ui/src/views/excelWidth.ts` の `fitExcelToPreview` を呼ぶ |

`Application.Width` の値には、ウィンドウの枠の幅も入る。リボンが使える幅は、それより枠と左右の余白の分だけ狭い。

### 18.2 配布前チェック（ツール メニュー・コマンドパレット）

配る前に見ておくべきことを分類ごとに件数つきで並べ、押すとその場所へ移る（要素を選ぶ、またはコールバック・アイコンの一覧を開く）。集計は `ui/src/distributionCheck.ts`（純粋な関数）、画面は `ui/src/dialogs/distributionDialog.ts`。開いている間に問題・VBA の照合・キャンバスの見積もりが変わったら描き直す（直しながら見られるように）。

| 分類 | 重さ | 中身 |
| --- | --- | --- |
| VBA にない・引数の合わないコールバック（照合できていないとき） | 要確認（未確認） | コールバックがあるのに VBA と照合できていなければ、この分類を一番上に出し、件数の代わりに「未確認 N」（N はコールバック名の数）と出す |
| エラーと警告 | 要確認 | Lint のエラーと警告。キーヒント・ラベルの長さ・VBA との照合の警告は、それぞれの分類に回して二度数えない |
| VBA にない・引数の合わないコールバック | 要確認 | 照合の結果が「未実装」「引数が不一致」のもの。**VBA と照合していなければ数えず、理由を出す** |
| チェックする画面の幅で畳まれる・収まらないグループ | 収まらない＝要確認、畳まれる・畳んだときのアイコンがない＝見直し | キャンバスが測った結果（§18.9）。まだ測っていなければ「キャンバスで幅を選ぶと確認できます」。畳んだときのアイコンがないものは、グループごとではなく「N グループで畳まれたときのアイコンが未設定です」の 1 行にまとめる（押すと最初のグループを選ぶ。汎用のアイコンで出るだけなので、並べると大事な項目が埋もれるため） |
| キーヒントの重複 | 要確認 | Lint の keytip の問題（重複・4 文字以上） |
| 長いラベル | 見直し | Lint のラベルの長さの警告（§18.10） |
| 使っていない画像 | 見直し | ファイルに入っているが、どの image 属性からも使われていない画像。VBA の getImage / loadImage で使っていればそのままでよいと添える |
| ヒント（screentip）のないボタン | 見直し | 自作（id / idQ）の button・toggleButton・menu・dynamicMenu・gallery で、リボンのグループに（box・buttonGroup・splitButton を通して）直接置いたもの。組み込み（idMso）は Excel が自分のヒントを持つので、メニューの中の項目はヒントが出ないので除く |
| アイコンのないボタン | 見直し | 同じ範囲で image / imageMso / getImage がなく、showImage="false" でもないもの |
| VBA で決まるラベル・文言 | 参考 | getLabel・getScreentip・getSupertip・getDescription・getKeytip・getText・getTitle・getHelperText・getAltText・getItemLabel。キャンバスには中身を出せないので、Excel で確かめてもらう |

見出しは、コールバックがあるのに VBA と照合できていなければ「VBA と照合できていません（コールバック N 件は未確認）」（ほかに要確認があれば「。ほかに M 件の確認が必要です」を続ける）。照合できていて「要確認」の件数が 0 なら「配ってよい状態です」、そうでなければ「N 件の確認が必要です」。照合できていないのに「配ってよい」と言うと、配った先で「マクロが見つかりません」になりうるため。「見直すとよいもの N 件」を添える。分類は 照合できていないコールバック → 要確認を含むもの → 見直し → 参考 → 0 件 の順に並べる。

### 18.3 コントロール一覧の書き出し（ファイル メニュー）

- 「コントロール一覧」▸「CSV ファイルに書き出す…」と「クリップボードにコピー」。列は タブ・グループ・種類・ラベル・id・マクロ・ヒント・キーヒント・画像。
- 行にするのはコントロール（スキーマの isControl）だけ。box・buttonGroup・区切り線・dialogBoxLauncher・dropDown などの item（選択肢）は行にしない（中のコントロールは出す）。右クリックメニューはタブの列に「右クリック：<idMso>」、クイックアクセス・Backstage もその名前を書く。
- VBA で決まる値は「（VBA：<Sub 名>）」。マクロの列には表示用（getLabel・getImage など）以外のコールバックを並べ、onAction は名前だけ、ほかは「名前 (属性)」。画像は image の Id、imageMso は「imageMso:<名前>」。
- **CSV は BOM 付きの UTF-8・CRLF。** BOM がないと、日本語版の Excel はダブルクリックで開いたときに Shift_JIS として読んで文字化けするため。値は , " 改行・前後の空白を含むときだけ "" で囲む（RFC 4180）。書き込みは `file.exportText`（ホストは BOM なしの UTF-8 で書くので、UI が先頭に U+FEFF を付ける）。
- 数式に見える値（= + - @ で始まるもの）に ' は付けない。自分のリボンの定義を書き出すもので、付けると値そのものが変わってしまうため。
- クリップボードには TSV（BOM なし）で入れ、Excel のセルにそのまま貼り付けられるようにする。値の中のタブと改行は空白にする（貼り付けで表が崩れないように）。
- 純粋な処理は `ui/src/controlList.ts`。

### 18.4 試しに押す（マクロを Excel で試す）

- キャンバス・ツリーの右クリックメニュー、ツール メニュー、コマンドパレットの「マクロを Excel で試す」。選んだコントロールの onAction を、開いているブックで `Application.Run "'<ブック名>'!<モジュール.>Sub"` で実行する（ブック名を付けるのは、同じ名前の Sub がほかのブックやアドインにあっても、開いているブックのものを実行するため）。要求は `excel.runMacro { path, macro, controlId?, argument? }`。
- **呼べる形**：引数のない Sub はそのまま呼ぶ。引数が 1 つで、型が IRibbonControl（Office. 付きも）・Object・Variant（型なしを含む）の Sub は、**control に Nothing を渡して**呼ぶ（`Application.Run name, New DispatchWrapper(Nothing)` に当たる。C# では `new DispatchWrapper(null)`。ただの null は VT_EMPTY＝引数の省略になり、「マクロを実行できません」になるため）。それ以外（引数が 2 つ以上・配列・ParamArray・String などほかの型）は理由を添えて断る（toggleButton・checkBox の onAction は引数が 2 つなので断る）。代わりのオブジェクトを差し込むコードをブックに足すことはしない（利用者のブックを書き換えないため）。**要確認**：実機の Excel で Nothing がこの形で渡るかは確かめていない。
- 押す前の知らせ：control に Nothing を渡すときは、確認のダイアログで「control 引数には Nothing を渡します。Sub の中で control.Id などを使うと実行時エラーになります」と知らせ、「実行する / キャンセル」を選んでもらう。
- 確かめ方：UI は照合済みの VBA（§8.2）の宣言から、読めていなければ XML のコールバックの形（`callbackSignature`）から呼び方を決め、呼べない形なら押す前に断る（`ui/src/vbaReveal.ts` の `checkRunnable`・`macroArgument`）。右クリックメニューでは、無効のときに項目の下に理由を出す（無効の項目にはツールチップが出ない環境があるため）。ホストは、VBA を読めれば（信頼の設定がオン）宣言から決め直し、読めなければ UI の `argument`（`none` / `control`）に従う。宣言の解析と呼び方の判定は `Sash.Core/Excel/VbaProcedureLookup.cs`（`FindParameters`：行継続 " _"・既定値の中の入れ子の括弧 `Array(1, 2)`・文字列の中の括弧に対応。`SplitParameters`・`Classify`）。
- 名前の確かめ：VBA を読めないときも、モジュール名と Sub 名が VBA の識別子（文字で始まり、文字・数字・_ だけ、255 文字まで。`VbaProcedureLookup.IsVbaIdentifier`）であることを必ず確かめる（Application.Run に渡す名前は Sash が組み立てるので、記号の混ざった名前は通さない）。
- マクロが MsgBox などを出しても Sash の後ろに隠れないよう、実行の前に Excel のウィンドウを前に出す。
- **実行中**：マクロが MsgBox やエラーのダイアログで止まると、閉じるまで COM のスレッドがふさがる。そこで UI は実行中ずっと「Excel でマクロを実行中です（Excel 側でメッセージやエラーを閉じると戻ります）」の通知を出したままにし（終わったら結果に差し替える）、ホストは `ExcelService` に実行中の印（`IsMacroRunning`。Run の前に立て、終わったら下ろす）を持つ。実行中は、Excel を使うほかの要求（`excel.apply`・`vba.read`・`vba.insert`・`vba.replaceLine`・`vba.reveal`・`excel.setWindowWidth`・`icons.prefetchStart`）を、COM のスレッドに並べずに入り口（`MessageRouter`）ですぐに同じ理由で断る。`excel.imageMso` は Excel に取りに行かずキャッシュだけで答える。二つ目のマクロも断る。`excel.labels` は並べる（起動時に一度だけ読むもので、断ると表示名がその間ずっと取れなくなるため）。

### 18.5 コールバック一覧から VBE の該当の Sub へ移る

- 要求は `vba.reveal { path, module, procedure }`。VBE を表示し（`VBE.MainWindow.Visible = True`）、`CodePane.Show` の後に宣言の行をまるごと `SetSelection(行, 1, 行, 行の長さ + 1)` で選び、少し上の行から表示する。行は `CodeModule.ProcBodyLine(name, vbext_pk_Proc)` で取る（`ProcStartLine` は Sub の前のコメント行から数えるため、宣言そのものの行にならない）。VBE のウィンドウを前に出す。
- どのモジュールにあるかは、照合のときに読んだ VBA から UI が決める（`ui/src/vbaReveal.ts` の `revealInVbe(name)`）。照合できていない・VBA にないときは理由を知らせる。
- 入口は、コールバック一覧の各行のボタン（下部パネル）、要素の右クリックメニューの「VBE で <名前> を表示」、コマンド「選択中のコントロールのコールバックを VBE で表示」。

### 18.6 操作の履歴（編集 メニュー）

- 「操作の履歴…」で、元に戻す・やり直しの一覧を古い順に並べる。先頭は「記録の始まり」（開いたとき、または上限の 200 件でそれより前が消えたところ）。押すと、その操作の直後の状態へまとめて移る。移った後もダイアログは残し、ダイアログの中で Ctrl+Z（元に戻す）・Ctrl+Y / Ctrl+Shift+Z（やり直し）を押しても位置が動く（モーダルの間はアプリのショートカットが届かないので、ダイアログが自分で受ける）。やり直せる（取り消した）操作は薄く・取り消し線で示す。
- ストアに `history(): { labels, index }`（labels は古い順の操作の名前、index は適用済みの操作の数）と `goTo(index)` を足した。goTo は元に戻す・やり直しを続けて行うのと同じ結果になるが、途中で XML を読み直さず、通知は最後の 1 回だけにする（何十件も戻るときに描き直しを繰り返さないため）。範囲の外は端に丸める。

### 18.7 表示 メニューの幅のプレビューと、左右のペインを畳む

- 表示 メニューに「画面の幅」▸ 自由（キャンバスの幅）/ 1280 / 1366 / 1920 / 2560、「拡大率」▸ 100% / 125% / 150%、「表示のしかた」▸ 全体を表示 / 実寸、「キーヒントを表示」、「Excel をプレビューの幅にする」を置く（キャンバスの見出しと同じ言葉にそろえた）。コマンドパレットからも同じものを呼べる。設定の持ち主はキャンバス（`views/ribbonPreview.ts`）で、メニュー（`shell/previewCommands.ts`）はキャンバスの `setPreviewWidth` / `setPreviewScale` / `setFitMode` / `toggleKeytips` を直接呼ぶ（先に設定だけを書き換えてから知らせると、キャンバスが「変わっていない」とみなして一時的に広げたグループを畳み直さず、描き直しも二度になるため）。window の `sash:preview` はほかから切り替えるための入り口として残す。
- 「左右のペインを一時的に畳む」：パレット・ツリー（左）とインスペクタ（右）を畳み、「元に戻す」付きの通知を出す。大きさは保存しない（次の起動では元に戻る）。元に戻すときは、その間に利用者が自分で開き直したペインはそのままにする。キャンバスからは window の `sash:collapseSidePanes` で頼まれる。

### 18.8 幅の試験用リボン（レシピ）と、畳まれる順番の測り方

レシピ「幅の試験用リボン」は、Excel が狭い画面でグループを畳む順番を実機で測るためのタブ（`tabWidthTest`）を入れる。グループは 7 つで、すべてにグループの画像（畳んだときに出る）を付ける。

| グループ | 中身 |
| --- | --- |
| 大きいボタン | 大きいボタン 4 つ（ラベル 4・6・8・10 文字） |
| 小さいボタン（autoScale） | 小さいボタン 6 つ（4・6・8・10・4・6 文字） |
| 空白入り | 大きいボタン 2 つ（「月次 集計」「シートを 新しく 作る」）、小さいボタン 1 つ。空白で 2 行に分かれる位置を見る |
| 入力 | dropDown（項目 3 つ）、editBox（sizeString="00000"）、comboBox |
| 混在（autoScale） | 大きいボタン、toggleButton、checkBox、区切り線、小さいボタン 2 つ |
| アイコンだけ | showLabel="false" のボタン 3 つ |
| 自動調整（autoScale） | 大きいボタン 2 つ（8・10 文字）と小さいボタン 3 つ |

ボタンはすべて共通の `Ribbon_WidthTest_onAction`（押した id を MsgBox で出す）、toggleButton と checkBox は `Ribbon_WidthTest_onToggle` を呼ぶ。10 文字の大きいボタンはわざと長くしてあり、ラベルの長さの警告が出る。

**測り方**

1. 新しいブック（xlsm）に「幅の試験用リボン」を入れ、VBA も入れて保存し、Excel へ反映する。
2. 表示 メニューの「リボンの幅」と「拡大率」を、1280 / 1366 / 1536 / 1920 のそれぞれに（拡大率は実機の設定に合わせて）切り替え、「Excel のウィンドウをプレビューの幅に合わせる」で Excel のウィンドウを同じ幅にする。1536 は選択肢にないので、キャンバスの「カスタム…」で入れる。
3. 幅ごとに、Excel のリボン（「幅の試験」タブ）とキャンバスのスクリーンショットを撮る。ファイル名は `<幅>_<拡大率>_excel.png` / `<幅>_<拡大率>_sash.png` とする。

5. Excel の版・ビルド、Windows の拡大率、モニターの解像度、フォントの設定を一緒に記録する。

### 18.9 キャンバスの幅のプレビュー（キャンバスの持ち場）

キャンバスの幅は既定のペイン（左 248px・右 300px）で、1920 幅の画面でも 1370px（Excel のリボンの約 7 割）しかない。そのため、狭い画面でグループが畳まれることに配る前に気づけるよう、リボンを決まった幅で描けるようにした。

### 18.11 Windows 実機で確かめていないこと

`excel.setWindowWidth`（`Application.Width` が換算どおりの幅になるか、SDI でのウィンドウの選び方、複数モニター・DPI の違うモニターでの作業領域と `Left` の動かし方、ウィンドウの枠の分）、`excel.setWindowWidth` の測り直し（`GetWindowRect` の幅と期待の幅のずれ方、1 回の直しで合うか、ブックを前に出す前の `Window.Hwnd` でのモニターの決め方）、`excel.runMacro`（`Application.Run` の名前の書き方、`DispatchWrapper(null)` で control に Nothing が渡るか、アドインのマクロ、Excel を前に出す動き、実行中の印で他の要求をすぐに断る動き）、`vba.reveal`（VBE の表示・宣言の行をまるごと選ぶ動き・前に出す動き）、CSV を Excel で開いたときの文字化けしないこと、§18.8 の測定は、Linux 上のビルドと単体テスト、ブラウザ（モック）での確認までしか行っていない。

## 19. 複数選択とまとめて変更（2026-11-23 追加）

リボンを狭い画面の幅に収めるとき（§18.9 の幅のプレビュー）は、いくつものコントロールを一度に変えることが多い（6 個のボタンを小さくする、何個かを別のグループへ移す、まとめて消す・写す）。そこで、キャンバスとツリーで複数の要素を選び、まとめて変更・操作できるようにした。

### 19.1 選択のモデル（`store.ts`）

| 項目 | 内容 |
| --- | --- |
| 主な選択と選択の組 | `selection: Path \| null` は**主な選択**（フォーカスのある要素）のまま残し、`selections: Path[]`（文書の順、主な選択を含む）を足した。インスペクタの単独表示・XML の強調とカーソル・挿入の位置・パレットの「置けるか」は、これまでどおり主な選択で決める。既存のコードは `selection` だけを見ても動く（互換のため） |
| 操作 | `select(path, source)`（1 つだけにする）・`toggleSelect`（Ctrl / ⌘+クリック。選んでいなければ足して主な選択にし、選んでいれば外す。最後の 1 つを外すと何も選ばない）・`selectRange(path, source, order?)`（Shift+クリック）・`selectAll(source, order?)`（Ctrl+A。主な選択の兄弟をすべて。`order` を渡すとその中の兄弟だけ）・`clearMulti(source)`（Esc。主な選択だけに戻す）。どれも `selection` の変更として通知する。読み取りは `selectedElements`・`isMulti`・`isSelected(path)` |
| 範囲の決め方 | 起点（最後に単独で選んだか Ctrl+クリックで足した要素）と目的の要素が同じ親なら、その間の兄弟を選ぶ。親が違うときは、ツリーでは**いま見えている行の順**、キャンバスでは描かれている順（先行順）で範囲をとり、範囲の中のほかの要素の祖先（間にあるグループなど）は外す。見えている順（`order`）を渡したときは、**同じ親でも見えている兄弟だけ**を選ぶ（ツリーの絞り込みや畳んだ行で隠れている兄弟を選ぶと、続けて Delete を押したときに見えない要素まで消えるため）。畳んだ中身は選ばない。Ctrl+A も同じで、ツリーは見えている行、キャンバスは描かれている要素の中の兄弟だけを選ぶ。メニューとコマンドパレットの「同じ階層をすべて選択」は、ツリーを絞り込んでいるときはツリーに見えている行の中だけ、絞り込んでいなければすべての兄弟を選ぶ |
| 祖先と子孫 | 祖先と子孫を一緒には選ばない（`normalizeSelections`）。足したほうを優先する（グループを足すと中のコントロールが外れ、コントロールを足すとそのグループが外れる）。祖先を消す・移すと子孫も一緒に動くので、両方を選ぶと同じ要素を二重に扱ってしまうため |
| 編集のあとの選び直し | `edit` は、選んでいた要素をパスではなく**要素そのもの**で覚えておき、編集のあとで今の位置のパスに直す。前に挿入・削除・移動があっても同じ要素を選んだままになり、消えた要素だけが外れる。編集のあとで指せなくなったパスは `selections` に残さず、主な選択が指せなければ残りの最後を主な選択にする（`selections` が無効なパスを持たないようにする）。fn がパスを返したら、その 1 つだけを選ぶ（従来どおり）。複数を選ばせたいときは `selectMany(paths, primary?)`（`SelectionSet`）を返す（空の配列が「customUI を選ぶ」と区別できないので包む） |
| 履歴 | 元に戻す・やり直し・操作の履歴での移動で、選んでいた組も戻す。XML の書き換えで指せなくなったパスは外す |

### 19.2 キャンバスとツリー

| 項目 | 内容 |
| --- | --- |
| マウス | Ctrl（⌘）+クリックで選び足す・外す、Shift+クリックで範囲を選ぶ。キャンバスでは要素ごとのクリックの処理（タブの切り替え・メニューを開くなど）より先に、捕捉の段階で受けて止める |
| キー | ツリーの Shift+↑↓ で 1 行ずつ範囲を広げる・狭める。キャンバスとツリーの Ctrl+A で同じ階層の（見えている）要素をすべて選ぶ（入力欄の中では文字の全選択のまま）。Esc は、複数選択中なら主な選択だけに戻す（キャンバスで親へ上がるのは次の Esc）。ただし見出しの「表示」メニュー（とその先のメニュー）が開いているときの Esc は、メニューを閉じて「表示」ボタンにフォーカスを戻すだけで、複数選択は解かない。Alt+↑↓ はまとめて動かす |
| 見た目 | 主な選択はこれまでどおりの実線の枠（フォーカスがあれば `--focus` の色）。ほかの選択は破線の枠（`.multi-selected`、色は `--sel-bg`・`--sel-border` だけ）。ツリーの行も同じ地の色で、`aria-selected="true"`・`aria-multiselectable="true"`（treeitem なので、主な選択もほかの選択も同じく付ける）。キャンバスの要素には `aria-selected` を付けない（選べる項目の役割を持たず、タブは role="tab" の `aria-selected` を「表示中のタブ」に使っているため）。選んだ数は、作り直さない 1 つの読み上げ領域（`role="status"`・`aria-live="polite"`、画面には出さない）の文字を書き換えて知らせる。XML エディタでは、ほかの選択の開始タグに薄い飾りを付ける（カーソルとスクロールは主な選択に合わせる） |
| 選択の数 | キャンバスの見出し（1 行のまま）に「3 個選択中」。押すと主な選択だけに戻す。状態の文字（縮むほう）より前に置いて縮めず、ほかの欄と同じ高さにする（見出しの高さは変わらない）。見出しが狭いとき（コンテナークエリ）は「3 個」と短くする。さらに狭いとき（640px 以下）は選択肢の幅を中身に合わせて詰め、間を狭め、「ペインを畳む」を隠す（メニューの 表示 ＞ 左右のペインを一時的に畳む で同じことができる）。それでも入らないとき（520px 以下）は、幅の欄の右側を切る。どの幅でも「表示」と「?」は見出しの右端に残す（1100px の画面で左右のペインを開いたまま、幅のプレビューを使っても、はみ出さない） |
| 右クリック | 複数選択の中の要素で開くと、選択を保ったまま、まとめての操作のメニュー（数つきの切り取り・コピー・貼り付け・複製・削除、上へ・下へ、新しいグループに移す、大きく・小さく、選択を解除）を出す。使えない操作は理由を添えて無効にする。前に挿入・子を追加・ID をコピーなど、1 つの要素を前提にした操作は出さない |

### 19.3 インスペクタのまとめて変更

| 項目 | 内容 |
| --- | --- |
| 見出し | 「N 個の要素（ボタン 4・トグルボタン 2）」。内訳は多い順 |
| 出す属性 | 選んだ要素の**すべてで使える**属性だけ（`bulkEdit.ts` の `commonAttrDefs`）。id・idMso・idQ・image・getImage は出さない（id は重なってはいけない、idMso / idQ は要素ごとに違うのが普通、image は画像の取り込みと一緒に扱うため）。imageMso は出す（選ぶボタンつき）。getLabel のような静的な値と組の get 系も出さない |
| 値 | すべて同じならその値、違えば「（複数の値）」。真偽値は 1 / 0 を true / false にそろえて比べる。列挙値は「（複数の値）」を選んだ状態から選び直すと全部に入る。文字の欄は空欄に「（複数の値）」を薄く出し、空のまま離れても何も変えない（うっかり全部を消さないため。消すのは横の「消す」ボタン）。文字の欄（label・screentip・supertip・コールバック名）も変えられ、違う値を上書きするときも確認しない（元に戻す 1 回で戻せるため） |
| 入力の確かめ | 単独のインスペクタと同じ決まり（`attrValidate.ts` の `attrValueError`）で確かめる：コールバック名（`isCallbackName`。「モジュール名.Sub名」「ブック!Sub名」も可）、整数、keytip は 3 文字まで。合わなければ確定せず、欄の下に理由を出す（`field-error`・`aria-invalid`）。keytip の長さは、この変更で単独のインスペクタでも確かめるようにした（4 文字以上は Excel が読み込めないため） |
| 書き込み | 変えた値は選んだ要素すべてに、**一度の編集**で入れる。履歴の名前は「6 個の size を large に変更」。静的な値を入れると組の get 系を外し、imageMso を入れると image・getImage を外す（単独のインスペクタと同じ決まり） |
| よく使う操作 | 上部に「大きく」「小さく」（size を持つ要素だけを変える）と「新しいグループに移す」 |

### 19.4 まとめての操作（`multiEdit.ts`・`clipboard.ts`・`dnd.ts`）

どれも一度の編集（元に戻す 1 回で戻る）で、履歴に「3 個の要素を削除」のような名前を付ける。1 つでも置けないものがあれば**何も変えずに理由を知らせる**（一部だけ変わると、どれが変わったのか分かりにくいため）。置けるかどうかは、実際に置いてから並び順と個数の決まり（§17.2）に合うかを確かめる（`orderViolation`）。操作の前から決まりに合っていない要素（知らない要素、位置のずれたダイアログ起動ツールなど）は数えず、**操作で新しく生まれた崩れ**（動かした・足した要素、それに押されて合わなくなった要素）があるときだけ断る（もとから崩れた親で、関係のない操作まで断らないため）。動かす要素は、もとの位置で合っていなかったとしても、移した先で合わなければ断る。メニューの有効・無効と理由は、文書の写しで試して求める（`dryRun`）。

| 操作 | 内容 |
| --- | --- |
| 削除 | まとめて消す。消したあとは、最後に消した要素の後ろの兄弟、なければ前の兄弟、なければ親を選ぶ（1 つのときと同じ決まり）。「元に戻す」付きの通知を出す |
| コピー・切り取り | 内部のクリップボードに、選んだ要素を文書の順で XML の文字列として持つ。OS のクリップボードには、整形した XML を改行でつないで書く |
| 貼り付け | 置き場所は最初の要素で決め（選択中の要素の中か後ろ。1 つのときと同じ）、残りはその後ろに元の順で続ける。id は `renameDuplicateIds` で振り直す。貼り付けたものをまとめて選ぶ |
| 複製 | 親ごとに、複製したものを**その親の中で選んだ要素の最後の後ろ**に、元の順でまとめて置く（A B C → A B C A′ B′ C′）。1 つずつ自分の後ろに置く（A A′ B B′ C C′）と、複製した組がばらばらになり、そのまま別のグループへ動かしにくいため。ただし並び順の決まりのある親では、1 つずつ `allowedInsertIndex` で置ける位置に収める（dropDown で item と button を選んで複製すると、item の複製は item の並びの最後に、button の複製は選んだ button の後ろに入る：i1 i2 b1 b2 → i1 i2 i1′ b1 b1′ b2）。まとめて置ける位置なら、収めても位置は変わらない。複製したものをまとめて選ぶ |
| 上へ・下へ（Alt+↑↓） | 同じ親のときだけ、選んだ要素がそれぞれ隣の（選んでいない）兄弟と入れ替わる（選んだ要素どうしの並びは変わらない）。親が違えば「親の違う要素はまとめて上下に動かせません」として無効にする |
| ドラッグ＆ドロップ | 複数選択の中の要素をつかむと、選んだ要素をまとめて運ぶ（選んでいない要素をつかむと、その 1 つだけ）。落とした位置に元の順で入れ、1 つずつ並び順の決まりで置ける位置に収める（グループの末尾に落としても、ダイアログ起動ツールの前に入る）。入れられない親・運ぶ要素の中・並び順に合わない位置では、ドロップ先の表示を出さない（キャンバスとツリー）。つかんだ要素を主な選択にする |
| 新しいグループに移す | リボンのグループの中のコントロール（同じタブ）を選んでいるとき。選んだ最後の要素のグループのすぐ後ろに新しいグループ（id とラベルは既定の付け方）を作り、選んだ順で移す。移したあとで元のグループが空になっても、消さずに残す（ラベルや id、コールバックを持っていることがあるため） |
| 大きく・小さく | 右クリックメニュー・インスペクタ・編集 メニューの「並べ替えと大きさ」。size を持つ要素だけを large / normal にし、持たない要素は飛ばす |
| メニューとコマンドパレット | 編集 メニューの切り取り・コピー・複製・削除などは、複数選択のとき「削除（3 個）」のように数を付ける。「同じ階層をすべて選択（Ctrl+A）」「複数選択を解除」と、「並べ替えと大きさ」（上へ・下へ・新しいグループに移す・大きく・小さく。使えないときは理由をツールチップに出す）を足した。コマンドパレットにも同じものが出る |

## 20. 使い勝手の改善（2026-11-23 追加）

画面を一通り使ったレビュー（`ux3/REVIEW.md`）で見つかった使いにくさの修正。ここには、決めたこととその理由を項目ごとに記す。

### 20.1 レシピの VBA 画面（D-1）

レシピを挿入したあと、VBA をクリップボードにコピーできなかったとき（WebView2 でフォーカスがない場合など）は、コードを画面に見せる。

- 題は「VBA に貼り付けるコード」。貼り付け先のモジュール（まだなければ作る共通モジュール・コールバックのモジュール・ThisWorkbook）ごとに、見出しと［コピー］を置く。
- フッターは［すべてコピー］（主）と［閉じる］。開いたら［すべてコピー］にフォーカスがある。
- 一括のコピーは、モジュールごとに `' ===== 名前 =====` の見出しコメントで区切る（`joinSections`）。
- 理由：以前は［閉じる］しかなく、選択して手でコピーするしかなかった。コピーに失敗した直後の画面なので、もう一度押せるボタンを置く。

### 20.2 アイコンライブラリが空のとき（D-2）

- ライブラリに 1 つもないときは、検索欄・タグの切り替え・格子を隠し、中央に空の状態（説明と［アイコンを作る…］）を出す。足もとには場所だけを出す。
- ［アイコンを作る…］は、要素を選んでいるときだけ押せる（アイコンエディタの対象が要るため）。選んでいなければ無効にし、理由（「先にキャンバスかツリーで、アイコンを付けるボタンなどを選んでください」）をボタンの下と title に出す。
- ［アイコンを作る…］でアイコンエディタを開く処理は、`openLibrary` の `opts.onCreateIcon` で呼び出し側（main.ts）から渡す。アイコンエディタもライブラリを開くので循環し、動的 import にすると「静的にも読まれている」ビルド警告が出るため。
- アイコンを選ぶために開いたとき（インスペクタ・アイコンエディタから）は、作る入口を出さず説明だけにする。そこで作ると、選び直しの流れが途切れるため。
- 空でないときの切り替え（すべて / お気に入り / タグ）は、入れ物の幅いっぱいではなく中身の幅にする。

### 20.3 差分ダイアログを開いてすぐ閉じる（D-4）

開いてすぐ Esc で閉じると、`no diff result available` の例外が出ることがあった。Monaco の差分の計算は別スレッドで行われ、`dispose` は計算を取り消さない。計算が終わる前にモデルを捨てると、計算結果が空で返り、取り消されていないため例外になる。

- ダイアログ（画面）はすぐ閉じるが、エディタとモデルを捨てるのは、差分の計算が終わってから（`onDidUpdateDiff`）にする。終わらないときの上限は 5 秒。
- 例外を握りつぶすのではなく、原因（計算中にモデルを捨てること）を避ける。

### 20.4 設定の足もとと Excel の状態（D-5）

- 足もとに［閉じる］と「変更はすぐに保存されます」を置く。設定は変えた時点で保存されるので、確定のボタンはない。［閉じる］は主ボタンにしない（入力欄で Enter を押して閉じてしまわないため）。
- 「バージョン」の行には Sash の版だけを出し、Excel の有無は「Excel 連携」という別の行（「利用できます / 利用できません」と説明）に分ける。

### 20.5 XML の構文エラー中の表示（X-1）

構文エラーで XML と画面の同期が止まっている間（`store.syncError`）は、ほかの画面が編集できるように見えてしまう。

- `#app` に `xml-sync-error` を付け、左ペイン・キャンバス・インスペクタを 60% の濃さにする（見た目だけ。`aria-disabled` は付けない：ツリーでの選択など止まっていない操作もあり、「操作できない」と読み上げると実態と合わないため。止まっていることは帯の `role="status"` が伝える。操作そのものは、各所のストアが断る）。直ったら外す。
- 帯に、［エラーの行へ移る］（行が分かるとき）と［最後の正しい状態に戻す］を置く。後者は、同期が止まる前に最後に正しく読めた文書で XML エディタの文字を置き換える。書いている内容が失われるので、確認を出す。読み込んだ時点で壊れていたファイルでは、最後の正しい状態は空の `customUI` になる。
- よく出る構文エラーを日本語にする（`src/xmlError.ts` の `describeXmlError`）。現在の Chromium（WebView2）の文と、以前の libxml2 系の文の両方に対応する。`Unexpected token inside opening tag: <` は「開始タグの中に予期しない文字があります（> の閉じ忘れの可能性）」にする（直前のタグの「>」の閉じ忘れがいちばん多いため）。日本語表示のときだけ変え、英語表示は原文のまま。知らない文は原文のまま出す（誤訳するより原文を見せる）。帯と下部パネルの問題一覧で、同じ関数を使う。

### 20.6 ホーム「はじめての方へ」の見出し（H-1）

見出しの前の ▸ を、文字ではなく枠線で描いた三角にして、見出しの文字と中央をそろえる（文字の字形は、フォントによって上下の位置がずれる）。開いたときは 90 度回して下向きにする。

### 20.x 左ペイン・外枠（組1）

- **パレットとツリーの境界**：左ペインのパレットとツリーの間に仕切り（role=separator、「パレットとツリーの高さ」）を置く。パレットの高さは左ペインの高さに対する比率（0〜1、既定 0.45）で持ち、`sash.layout` に `palette` と `last.palette`（畳む前の比率）として保存する。読み込みで 0〜1 に丸め、壊れた値は既定に戻す。0 はパレットを畳んだ状態、1 はツリーを畳んだ状態を表し、両方を同時に畳むことはない。
- ドラッグ中は各側の最小を 72px とし、36px 未満まで引いた側は畳む。畳んだ側は見出しの行（28px）だけ残し、見出し（ボタン、aria-expanded）のクリックまたは Enter で開閉する。畳むところまで引いたときの戻し先は、引く前の比率とする。
- ダブルクリックと Enter/Space は既定の比率（0.45）に戻す（ほかの 4 本の仕切りは「畳む」）。↑↓ は 16px、Shift+↑↓ は 64px、Home でパレットを、End でツリーを畳む。aria-valuenow は百分率。
- 「既定のレイアウトに戻す」は比率も戻す。F6・Ctrl+2 で畳んだ側へ移るときは、その側を開いてから移る。
- 下部パネルの既定の高さは 140px。畳んだ下部パネルの帯には「問題 n ・ コールバック n」を出し、帯の名前（aria-label）にも添える。
- ホーム画面の表示中は、メニューバー以外（ツールバー・各ペイン・下部パネル・仕切り）を inert にする（隠れた XML エディタに Tab が捕まらないように）。
- ツリーの F2・Enter・ダブルクリックは、その行でラベルをその場で書き換える（Enter で確定、Esc で取り消し、確定後もツリーにフォーカス）。
- その場の書き換え（キャンバス・ツリー共通）の安全策：畳んだ枠の中（非表示）など入力欄にフォーカスが移らないときは、始めなかったことにする（入力中の旗が残ると描き直しが止まり、古い入力欄が残って、あとで別の要素に書き込みかねないため）。入力中に文書が変わって入力欄のパスが別の要素を指すようになったら、確定せずに捨てる（同じ要素のままなら続ける）。ツリーで入力中に別の行を押して外れたときは、確定の描き直しでその行が作り直されて click が届かないので、押した行（Ctrl・Shift も）を確定のあとで選ぶ。ラベルを持たない要素と getLabel を使う要素は、インスペクタのラベル欄へ移る。
- 問題の一覧は「対象のラベル（種類）：文」の順に左寄せにし、長いラベルには「ラベルを編集」、ID の重複には「ID を振り直す」を付ける。コールバック一覧の行のボタンは「雛形をコピー」。
- 下部パネルのタブは、選択中だけ Tab で止まり、←→・Home・End で移る（role=tablist / tab / tabpanel）。ツールバーのボタンには aria-keyshortcuts を付ける。
- ファイル メニューの先頭に「新しいリボンを作る…」を置き、リボンを付けたいブック（.xlsm / .xlam）を選ぶよう案内してからファイルの選択に進む（Sash はブックそのものは作らない）。
- layout は `growTemporarily('top', px)` を提供する。キャンバスの高さを一時的に広げるだけで、保存しない。広げる上限は、中央の列（`.pane.center`）の高さから XML エディタの最低高さ（120px）と仕切りを引いた分（窓の高さの割合では、メニュー・ツールバー・下部パネルを無視して広げすぎ、1366×768 で XML エディタの高さが 0 になった。中央の列の高さが測れない環境では窓の高さの 85%）。キャンバスは広げる前の高さを測り、比べる枠の下端までに足りない分だけを求める（枠の全高は足さない）。
- 実機（WebView2）で確かめていないこと：inert とホームを出た直後のフォーカス、仕切りのドラッグの感触、ツリーの入力欄での IME の確定、「新しいリボンを作る…」からファイルダイアログへの流れ。

### 20.y キャンバス・インスペクタ（組2）

**キャンバス**
- **追加直後の名前入力**：［＋］・挿入メニュー・右クリックの「前に挿入／子を追加」で要素を足すと、キャンバスにフォーカスを戻し、足した要素のラベルをその場で全選択して編集できる状態にする（Enter で確定、Esc で既定名のまま。IME の変換確定の Enter では確定しない）。パレットのダブルクリックはフォーカスをパレットに残す（続けて足す使い方のため）。
- **実寸表示**：横にあふれても、見出し（表示の切り替え・幅の選択）は左端に貼り付けて流れ去らない。
- **組み込みタブの「…」**：タブの列が枠より広いときは、選んでいない組み込みタブ（挿入〜ヘルプ）を右から「…」1 個にまとめる。自作タブ・手を加えた組み込みタブ・「ファイル」・「ホーム」・表示中のタブは必ず見せる。
- **縮小の目安**：縮小率が 80% 未満なら「ペインを畳む」を勧め、70% 未満なら状態に「（文字が小さく表示されます）」を添える。「2つの幅を比べる」のときは、キャンバスの高さを下の枠のぶんだけ一時的に広げる（保存しない）。
- **読み上げ**：キャンバスで 1 つ選んだときは「ボタン 集計する、集計 グループ、4 個中 1 個目」の形で読み上げる（フォーカスがキャンバスにあるときだけ）。
- **組み込みグループ名**：Excel から表示名が取れないときは、よく使うタブのグループ名だけ同梱の日本語の対応表を使う。
- 幅が「自由」で使えない「全体／実寸」は、選択色ではなく無効の見た目にする。

**インスペクタ**
- 並び順は「基本・画像・コールバック・表示・詳細」。静的な値と get 系コールバックの切り替えは、入力欄の右端の小さなボタン「VBA」1 個（固定は輪郭だけ、VBA で返しているときは色付き、aria-pressed）。固定に戻すと、切り替える前の固定の値に戻る。1 属性 1 段（約 34px）。
- ID の「提案」は、ラベルから作った案（英字なら単語をつなげ、日本語などはそのまま。id には Unicode の文字を使える、§17.2）と、種類と連番の案を選ぶ小メニュー。選択肢が 1 つならそのまま入れる。値が変わらないときは理由を通知する。
- アイコン欄に 24px の見本を出す（取れなければ「？」）。アイコンの候補は Fluent と Tabler の両方から出す。
- 列挙値の未指定は、既定値が分かる属性（size・itemSize・boxStyle）では「既定（normal）」の形で出す。ラベル列は 2 行まで折り返す。

**カタログ（imageMso）**
- 列の最小幅を 240px にし、長い名前は 2 行まで折り返す。注目している項目（フォーカス・マウス・選択中）の名前の全文をフッターに出す。

**実機（WebView2）で確かめていないこと**：zoom・sticky・container-type・line-clamp の見え方、実際の Excel から取ったアイコンの見本とグループの日本語名、日本語 IME での実入力。

## 21. 分割ボタンのアイコン・ラベルと、アイコンの総点検（0.1.2 追加）

### 21.1 分割ボタンは中のボタンに書く

- スキーマ上、**分割ボタンには label / getLabel / screentip / supertip / image / imageMso / getImage / showImage / getShowImage を付けられない**（customUI14.xsd の CT_SplitButtonRestricted で prohibited。中の先頭の button / toggleButton から受け継ぐ）。分割ボタンが持つのは id 系・挿入位置・size・visible・enabled・showLabel・keytip だけ。以前から `schema.ts` は正しくこの形で、変えていない。
- 利用者が分割ボタンを選んでアイコンやラベルを設定しようとしたときは、**中のボタンを対象にする**。`ui/src/iconTarget.ts` に「書き込み先の決め方」を 1 か所にまとめた（`iconTargetOf` / `iconTargetPath` / `canSetIcon` / `delegatesToInner`）。分割ボタンなら中の先頭の button / toggleButton、それ以外は自分自身。
- 対象にした入口：インスペクタ（「ラベル・アイコン・ヒント」の区画）、アイコンエディタ（`openIconDialog`。どの入口から渡された path でも、ここで付け替える）、ライブラリからの設定（`applyLibraryIcon`）、キャンバスへの画像ファイルのドロップ、コマンド「選択中のコントロールのアイコンを作る…」「imageMso カタログ…」、まとめて変更（`bulkEdit.ts` の `ownerOf`。分割ボタンと普通のボタンを一緒に選んだときも label・imageMso が共通の属性になり、分割ボタンには中のボタンに入る）。中のボタンが無い分割ボタンや、アイコンを持てない要素（tab など）には、アイコンエディタ・ライブラリのどちらからも設定できない（知らせて閉じる。スキーマ違反の属性を作らない）。
- 分割ボタンのまま選択を動かさない（設定後も、画像のドロップ後も分割ボタンを選んだまま。`onImageDrop` はドロップされた要素の path と書き込み先の path を別々に渡す）。元に戻す／やり直しは 1 操作 1 回。
- **書き込み先は path ではなく要素そのもので持つ。** インスペクタの `commit` は、入力中に構造が変わっても（前に要素が差し込まれても）別の要素に書かないよう、確定時に「その要素が文書にあり、いま選んでいる要素の書き込み先であること」を確かめる。確かめられなければ書かない（従来の「選択が変わっていたら書かない」と同じ守り）。ダイアログ（アイコンエディタ・ライブラリ・コールバック名の変更）を開くときの path も、押した時点で要素から作り直す。
- 区画には、ラベル・アイコンのほか、中のボタンの screentip / supertip も出す（Lint の案内「ラベル・ヒント・アイコンは中のボタンに付けます」と同じ範囲）。中のボタン（書き込み先）についての Lint の指摘も、この区画に出す。ID の「提案」は、分割ボタンでは中のボタンのラベルから作る。キャンバスの名前の直接編集（F2）も中のボタンの label に対して行い、分割ボタンのアイコンを出すかは中のボタンの showImage で決める。
- 見た目：ツリーの行の名前（`displayName`）と、キャンバスのメニュー・右クリックメニューの中の分割ボタンの項目は、中のボタンのラベル・アイコンで出す。分割ボタンの行は中の先頭のボタンを兼ねて表すので、その子の行は並べない（同じ見た目の行が 2 つ並ばない）。リボンのメニューのポップアップは、アイコンとラベルの間を 6px あける。分割ボタンの行は、分割ボタン自身に加えて中の先頭のボタンを選んでいるときも選択中にし、中のボタンのエラーの印（has-error）も表す。**ポップアップと右クリックメニューからは、中の先頭のボタンを直接選べない**（ツリーか、分割ボタンのインスペクタの「中のボタンを選ぶ」で選ぶ）。Lint は、分割ボタンに label / imageMso などを書いた XML に「中の button / toggleButton に付けます」と直し方を添える。
- **dialogBoxLauncher は同じ扱いにしない。** 中の button は Excel の画面ではアイコンが出ない（グループ右下の小さな矢印に決まっている）ので、dialogBoxLauncher を選んでも設定先にはならない。中の button を直接選べば、スキーマどおり image 系の属性は書ける。
- `splitButton` の中の `menu` のアイコン・ラベルは Excel の画面に出ない見込みだが、実機で確かめていないので、配布前チェックの「アイコンのないボタン」の対象のまま（変えていない）。

### 21.2 総点検の結果（customUI14.xsd との突き合わせ）

リボンのコントロール・Backstage・コンテキストメニュー・QAT の全要素について、`image` / `imageMso` / `getImage` / `label` / `getLabel`（と showImage / showLabel）を持てるかを XSD と照合した。**リボン側は、スキーマの定義に不足も誤りもなかった**（tab は label だけ、group は label と image 系、checkBox・labelControl・box・buttonGroup・separator・dialogBoxLauncher は image 系なし、など XSD どおり）。直したのは次のとおり。

| 場所 | 内容 |
|---|---|
| Backstage の `item`（dropDown・comboBox の中）と `radioButton` | XSD の CT_BackstageItem は id・label・getLabel だけ。誤って持たせていた image / imageMso を外し、不足していた getLabel を足した（リボンの `item` は CT_Item で image / imageMso / screentip / supertip を持てるので変えていない）。**以前の版で image / imageMso を付けて作ったファイルは Lint のエラーになる**ので、メッセージに「Backstage の項目はアイコンを持てません。XML エディタで image / imageMso を消してください」と添える |
| キャンバス：editBox・comboBox・dropDown | getImage（VBA で返すアイコン）の印が出ていなかった。ほかのコントロールと同じ「動的」の印を出す |
| キャンバス：リボンのメニュー・ギャラリーなどのポップアップ | 項目のアイコンが描かれていなかった。右クリックメニューと同じく、アイコンを描く（無い項目は同じ幅の空き） |
| キャンバス：右クリックメニュー・ポップアップの分割ボタンの項目 | id が出ていた。中のボタンのラベルとアイコンで出す |
| キャンバス：Backstage | getImage のボタン・タスクに「動的」の印が出ていなかった。hyperlink のアイコンが描かれていなかった |
| ツリー | 分割ボタンの行が id だけだった。中のボタンのラベルを出す |

点検で「定義上は持てない」と分かったが直していないもの（アイコン・ラベルとは別の属性なので範囲外）：Backstage の一部のコントロールが持つ idMso / insertAfter・insertBefore 系・screentip / supertip などは、XSD にない／あるの食い違いがある（例：taskFormGroup の task の onAction・isDefinitive は XSD にない）。次の版で別に点検する。

### 21.3 実機（Windows・Excel）で確かめていないこと

- 実際の Excel のリボンで、分割ボタンの中のボタンに付けたアイコンとラベルがそのとおり表示されること（スキーマには適合している）。
- 分割ボタンの中の `menu` に付けた label・image が、Excel の画面に出ないこと。
- Backstage の hyperlink・task にアイコンが出る表示の細部。

## 22. 総点検（0.2.0 追加）

製品版に向けた総点検（高・中の指摘 31 件）の対応で決めたこと。指摘の ID（G-1 など）は括弧で添える。

### 22.1 表記の決まり（G-10）

- 英字・数字と日本語の間は半角空白 1 つ。ただし括弧・句読点の前後には入れない。対象は `Excel` `XML` `VBA` `VBE` `ID` `DPI` `Sub` `CSV` の直前・直後（例：「Excel へ反映」「VBA の Sub 名」「高 DPI」）。`ui/test/textStyle.test.ts` が画面の文言（`ui/src` と `index.html`）を調べ、戻らないようにする。ホスト（C#）の文言も同じ形に直し、`L("…")` と `UserFacingException`・`UserErrors` の日本語側を同じテストで調べる（§22.11）。サンプルのラベル（利用者のデータの例）は対象外。
- 数は後ろに付ける：「削除（2 個）」。右クリックメニューも同じ形にした（以前は「2 個を削除」）。
- 元に戻すの名前は「〜を追加」「〜を移動」の形（「トグルボタンの追加」をやめた）。
- 右クリックメニューのことは、どこでも「右クリックメニュー」と書く（タグ名 `contextMenu` は補足）。

### 22.2 ペインの大きさ（G-1・I-1・B-1）

- 仕切りで動かした大きさは、窓より大きくなりうる。**保存値とは別に、表示する値だけを窓に収める**（`layout.ts` の `fitSizes`。保存値は書き換えないので、窓を戻せば元の大きさに戻る）。`window` の `resize` でも丸め直す（1 フレームに 1 回）。
- 横：左 + 右 ≤ 窓の幅 − 中央の最小幅 320 − 仕切り。超えたら、いま動かしていない側から縮める（指定がなければ右から）。縦：下部 ≤ 窓の高さ − 76（メニューとツールバー）− 仕切り − 中央の最小 200、キャンバス ≤ 中央の行 − 仕切り − XML エディタの最小 120。
- 開いているペインの下限：左 200・右（インスペクタ）260・下部 96・キャンバス 60。それより狭く引いたら下限で止まり、**48px 未満まで引くと畳む**（キーボードは下限のあと、さらに縮めると畳む）。ドラッグの上限は、もう片方を下限まで縮めたときの残り（「窓の 70%」をやめた）。既定の右は 300 → 320px。
- インスペクタが 280px 未満のときは、`.insp-row` をラベルの下に値を置く 1 列にする（コンテナークエリ。ラベル列の幅は 96 → 108px）。
- **下部パネルの自動開閉**：利用者が開閉・ドラッグしていない間は、問題（エラー・警告）がなければ帯（「問題 0 ・ コールバック 10」。高さ 24px）に畳み、出たら開く。自動の開閉は保存しない。利用者が操作したら `bottomAuto: false` を `sash.layout` に保存し、以後は自動にしない（「既定のレイアウトに戻す」で自動に戻る）。古い保存で下部の大きさが既定（140）でないものは、「自分で変えた」とみなして自動にしない。

### 22.3 ホスト（W-1〜W-5）

- **ウィンドウの位置と大きさ**（W-1）：`settings.json` の `window`（x・y・width・height・maximized）に保存する。閉じるとき、最大化中は戻したときの値（`RestoreBounds`）を保存。起動時は、保存値が今の画面の作業領域に横・縦とも 100px 以上掛かっていて、最小（960×600）以上なら使う。なければ既定：作業領域の 90%（上限 1440×900）で中央、**作業領域の幅が 1440 未満なら最大化**。判断は `WindowPlacement.Resolve`（テストあり）。設定画面からは変えない。
- **拡大・縮小**（W-2）：`IsZoomControlEnabled = false`・`IsPinchZoomEnabled = false`。Ctrl+ホイールで拡大されて Ctrl+0 で戻せない事故を止める（拡大の操作を設ける案 (b) は見送り）。入力の候補とパスワード保存の案内も切った（D-13 の一部）。
- **UI スレッドから外す**（W-3）：`file.open`（ダイアログ以外）・`file.save`・`file.exportText` の書き込み・`backup.restore`・`library.*`・Excel がないときの `excel.apply` の書き込みを `Task.Run` で動かす。ファイルの選択ダイアログは UI スレッドに残す。
- **壊れたファイル**（W-4）：zip として読めない・Package として壊れている・XML が壊れているブックは、「このファイルは Excel のブックとして読めませんでした。壊れているか、別の種類のファイルです」（元の例外は `InnerException` に残し、ログへ）。`DescribeError` は、利用者向けに書いた例外（`UserFacingException`・`InvalidOperationException`・入出力）以外は文言を出さず、「予期しないエラーが起きました（詳しくはログ：パス）」にしてログへ書く。
- **Excel が応答しないとき**（W-5）：反映が 15 秒を超えたら、通知を「Excel の応答を待っています。Excel 側にメッセージが出ていないか確かめてください」に変え、［待つのをやめる］を出す（`busy` を戻すだけ。ホストの処理は続き、結果が届いたら通知する。保存済みの印は結果が届いてから付ける）。VBA の読み書き（`vba.*`）は、15 秒を超えたら同じ文言の通知を出す（待つのをやめる操作は付けない。UI に待ちの状態がないため）。マクロの実行（`excel.runMacro`）は MsgBox などで長く止まるのが普通なので対象にしない。

### 22.4 想定外の例外と右クリック（G-5・G-3・X-1・X-2）

- `window` の `error` / `unhandledrejection` を拾い、通知「予期しないエラーが起きました：…」（同じ文言は 1 回だけ）を出して、ホストへ `app.log { level, message, stack }` を送り `app.log` に書く（`ui/src/shell/errorReport.ts`）。ブラウザの無害な通知（ResizeObserver）は出さない。起動の最初の問い合わせが失敗しても、既定の設定で画面を動かして知らせる。
- 入力欄（text・search・number・textarea）の右クリックに、切り取り・コピー・貼り付け・すべて選択を出す（`shell/textMenu.ts`）。製品版は WebView2 の既定のメニューを切っているため。貼り付けはクリップボードを読む（読めなければ「Ctrl+V で貼り付けられます」）。ペインの余白では何も出さない。
- XML エディタは Monaco 自身の右クリックメニュー（元に戻す・やり直し・XML を整形・切り取り・コピー・貼り付け・すべて選択）を使う。日本語の画面では、Monaco 本体より先に `nls.messages.ja.js` を読み込む（読み込みの順は `views/monacoApi.ts` に集約。top-level await）。XML エディタで Esc を押すとキャンバスへ戻る（補完・検索が開いているときはそちらを閉じる）。
- 「最後の正しい状態に戻す」は、全文を入れ替えず、同期と同じく変わった所だけを置き換える（選択が customUI に飛ばない）。確認の文は「構文エラーになる前の内容に戻します。元に戻す（Ctrl+Z）で、いまの内容に戻せます」。

### 22.5 メニュー（G-4・G-6〜G-9・G-11・G-12・D-11）

- **アクセスキー**：メニューの項目に `mnemonic`（英字 1 文字）を持てる。日本語は「保存(S)」、英語は下線。開いているメニューでその字を押すと実行（サブメニューなら開く）。同じ字が複数あれば順に移るだけ。付けたのはファイルとの編集の主な項目（N/O/R/E/S/C/B/X、U/R/H/T/C/P/D/L/N/A/M/F）。
- **表示メニュー**は、ペインへ移る／キャンバスの表示／編集するパーツ（2 つあるとき）／画面の幅・拡大率・表示のしかた／下部パネルとそのタブ／左右のペインを畳む／テーマなど、働きごとの入れ物にまとめた。
- **ファイル**に「Excel で開いているブック ▸」（開くたびに取り直す。Excel がなければ無効にして理由）・Ctrl+N・Alt+F4 の表示を足し、「サンプルを開く」はヘルプへ移した。**編集**に「名前を変える（F2）」を足し、上へ・下へ移動の Alt+↑↓ を出し、削除の表示を `Del` に統一した。コマンドパレットはヘルプの先頭（「コマンドを探す…」）。**ツール**の VBA 項目は「VBA ▸」にまとめ短い名前にした。**ヘルプ**に「使い方（README）を開く」「ログのフォルダーを開く」を足した。表示だけのショートカット（Alt+F4・Alt+↑↓）は `displayOnly` でキーの照合に使わない。
- **サンプル**では、保存・反映のボタンとファイル → 保存を無効にし、理由（「サンプルは保存できません。自分のブックを開くと使えます」）を出す。ファイル名の印は「サンプル（保存できません）」（`--info-*` の色）。
- **Excel とのつながり**：ファイル名の右に「Excel：未検出／このブックを開いています／開いていません」の印を出す（ファイルを開いたとき・窓に戻ったとき・反映が終わったときに取り直す。入力のたびには問い合わせない）。Excel がないときは反映ボタンの文字を「ファイルに書き込む」にする。
- **コマンドパレット**は、探したとき使えないコマンドも薄く出し、右に理由を添える。Enter では実行せず理由を読み上げる。使えるものを先に並べる。何も打っていないときは使えるものだけ。

### 22.6 配布前チェック（D-1）

エラー（id の重複・id のないボタン・使えない属性・ない画像など、Excel でリボンが出なくなるもの）は、警告と分けて赤で出す。見出しの判定は 3 段：エラーが 1 件でもあれば赤で「このまま配ると、Excel でリボンが表示されません（エラー n 件）」、エラーがなく要確認があれば黄、どちらもなければ緑。節は「エラー」「警告」に分け、エラーの節を先頭（VBA 未照合の節より前）に置く。項目の印も、エラーは赤い丸。閉じるだけのダイアログの［閉じる］は主ボタン（緑）にせず、最初のフォーカスだけを置く（D-9 の一部）。

### 22.7 デザインのトークン

- **色**：`--stroke-control`（ボタン・切り替え・印・入力欄の周り。#d1d1d1／#5c5c5c）と `--stroke-input-bottom`（入力欄の下の線。#616161／#adadad。フォーカスで 2px の `--focus`）を足した。`--border-strong` は点線の枠・畳んだ帯のつまみ・チェックボックスの枠だけ。`--sel-bg` は #ebf3fc／rgba(71,158,245,.22)。`--scrollbar-thumb`（と `-hover`）を足し、スクロールバーを 10px の細いものにした（`::-webkit-scrollbar`。Chromium 109 でも効く）。
- **役割**：緑（`--accent`）は反映・保存・挿入の主ボタンと、キャンバスの中の Excel の再現（タブの下線）だけ。選択・フォーカス・切り替えの「入」（`.segmented .active`）・下部タブの下線は青（`--sel-*`）。インスペクタの［VBA］は枠なしの小さなボタン（VBA で返しているときだけ `--accent-soft` の地）。
- **文字・間隔・角丸**：`--fs-2xs`（11px。これより小さくしない）・`--fs-2xl`（24px）・`--sp-6`・`--ctl-h-xl`（40px）・`--row-h`・`--pane-head-h`・`--radius-xs`（2px）・`--radius-pill` を足し、CSS の直書きの文字の大きさ・角丸・太さ（700 は 600 に）をトークンに置き換えた。メニュー・通知・カード・ダイアログは角丸 8px に統一。キーヒントの再現（9px）だけは Excel の描き方に合わせて直書きのまま。
- **影**：`--shadow-menu`（0 4px 8px）・`--shadow-toast`（0 8px 16px）・`--shadow-modal`（0 32px 64px）に改め、`--backdrop` は .4／.6。重なる面は 1px の `--border` も付ける。
- **XML エディタ**：Monaco のテーマ `sash-light`／`sash-dark` を定義し、地を `--surface` に合わせ、スクロールバーを 10px にした。

### 22.8 そのほか画面のまとめ（C-1・L-1・H-1・D-4・D-2・G-2）

- 空の状態（Backstage・右クリックメニュー・自作のタブがないとき）は `views/emptyState.ts` の 1 つの部品（アイコン 24px・見出し 14px・説明 12px・主ボタン 1 つ。点線 1px・角丸 8px）で出す。
- ツリーは、子が `tabs` だけの `ribbon` を「ribbon › tabs」の 1 行にまとめる（選択とドロップ先は tabs。「ribbon」の字を押すと ribbon を選ぶ）。字下げは 1 段 12px。ID は右寄せで、足りないときは ID から省略する。
- ホームは、アイコン（40px）・見出し 24px・［ファイルを開く］と［サンプルを開いて試す］を並べ、点線の四角をやめて 1 行の案内に替え（ファイルをドラッグしている間だけ、ホーム全体に点線の枠を出す）、空いた右側に「Excel で開いているブック」を置いた。
- アイコンエディタは、左の列を「プレビュー → 画像を選ぶ（2 列のボタン）→ 元の画像」の順にし、右の列の枠（fieldset）をやめて見出し＋区切り線にした。画像を読み込むまでは右の設定を薄くして触れなくし、［切り抜きを解除］は切り抜いたときだけ有効にする。色の入力 4 つに名前を付けた。
- ダイアログの左下のボタンは `footer-start` クラス（以前の `left` はペインの配置用の `.left` と衝突し、`display: grid` になって文字が上にずれた）。ダイアログを開いている間は `body.modal-open` を付け、通知を右上に出して［閉じる］に重ならないようにする。

### 22.11 見直しと「低」の指摘への対応（0.2.0 の続き）

高・中の対応のあとの見直し（13 件）と、総点検の「低」38 件で決めたこと。

### 見直しで直したもの

- **入力欄の右クリック［貼り付け］**：`document.execCommand('insertText')` で入れる（利用者が打つのと同じ経路なので、`input` に続いて `change` も出る。インスペクタは `change` か Enter で確定する）。使えないときだけ `setRangeText` で入れ、`input` と `change` を自分で送る。`type=number`・`email` は範囲を持てない（`setRangeText` が例外になる）ので、値全体を置き換える。失敗は自分で受け、「Ctrl+V で貼り付けられます」の通知にする。
- **利用者向けの例外**：`Sash.Core` が `L()` の文言つきで投げる `ArgumentException`・`FormatException` には、`UserErrors.Argument` / `UserErrors.Format` で印（`Exception.Data`）を付ける。型は変えない（呼び出し側の `catch` とテストが型で受けているため）。ホストの `DescribeError` は、印のある例外の文言をそのまま見せる。対象は更新の確認先・更新フィード・レシピの id・アイコンの id。
- **Excel への問い合わせの間引き**（`shell/pollGate.ts`）：窓に戻るたびの `excel.openWorkbooks` は、問い合わせ中は重ねず、30 秒に 1 回まで、保存・反映の最中は送らない。ファイルを開いた・閉じた・反映が終わったときは、間引かずに取り直す。問い合わせに失敗したら、前の表示のままにする（「開いていません」と言い切らない）。
- **ウィンドウの位置**：保存値は、**タイトルバーの帯（上端から 30px）が作業領域に入っている**（横 100px・縦 20px 以上）ときだけ採用する。作業領域より大きければ収まるよう丸め、下端がはみ出すときは上へ寄せる。最小化したまま閉じても、最小化する前の状態（最大化か）を保存する。
- **保存したペインの大きさ**：旧版で保存した下限未満の値は、畳むしきい値（48px）未満なら畳み（0）、それ以上なら下限に丸める。畳む前の大きさ（`last`）は 0 にしない。
- **クリップボードの権限**：WebView2 の `PermissionRequested` で、自分のオリジン（`UiAssets.Origin`、開発時は Vite のオリジン）からの `ClipboardRead` だけを許す。ほかは既定のまま。
- **待つのをやめたあとの `needsSave`**：反映されていないので、緑の成功にせず警告にして、「［Excel へ反映］をもう一度押して『保存して反映』を選ぶ」を案内する（確認の画面は、別の操作中かもしれないので出さない）。
- **メニューバー**：マウスで開いたメニュー（フォーカスがメニューバーのボタンにある）でも、項目のアクセスキーと頭文字の移動が効く。
- **例外の受け皿は `src/boot.ts` で最初に登録する**。ES モジュールの import は書いた順に評価されるので、`main.ts` の先頭の import に置けば、Monaco の読み込みなど後ろの import の評価中の例外も拾える（`main.ts` の本文は、すべての import のあとに動く）。
- **F2**：キャンバスとツリーが自分で受ける。入力欄の中では奪わない（`inText` を付けない）。入力欄の外のパレットなどと、メニュー・コマンドパレットからは、キャンバスで名前の入力に入る。
- **コントラスト**：切り替え（`.segmented`）の外枠と区切りは `--border-strong`（地に 3:1 以上）、スクロールバーのつまみは地の 50%（ライト 3.8 以上、ダーク 4.0 以上。ホバーで 65%／70%）にした。

### 「低」の対応で決めたこと

- **F6 の順**（G-13）：パレット → ツリー → キャンバス → XML → インスペクタ → 下部（画面の並び）。
- **ハイコントラスト**（G-14）：`@media (forced-colors: active)` で、選択した行・要素・切り替え・メニューの項目を `outline: Highlight` で見せ、ダイアログ・通知・メニューの枠を `CanvasText` にする。
- **キー入力のたびにコマンドの一覧を作らない**（G-15）：ショートカットの表（id とキー）を初回に 1 度だけ作り、当たったときだけコマンドを作る。
- **英語の大文字**（G-16）：メニュー・ボタンの英語は文の形（先頭と固有名詞だけ大文字。`Command palette`・`Reload VBA and check`）。Excel の画面の呼び名（Quick Access Toolbar・Macro-Enabled Workbook）はそのまま。
- **削除の通知**（G-17）：コントロール 1 つを消したときは出さない。複数・中身を持つ要素（タブ・グループ・メニュー）を消したときだけ出し、前の「元に戻す」の通知は閉じてから出す（積まない）。
- **ホーム**（H-2・H-3）：ドロップの案内の 1 行は押せる（ファイルの選択を開く）。「はじめての方へ」の 1 番は「Excel でブックを保存」。
- **パレット**（L-2）：行 24px・分類の見出し 22px。幅が 219px 以下ならタグ名を隠す（コンテナークエリ。ツールチップにはある）。
- **別のファイルを開いたとき**（L-3）：ツリーのスクロールは先頭へ、XML エディタはスクロールとカーソルを 1 行 1 列へ戻す（同じファイルの描き直しでは動かさない）。
- **右クリックメニュー**（C-2・C-3）：画面の文言を「右クリックメニュー」に統一した（見出しは「右クリックメニュー（contextMenu）」）。見出しは「セル（ContextMenuCell）」の形（セル・行・列・シート見出し・テーブル）。日本語名が分からない組み込みグループ（Activation など）は、英字の ID を出さないよう描かない（自分のグループがその前後に置いてあれば描く）。
- **「?」の案内**（C-4・C-6）：button にして、押す・Enter で案内（`.cv-pop`）を開く（`aria-expanded`・`aria-controls`、Esc・外を押すと閉じる）。「Esc：親を選ぶ（複数選択のときは解除）」を案内とショートカット一覧に足した。
- **インスペクタ**（I-3・I-4）：アイコンの候補は 1 つの Tab 停止にして、中は ←→・Home・End で移る。何も選んでいないときは、空の状態の部品で案内し、［タブを追加］［レシピから作る…］［customUI の設定（onLoad）を開く］を並べる。
- **XML エディタ**（X-5）：「XML に誤りがあるため、キャンバスとツリーへの反映を止めています（…）。直すと自動で再開します」。長いときは 1 行で省略し、全文はツールチップ。
- **下部パネル**（B-2・B-3）：絞り込み（エラー・警告・情報）は `aria-pressed` の切り替えボタン（入っているときだけ選択の色、外すと薄く、0 件は押せない）。通知は下部パネルの上端より上に出す（`--bottom-h` を `html` にも書く）。
- **ダイアログ**（D-3・D-6・D-7・D-8・D-10・D-12・D-13）：配布前チェックの対象は日本語の種類名（「集計する（ボタン）」）。画像を読めないときはブラウザの英語を出さず「画像として読めませんでした。ファイルが壊れているか、対応していない形式です（名前）」にして、元の文はログへ。差分は、変更がなければエディタを出さず「保存済みの内容と同じです」、幅を 1200px にして左右に並べる（［左右に並べる｜1 列］の切り替え付き）。ショートカット一覧は段組みにして、絞り込み欄を足した。構文エラーの間は、挿入メニューの「レシピ…」・コマンドパレットの recipe.*・［挿入］を無効にして同じ理由を出し、ダイアログも閉じない（要素の挿入は無効にせず、押すとストアが断って理由を通知する）。差分の［左右に並べる］は `useInlineViewWhenSpaceIsLimited: false` も渡して、ボタンの状態と表示を一致させる。検索欄の「×」は 1.5px の線・`--text-subtle` の自前の描画。`h('input' | 'textarea')` は、指定がなければ `spellcheck=false`・`autocomplete=off` を付ける（以前の `spellcheck: false` は、`false` を飛ばす処理で捨てられて効いていなかった）。
- **デザイン**（S-4・S-5・S-6）：文字の大きさ・角丸・太さの直書きをなくし、`ui/test/cssTokens.test.ts` が戻らないよう調べる（`color-mix()` と入れ子の CSS も使わない）。ペインの見出しは `--text`・下に区切り線。ツールバーは［元に戻す］［やり直し］をアイコンだけ（28×28px）にし、［配布前チェック］を足した。
- **メニューのアクセスキー**（G-4）：表示・挿入・ツール・ヘルプの項目にも付けた（挿入の要素の項目は、日本語名の頭文字が英字にならないので付けない）。
- **VBA 照合の印**（G-12）：ファイル名の右に「VBA：照合済み／要対応 n／未照合／照合できません／保護されています」を出す（Excel がない・読んでいないときは出さない）。
- **行の高さ**（L-1）：ツリーとパレットの行は `--row-h`。

### 見送ったもの（理由）

- **S-7**（小さいボタンの空の四角）：指摘自身が「Excel の実際の描き方を 365 の実機で確かめてから」としている。確かめられないので、今のまま。
- **W-2 (b)**（拡大・縮小のメニュー）：WebView2 の `ZoomFactor` と、拡大したときのレイアウトの収まりを実機で確かめられない。事故は (a)（拡大を止める）で止めてある。
- **W-6**（外部で書き換えられた customUI を黙って上書きする）：Excel が保存し直したとき customUI のパーツの中身（バイト列）が変わるかを実機で確かめられない。変わると、毎回「書き換えられています」と誤って出る。**→ 0.3.0 で、バイト列ではなく「XML を正規化した中身と画像」で比べる形で実装した（§23.4）。**
- **W-7**（同じファイルを 2 つの Sash で開ける）：名前付き Mutex とパイプでの受け渡しは Windows 実機でしか確かめられない。W-6 の照合ができていないので、後から保存したほうが勝つのは変わらない（**0.3.0 で、保存・反映の前の照合は入った。§23.4**。2 つの Sash の受け渡しは今も未実装）。
- **X-3 の「F6 で次のペインへ」の通知**：Esc でキャンバスへ戻れること（実装済み）と、XML エディタの `aria-label` に F6 を書いてあることで足りるとした（フォーカスのたびに通知を出すと邪魔になる）。
- **L-2 の検索欄と見出しを 1 行にまとめる案**：検索の虫眼鏡ボタンの追加が要る（規模）。行・見出しの高さを詰め、タグ名を隠すことで、見える部品を増やした。
- **S-5 の XML エディタの上の見出しの帯**：新しい帯の追加が要る（規模）。ペインの見出しの強さだけ直した。

### 23.1 既存のマクロをボタンに割り当てる

リボンの `onAction` は `IRibbonControl` を受ける Sub でなければ呼べないので、既存の「引数なしの Sub」は、そのままは割り当てられない（押すと「引数の数が一致しません」になる）。それを、**そのマクロを呼ぶだけの呼び出し用の Sub を作って割り当てる**ことで解決する（`macroAssign.ts`・`callbacks.ts` の `assignMacro`・`dialogs/macroDialog.ts`）。

- **入口**：インスペクタの `onAction`（と `onChange`）の下の［マクロを選ぶ…］／ツール → VBA の［既存のマクロを割り当てる…］（アクセスキー A、コマンドパレットにも出る）／下部パネルのコールバック一覧で「引数が不一致」になっている行の［呼び出し用の Sub を作る］。複数選択のときは使えない（1 つずつ）。
- **候補**：読み込み済みの VBA（`vba.modules`）の Sub を、モジュールごとに並べる。絞り込み欄つき。**選べるのは、標準モジュールの、Private でない、引数なし（すべて `Optional` も可）の Sub**。次のものは薄く出し、理由を添えて選べなくする：Private（呼び出し用の Sub から呼べない）／引数あり／Function（戻り値がある）／クラス・シート・ThisWorkbook のモジュールの Sub（標準モジュールから直接は呼べない。クラス・ThisWorkbook 経由の呼び出しは、見送った）。`IRibbonControl` を受ける Sub は、すでにコールバックなので候補に出さない。
- **生成する Sub**：属性ごとの正しい引数（`callbackSignature`）で作る。中身は `Call モジュール名.Sub 名`。**常にモジュール名つきで呼ぶ**ので、同じ名前の Sub が別のモジュールにあっても取り違えない（一覧に「同じ名前が別のモジュールにもあります」と添える）。トグル・チェックボックス・ドロップダウンなど引数が増えるコントロールでは、増えた引数（`pressed` など）を使わないことをコメントに書く。`ByRef` の戻り値を持つ属性（`getXxx`・`onLoad`・`command` の `onAction`）には作らない。
- **名前**：命名規則（設定）で決めた名前（`Ribbon_btnCsv_onAction`）を使い、VBA のすべての Sub・Function と、XML のほかの場所のコールバック名（割り当て直す属性の今の値は除く）と**重なれば、番号を付けて避ける**（`…_onAction2`）。命名規則で「Sub を共有する」にしているとき、同じ名前・同じ引数の形のものは 1 つの Sub を共有する。
- **書き込み**：Excel で開いていて VBA を書き込めるときは、設定の挿入先モジュール（既定 `modRibbon`）へ `vba.insert` で入れてから、属性を付け替える（**VBA への挿入が失敗したら XML には触らない**）。属性の付け替えは 1 つの履歴（元に戻すで属性は戻る。VBA に入れた Sub は残る）。属性がすでに同じ名前だった（名前だけ追加してあった）ときは、VBA へ入れるだけで成功にする。Excel で開いていないときは、Sub の名前を手で入れてもらい（「集計」「modMain.集計」の形。VBA の識別子として使えない名前は断る）、生成したコードをクリップボードへコピーする。
- **見送ったもの**：(6) 何も割り当てないときの雛形の中身を設定で選ぶ（コメントだけ／押されたことが分かるメッセージ）、(7) 複数選択のときの「ボタン名 ↔ マクロ名」の表。問題の一覧（Lint）の行への［呼び出し用の Sub を作る］（コールバック一覧にだけ置いた）。

### 23.2 未保存の編集の自動退避と復旧

編集中の XML と、足した・変えた画像を、%AppData%\Sash\recovery に定期的に退避し、保存したら・閉じたら消す。落ちたとき・電源が切れたときに、次にそのブックを開くと復旧を選べる（`recovery.ts`・`dialogs/recoveryDialog.ts`・ホストの `Sash.Core/Recovery/RecoveryStore.cs`）。

- **退避する内容**：保存していないパーツだけを、保存のときに書き込む形（XML と、**保存済みからの画像の差分**＝足した・差し替えた画像と、消した画像の Id）で持つ。画像が多いブックでも、変わった画像だけを書く。操作の履歴は退避しない（復旧後の元に戻すは、復旧する直前に戻るだけ）。
- **いつ書くか**：XML・画像が変わった（選択だけの変更は除く）あと **3 秒**、続けて編集していても最初の変更から **15 秒**たてば書く（`createDebouncer`）。前回と同じ内容なら書かない。ホストへの書き込み・削除は 1 本の待ち行列で投げた順に行い、消したあとに古い書き込みが追い越して退避が残らないようにする。
- **失敗しても編集を止めない**：書けなくても例外にせず、ログ（app.log）に残す。**3 回続けて失敗したときだけ、1 度だけ**「自動で退避できていません」と警告する。サンプル（パスのないセッション）・設定でオフのときは書かない。
- **消すとき**：保存して保存済みと同じになった／元に戻して保存済みと同じになった／ファイルを閉じた・別のファイルを開いた（未保存の確認を通ったあと）／終了で「保存しない」を選んだ（`quit` が、`app.close` の前に消す）。落ちた・強制終了のときは残る。
- **保存先**：ブック 1 つにつき、Sash（プロセス）ごとに 1 ファイル（フルパスを大文字にして SHA-256 を取った先頭 32 文字＋`.`＋プロセス ID＋`.json`。上書きしていく。§23.8）。一時ファイルに書いてから置き換える（`JsonFile.WriteAtomic`）ので、書き込みの途中で落ちても前の退避を壊さない。中に書いたパスが違うものは、別のブックのものとして返さない。
- **掃除**：退避の一覧（`recovery.list`）を作るとき、**30 日より古いもの・壊れて読めないもの・書きかけの一時ファイル（1 日より古い）を消す**。起動したときのホームの描画で呼ばれる。
- **復旧**：ブックを開いたとき、退避が残っていれば［復旧する］［差分を見る…］［捨てる］を聞く。**Esc・×では閉じない**（決めずに閉じると、残した退避を新しい編集が上書きしてしまうため）。差分は、ファイルの内容（左）と退避した編集（右）。復旧した内容は**未保存の状態**で開き、元に戻す 1 回で開いた直後に戻る。ファイルにないパーツ（中身が変わっていた）は適用せず、知らせる。
- **提案との違い**：「退避が保存済みより新しければ復旧を選べる」は、**退避があれば常に聞く**形にした。元のファイルが退避のあとに変わっている（Excel などで保存された）ときも、捨ててしまうと編集が消えるので、聞いたうえで「退避のあとに別の場所で保存されています」という警告を添える（ホストが更新日時で判定。`RecoverySummary.FileNewer`）。
- **ホーム**：「復旧できる編集があります」のカードに、ブック名・日時・編集の回数を並べる。ブックを押すと、開いて、そこで復旧を聞く。［捨てる］で退避だけを消せる。
- **設定**：一般 →「編集の自動退避」（既定オン）。

### 23.3 別のブックのリボンを取り込む・見比べる

- **読み込み（ホスト `file.read`）**：ファイルを開かずに、リボンの中身だけを読む（最近使ったファイルには載せない）。ブック（`.xlsm` / `.xlam` / `.xltm` / `.xlsb`）は customUI と画像、`.xml` は customUI の XML 1 つ（名前空間から世代を決める。`CustomUIXml.DetectVersion`。XML として読めない・ルートが customUI でない・名前空間が違うときは理由つきで断る）、`.json` は Sash のリボン定義（UI が `parseSash` で解析する）。20 MB を超えるテキストは断る。
- **取り込む（ファイル メニュー［別のブックから取り込む…］。アクセスキー M）**：左に取り込み元の部品（タブ → その中のグループ、コンテキストタブ、右クリックメニュー、Backstage）をチェックつきで出し、右に取り込んだときの様子（取り込む数・id の振り直し・画像・使うコールバック・取り込まれる XML）を出す。タブを選ぶと中のグループは一緒に入る（二重に取り込まない）。グループだけを選んだときは、入れるタブ（今の文書のタブ／新しいタブ）を選ぶ。
  - **id**：重なるものは番号を付けて振り直す（`renameDuplicateIds`。レシピの挿入と同じ）。切ることもでき、切ると重なったまま入る（Lint のエラーになることを画面に出す）。
  - **画像**：`image` 属性が指す画像を一緒に運ぶ。同じ id で同じ中身なら使い回し、**同じ id で中身が違うものは番号を付ける**（`logo` → `logo_2`）。ボタンの `image` も付け替える。画像のない取り込み元（`.xml`）の参照は、そのまま残して「運べない画像」として知らせる。
  - **同じ組み込み**：`idMso` が同じタブ（`TabHome` など）・右クリックメニューは 2 つ置けないので、既存のものの中へ足す。取り込み先が 2007 形式のときは、Backstage と右クリックメニューを選べなくする（理由つき）。取り込み元が別の世代でも、取り込み先の名前空間で入る。取り込み先にすでに Backstage があるときは、Backstage を選べない。
  - **履歴**：XML の編集と画像の追加を 1 つの履歴にする（`PartStore.addImagesAndEdit`）。元に戻す 1 回で、取り込む前に戻る。
  - **VBA は運ばれない**：使っているコールバックを一覧にし、結果の画面で「VBA は運ばれません。次の Sub が要ります」と、VBA にあるか（Excel で開いているとき）を示す。［Sub の一覧をコピー］と、書き込めるときは［VBA に挿入］。
- **比べる（ツール メニュー［別のブックと比べる…］。アクセスキー B）**：差分ダイアログの左を選んだブックの XML、右を今の編集中の内容にする。XML は Sash の整形にそろえて比べる（他のツールの書き方との字下げの違いで全行が違って見えないように）。画像は id ではなく中身で比べる。差分ダイアログは `openDiffViews` に一般化し、保存済みとの差分・復旧・ほかでの変更・別のブックとの比較で共用する。
- **書き出す（ファイル メニュー［customUI の XML を書き出す…］。アクセスキー P）**：いま編集している 1 パーツを `.xml` で書き出す（他のツール・Git・質問サイトへ貼る用。画像は含まれない）。
- **見送ったもの**：取り込み元のリボンの見た目（キャンバス）の表示（右には XML を出す）。取り込みの画面の［レシピとして保存］。

### 23.4 ほかで書き換えられたファイルの検知（W-6）

§22.11 で見送った W-6 を、**バイト列ではなく内容で比べる**ことで入れた（Excel が保存し直してパーツのバイト列が変わっても、誤って知らせない）。

- **照合値（`RibbonFingerprint`、Sash.Core）**：パーツ（customUI14 / customUI）ごとに、XML を正規化した文字列と画像の組から SHA-256 を求める。**無視するもの**：XML 宣言・属性の順・タグの間の空白・コメント・名前空間の接頭辞（URI は比べる）・画像の Id（`image` 属性は参照先の画像の中身に置き換えるので、Excel がリレーション Id を振り直しても同じになる）。**比べるもの**：要素の名前・並び順・属性の値（値の中の空白も）・文字・画像の中身。XML として読めなければ、改行をそろえた生の文字列で代用する。リボン以外（シート・VBA）が変わっても、照合値は変わらない。
- **基準**：ファイルを開いたとき（`file.open` の応答の `fingerprint`）、保存したとき（`file.save` が書いたあとに読み直して返す）、Excel へ反映したあと（`file.fingerprint` で読み直す）に取り直す。読めなかったときは基準なし（検知しない。保存や反映は止めない）。
- **保存・反映の前**：書き込むものがあるときに、ファイルの今の照合値と比べる。違えば確認を出す：［上書きして保存（反映）］（自分の編集で上書き。赤）／［ほかの変更を読み込む］（自分の編集は捨てて読み直し、書き込みはしない）／［差分を見る…］（開いたときの内容と、いまのファイルの内容）／［キャンセル］。編集があるときの既定は［キャンセル］。反映は、自分の編集がないとき（書き換えるものがない）は確かめない。
- **窓に戻ったとき**：既存の窓に戻ったときの問い合わせと同じ門番（`createPollGate`）で、**30 秒に 1 回**に間引く。ダイアログを開いている間・保存や反映の最中は調べない。違っていて、**自分に未保存の編集がなければ、黙って読み直し**、「読み直しました」と知らせる。**編集があれば、読み直さず**、閉じるまで残る警告の通知で知らせる（同じ状態では 1 度だけ。［確認する］で［ほかの変更を読み込む］／［あとで］を選べる）。提案の「帯」は、通知で代用した。
- **設定**：一般 →「外部での変更の検知」（既定オン）。Excel が保存し直したときの実際の挙動を実機で確かめきれていないので、切れるようにしてある（§23.7）。
- **W-7（2 つの Sash の受け渡し）**は別件のまま残る。ただし、この検知で「後から保存したほうが黙って勝つ」は、保存・反映の前に知らせる形になった。

### 23.5 配布前チェックの追加項目

`distributionCheck.ts` に分類を足した（§18.2・§22.6 の決まりに従う：件数に数える「要確認」ではなく、**見直すとよいもの（should）と参考（info）**。エラーは赤、警告と節を分ける）。

- **ほかのアドインと重なりやすい名前**（見直し）：接頭辞のない、種類を表す語＋番号だけの id（`btn1`・`Button2`・`tab_1`。`acct_btnSum` のように固有の接頭辞があるものは対象外）、Excel やよくあるアドインのタブ名と同じタブ名（「ホーム」「アドイン」など）、`Button1_Click`・`OnAction`・`Macro1` などのコールバック名。標準の命名規則（`Ribbon_…`）は、規則で別の名前にできるので対象にしない（誤って出すと煩わしいので判定は控えめ）。［ID の一括置換］への案内を添える。
- **onLoad と Invalidate の入れ忘れ**（見直し）：`get〜` の動的な属性があるのに customUI に `onLoad` がない／（VBA と照合できているとき）onLoad の Sub が受け取った `ribbon` を使っていない（コメントだけ・TODO だけ）／VBA に Invalidate を呼ぶところがない。**共通コード（`modRibbonCore`）の中の定義は、呼び出しに数えない**（定義だけで呼んでいないため）。［onLoad と Invalidate の雛形を挿入］への案内を添える。
- **テーマで見えにくいアイコン**（見直し）：リボンから使っている画像を描いて画素を集計し（`imageStats.ts`）、**暗い単色**（不透明な画素の平均の明るさ 60/255 未満で、80 未満の画素が 85% 以上）、**白に近い単色**（平均 215 超で、190 超が 85% 以上）、**透明になっていない白・黒の背景**（四隅がすべて不透明でほぼ同じ色で、白は 235 超・黒は 40 未満、透明な画素がない）を挙げる。不透明な画素が 16 個に満たない画像は判定しない。画像の色を調べるのは非同期なので、ダイアログを開いたあとに調べ、終わったら描き直す（それまでは「調べています」と注記）。
- **大きすぎる画像**（見直し）：**64px を超える**寸法（PNG のヘッダーから読む。PNG 以外は描いて測った寸法）、または **50 KB を超える**バイト数。
- **配布先でのマクロのブロック**（参考。件数に数えない）：「メールやダウンロードで受け取ったブックは、Windows がマクロをブロックすることがあります」の案内を常に 1 行出し、対処（共有フォルダから各自の PC へコピーしてもらう・ファイルのプロパティの［許可する］で解除してもらう・［信頼できる場所］に置いてもらう）を添える。**いま開いているブック自体にインターネットから取得した印（Zone.Identifier の ZoneId が 3 以上。`MarkOfTheWeb.IsMarked`）が付いている**ときは、見直すものとして先頭に出す。Sash は印を付け外ししない。
- 移る先のない案内の行（`target: 'none'`）は、押せるものに見えないよう、ボタンにしない。

### 23.6 そのほか決めたこと

- **設定の追加**：`autoRecovery`（既定オン）と `detectExternalChanges`（既定オン）。設定ファイル・`settings.get` / `settings.set`・設定画面（一般）に出す。

### 23.7 実機（Windows・Excel）で確かめていないこと

Linux 上の単体テスト（.NET・Vitest）とブラウザ（Playwright。ホストはダミー）で確かめた範囲に、次は含まれない。

- **§23.1**：`vba.insert` で実際にモジュールへ Sub が入ること（既存の §17.6 の未確認が前提）。日本語の Sub 名・Sub 名が同じ別モジュールがあるときの `Call モジュール.Sub` の解決。生成した Sub を、リボンのボタンから実際に呼べること。
- **§23.2**：WebView2 が落ちたときの挙動（`ProcessFailed`）と、そのあとに実際に復旧できること。共有フォルダ上のブックの更新日時の比較（`FileNewer`）。%AppData% への頻繁な書き込みが重くないこと（画像が多いブック）。
- **§23.3**：Excel で開いているブックから、共有違反なしに読めること（`file.read`。`Package.Open` は `FileShare.ReadWrite`）。取り込んだリボンが Excel で表示されること。
- **§23.4**：**Excel が保存し直しても、照合値が変わらない（誤って知らせない）こと**。この機能の前提で、実機でしか確かめられない。特に、Excel がリレーション Id・画像のコンテンツタイプ・名前空間の接頭辞をどう書き直すか。Excel が開いている間のファイルの読み取り。変わるときは、設定の「外部での変更の検知」を切る。
- **§23.5**：`Zone.Identifier`（NTFS の代替データ ストリーム）の読み取りが .NET から動くこと（読めないときは「印なし」として扱う）。画像を描いたときの色の判定（ブラウザの `canvas` の色空間による違い）。案内の文言と、Excel の実際の表示名（［許可する］など）が合うこと。

### 23.8 見直し（レビュー）での修正

0.3.0 のレビューで出た中 7 件・低 10 件を直した。決めたこと：

- **取り込みでのコールバック名（中 1）**：id を振り直したとき、**命名規則（設定）が元の id から作った名前**のコールバック（`Ribbon_btnSum_onAction` など）は、新しい id で付け直す（VBA の Sub・XML のほかの名前と重なれば番号を進める）。規則外の名前（`Quick` など）で、取り込み先のほかのコントロールと同じ名前になるものは、付け直さず、結果画面に警告する（押すと既存の Sub が動くため）。「Sub を共有する」規則のときは名前を触らない。id を振り直し、かつコールバックがあるときは、「共通のコールバックで `control.Id` を `Select Case` で振り分けていると一致しなくなる」と注意を出す。
- **名前空間の接頭辞（中 5）**：取り込み元のルートで宣言された接頭辞が `idQ`・`insertAfterQ`・`insertBeforeQ` の値で使われているとき、取り込み先のルートに `xmlns:接頭辞` を足す。同じ接頭辞が別の URI で宣言済みなら、`x2` のように付け替えて値も直す。**Lint は、宣言のない接頭辞をエラーにする**（Excel が読めないため）。
- **キーヒントと合流（低 14・15）**：取り込み先のキーヒント（大文字小文字を区別しない）と重なる `keytip` は外し、結果画面に挙げる。同じ idMso のタブ・右クリックメニューへ合流させたとき、取り込み元のその要素自身の属性（`label`・`getVisible` など）は使われないので、捨てた属性を結果画面に挙げる。
- **退避の読み出し（中 2）**：`recovery.read` も、書く・消すと同じ待ち行列を通す（開き直した直後に、削除が終わる前に読んで、捨てたはずの退避の復旧を聞かないため。ほかで変更されて読み直すときも同じ）。
- **窓に戻ったとき（中 3）**：黙って読み直す前に、入力中の欄を確定し（`flushEdits`）、照合の後にも編集の有無をもう一度見る。編集があれば、読み直さず通知に回す。
- **反映と基準（中 4）**：基準の取り直しは、**自分が書き込んだとき（書き込むパーツがあるとき）だけ**行う。編集のない反映では基準を動かさない（ほかの変更を照合しないまま基準にして、次の保存で黙って上書きするのを防ぐ）。
- **2 つの Sash（中 6）**：退避のファイル名にプロセス ID を入れ、書く・消すのは**自分のものだけ**にする。ほかのプロセスの退避は、**そのプロセスが動いていれば、復旧の候補にも一覧にも出さず、消さず、古くなっても掃除しない**。動いていなければ（落ちた Sash が残したもの）、復旧の候補にし、そのブックを捨てる・保存したときに一緒に消す。同じブックの退避が複数あれば、新しいほうだけを出す。退避には書いたプロセスの **ID・開始時刻・名前**を記録し、**3 つがすべて一致する（開始時刻は 1 秒の誤差まで）ときだけ「生きている」**とみなす（プロセス ID が使い回されても、落ちた Sash の退避が隠れ続けないため）。開始時刻・名前が取れない（アクセス拒否など）ときは「生きていない」側に倒す（ただし今の自分のプロセスは除く）。記録のない古い形式の退避は ID だけで判定する。Windows 実機での挙動は未確認。
- **割り当てと文書の変化（中 7）**：VBA への挿入を待つ間に文書が変わったときの取り違えを防ぐ。選んだ要素の目印（種類・id・idMso・いまの属性の値）を控え、挿入のあとに、同じパスの要素が同じ目印か確かめてから付ける。違えば付けずに知らせる（挿入した Sub は残る）。
- **退避を消す場面（低 8）**：終了で「保存しない」を選んだとき、言語の切り替えで「破棄して切り替える」を選んだとき、更新のインストールの前に未保存の確認を通ったとき、書く予約も取り消して退避を消す（`discardCurrentRecovery`）。更新をやめて編集を続けるときは、退避を取り直す。
- **復旧後の［元に戻す］（低 9）**：復旧した**すべてのパーツ**を戻す。
- **フィンガープリントの失敗（低 10）**：保存したあとの照合値の読み直しは、**どんな例外でも null**（`RibbonFingerprint.TryComputeFile`）。書き込み済みなのに「保存できませんでした」と出さない。
- **画像の色の覚え（低 11）**：「調べたが読めなかった」画像（null）と「未調査」を区別し、前者では「調べています…」を出さない。覚えは 100 件まで（古いものから捨てる）で、チェックを開くたびに、いま開いている画像以外の分を捨てる。
- **共通コードのモジュール名（低 12）**：配布前チェックは `modRibbonCore` を直書きせず、共通コード側の定数（`RIBBON_HOLDER_MODULE_NAME`）を使う。
- **行継続の宣言（低 13）**：onLoad の Sub の宣言が行継続（行末の ` _`）で複数行でも、宣言の全行を本体から除いてから ribbon の使用を調べる。
- **退避の送り方（低 16）**：画像は、前回までに退避へ送ったものと違うもの（足した・差し替えた）だけを `addImages` に入れ、いま足している画像の id の全部を `addImageIds` に入れる。ホストは、前回の自分の退避から残りを引き継ぐ。書き込みに失敗したら、次は全部送り直す。前回と同じ内容かは、全体を直列化せず、XML・画像の id と中身・編集の回数を直接比べる。
- **元のファイルの確認の時間切れ（低 17）**：退避の一覧（ホーム）と「ファイルが退避のあとで変わっているか」で、元のファイルの有無・更新日時を調べるとき、**2 秒で打ち切る**。打ち切ったときは「ファイルはある・日時は不明」として扱い、復旧の候補から外さない（開こうとすれば、そこで分かる言葉の失敗になる）。
- **黙った読み直しと読み込み中の編集（再確認 A）**：`openFile` に `keepIfDirty` を足し、`file.open` を待つ間に入った編集（入力中の欄を含む）があれば、読み込んだ内容を適用せず（`false` を返す）、窓に戻ったときの検知は通知に回す。
- **退避の画像の引き継ぎ（再確認 2）**：ホストは、`addImageIds` にあるのに、前回の自分の退避にも今回の送り分にもない画像があれば、**書き込みを失敗**にする（欠けた退避を書かない）。UI は失敗で送った画像の記録を捨て、**自動でもう一度**（続けて失敗していないとき）画像を全部送って書き直す。
- **画像の色の覚え（再確認 3）**：固定の上限（100 件）はやめた（開いている画像が多いと、調べた分が追い出されて「調べています…」に戻るため）。閉じたファイルの分は、チェックを開くたびに捨てる。
- **共有の規則と重なりの警告（再確認 4）**：命名規則が「Sub を共有する」のとき、規則どおりの名前（`Ribbon_onAction` など）は、取り込み先と同じ Sub を共有するのが意図なので、重なりの警告から外す（規則外の名前は出す）。
- **keytip の比べる範囲（再確認 5）**：タブどうし、同じタブの中のコントロールどうしで比べる（別のタブの同じ keytip は重なりではない）。取り込んだグループを既存のタブへ足すときは、そのタブの中のコントロールと比べる。

### 24.3 概念の辞書の拡充（日本語の関連性）

### 24.4 アイコンの色の既定の配色（パレット）

アイコン集のダイアログの色は、これまで既定の #424242 と 6 色のプリセット、ブラウザの色選びだけだった。アイコンエディタの色（単色・色の置き換え・バッジ）は、ブラウザの色選びだけだった。**「最近使った色」はどちらにもなかった**ので、残すものはなく、新しく足した。

- **データと判定**は `ui/src/fluent/iconPalette.ts`（純粋）、**画面部品**は `colorPalette.ts` / `colorPalette.css`。アイコン集のダイアログとアイコンエディタが同じものを使う。
- **並べ方**：色相ごとの列（グレー・赤・オレンジ・黄・黄緑・緑・青緑・水色・青・藍・紫・桃・茶の 13 列）に、濃い方から 5 段（濃い・やや濃い・標準・やや淡い・淡い）。その下に Office の「標準の色」10 色（濃い赤 #c00000・赤 #ff0000・オレンジ #ffc000・黄 #ffff00・薄い緑 #92d050・緑 #00b050・薄い青 #00b0f0・青 #0070c0・濃い青 #002060・紫 #7030a0）。**合わせて 75 色**（これまで 6 色）。
- **以前の 6 色**（#424242 グレー（標準）・#217346 Excel の緑・#0f6cbd 青・#c42b1c 赤・#ca5010 オレンジ・#000000 黒）は、同じ値のままグリッドの中にある（グレー・やや濃い／緑・やや濃い／青・標準／赤・標準／オレンジ・標準／グレー・濃い）。
- **色の名前**：「赤・濃い（#691411）」のように色相と濃さと色コードを、ボタンの `aria-label` とツールチップに持つ。標準の色は Office の名前。英語の訳もある（Red・Dark など）。
- **パレットの動き**：アイコンエディタのパレットは、最初に「▾」を押したときに部品を読み込む（起動時の読み込みを増やさない）。パレットを開いているときの Esc は、パレットだけを閉じて「▾」にフォーカスを戻す（`openModal` の `onEscape`。最初の版は Esc でアイコンエディタごと閉じて、加工を失っていた）。パレットで色を選んだとき、その色を使う設定（単色にする・色を置き換える・バッジ）がオフならオンにする。色の入力欄の読み上げ名は、開いている対象（置き換える前／後など）に合わせて変わり、ブラウザの色選びで色を変えたときは、開いているパレットの選択の印も合わせる。#RRGGBB の入力欄は文字数を制限しない（前後に空白のある貼り付けも通る）。
- **最近使った色**：アイコンを決定したときの色を最大 8 色まで覚える（この利用者の手元の localStorage。保存できない環境では覚えないだけ。読むときは大文字小文字だけ違う重複を除く）。
- **色の入力**：`#RRGGBB`（`RRGGBB`・`#RGB` も可）を直接入力でき、Enter か欄を離れたときに確定する。読めない入力は選ばず、案内を出す。ブラウザの色選びも残している。
- **キーボード**：グリッドと標準の色と最近使った色は、それぞれ Tab で 1 つだけ止まり（今の色か先頭）、矢印で隣へ、上下の矢印で段を移り、Home / End で行の端、Ctrl+Home / End で全体の端へ移る。Enter / Space で選ぶ。
- **リボンの上での見え方**：Office の黒・濃い灰色のテーマで沈む色（平均の明るさ 60 未満）と、白・明るいテーマで沈む色（215 超）に、ボタンの右下に印（暗い点／白い点）を付け、選んだときはメモ（「Office の黒・濃い灰色のテーマで背景に沈みます」など）を出す。**基準は配布前チェック（`distributionCheck.ts`、§23.5）と同じ値**で、`imageStats.ts` の `SINK_DARK_LUMA`・`SINK_LIGHT_LUMA`・`sinkOfColor` に 1 か所にまとめて共有する（テストで、パレットの全色が画素の集計と同じ判定になることを確かめる）。淡い色・濃い色を選ぶことはできる（警告するだけ）。
- **ライト・ダーク**：パレットの枠・文字はアプリのテーマの変数を使う。ボタンの縁は `--border-strong`、選択中は 2 重の輪（`--text` と `--focus`）。印の点は沈む先の背景の色（暗い点＝黒いテーマ、白い点＝白いテーマ）で、テーマに関わらず固定。
- **ツールチップの個数**：アイコン集のボタンの説明の「Fluent・Tabler・Lucide・Sash、約 8,300 個」は、`iconCounts.ts`（`npm run icon-counts` でデータから数えて作る）から作り、直書きしない。`ui/test/review031.test.ts` で、実際のデータの個数と合っているか確かめる。
- **配置**：アイコン集のダイアログは、右の欄（プレビューの下）にパレットを常に出す（以前の上段の 6 色の行はやめた）。中身が多いので、このダイアログだけ縦を 720px まで広げる（`openModal` の `tall`）。アイコンエディタでは、色の入力の横の「▾」でその行の下にパレットを開く（同じ行の 2 つの色の入力は 1 つのパレットを使い回す）。

### 25.1 形（アイコンエディタとの関係）

- 今のアイコンエディタ（元画像＋パラメータの非破壊の加工）は、そのまま残す。そのうえに、別のダイアログ「**描いて編集**」（ペイント画面。`ui/src/icon/paint/paintDialog.ts`）を重ねて開く。大きさは 16／32／64px のキャンバス 1 枚（正方形）。
- **入口は 2 つ**：①画像を選ぶ欄の［新しく描く］（大きさを 16×16／32×32／64×64 から選び、空の絵から始める）。②元画像を読み込んだあとの［描いて編集…］（今の加工の結果を出力の大きさで焼き込んで下絵にする。初回だけ「余白や色の設定は初期化されます」と案内する）。
- **描くのは加工の前**：［完了］を押すと、描いた絵がアイコンエディタの新しい元画像になる。描いた点は元画像の座標にあるので、あとで余白・サイズ・角丸・バッジを変えても点がずれない。余白・角丸・バッジなどは、描いたあとの「仕上げ」として今までどおり使える。
- ［完了］のとき、**普通の画像から描いたなら加工の設定を中立（余白 0・自動カットなし・切り抜きなし・透過なし・単色なし・色の置き換えなし・明るさ 0・形なし・バッジなし・シャープ 0）に戻す**（焼き込み済みの絵に、もう一度余白などをかけると二重になるため）。右の設定欄の表示も、すべての欄を同期する。**描いた絵の続きを描き直したとき（`options.paint` がある元画像）は、焼き込まず、元画像から絵を戻して描き、仕上げの設定はそのまま残す**。
- 出力の大きさ（32／64）を変えたとき、元画像が描いた絵なら、絵から元画像を作り直す（拡大した元画像をさらに拡大するとぼけるため）。
- 取り消し（［キャンセル］・×・Esc・背景のクリック）のとき、描いた内容が開いたときと違えば「描いた内容を捨てますか？」を出す（選択だけの操作は数えない）。［完了］はすぐ閉じる。そのために `modal.ts` に **`size: 'xl'`**（幅 1320px・高さ 760px まで）と **`beforeClose`**（×・Esc・背景のクリックで閉じる前に確かめる。渡さないダイアログは今までどおり。`handle.close()` は確かめずに閉じ、利用者の操作と同じ動きは `handle.requestClose()`）を足した。確認の途中の Esc・×は二重に出さない。
- ペイント画面を開いている間は、アイコンエディタの `document` の `paste` とドロップを受けない（元画像が入れ替わるため）。ペイント画面の貼り付けは、画面の中身（`root`）の `paste` で受ける（貼り先が入力欄のときは入力欄に任せる）。
- **画面の部品は動的 import**：アイコンエディタは `paint/` を静的に読まない（［新しく描く］［描いて編集…］を押したときに初めて読む）。ペイント画面の英語の訳も、画面の塊の中で `addDictionary()` で足す（起動時の辞書に入れない）。

### 25.2 画素の扱い

- 画素は既存の `Pixels`（`{ data: Uint8ClampedArray, width, height }`。**ストレートアルファ**の RGBA）で持つ。**描画・塗りつぶし・選択のマスク・合成・変形はすべて `Pixels` を受け取る純粋な関数**（`ui/src/icon/paint/` の `color.ts`・`pixels.ts`・`raster.ts`・`fill.ts`・`selection.ts`・`transform.ts`・`history.ts`・`doc.ts`・`session.ts`）で、jsdom の Vitest で試す。canvas を使うのは、表示（`view.ts`）・PNG への変換・焼き込み（`process()`）・貼り付けた画像の読み込みだけ。
- **合成は自前のストレートアルファ source-over**（canvas の合成は乗算済みアルファを通って半透明の色が丸めでずれるため）。丸めは固定：`outA = sa + da·(255−sa)/255`、各色 `round((src·sa + dst·da·(255−sa)/255) / outA)`、alpha も round。不透明（sa=255）はそのまま写し、完全に透明は dst を変えない。完全に透明な画素は RGB を 0 にそろえる（PNG に余計な色を残さない。比べるときも透明どうしは同じ）。
- **アンチエイリアスはない**（16px ではドットが大事）。鉛筆は色をそのまま書く（背景色＝透明で描けば消える）。消しゴムは透明を書く。点と点の間は Bresenham の直線で埋め、始点と終点を入れ替えても同じ点になる。筆先は太さ 1〜8、四角か丸（太さ 3 の丸は十字、太さ 4 以上は角が欠ける）。
- **塗りつぶし**：4 近傍（斜めには漏れない）、許容差 0〜100（RGBA 4 成分の距離の最大値 510 に対する割合。0 は完全一致）、「つながった所だけ」か「全体」。選択範囲があれば、その中だけ（つながりも外へ広がらない）。同じ色で塗っても止まる。
- **選択**：マスク（絵と同じ大きさの 0／255）。四角形の選択の中をドラッグすると、中身を「浮いた選択」に持ち上げて（元の場所は透明に）動かす。動かさずに離したら持ち上げない。確定するとき、**透明な部分は下の絵を消さず**、はみ出した部分は捨てる。全部はみ出したら選択も消える（空の選択が残ると、どこにも描けなくなるため）。描くツールは選択範囲の中にだけ書く。浮いたまま別のツールに替える・選択の外をクリックする・Enter・Esc・［完了］で確定する。
- **履歴**：丸ごとのスナップショット（絵・選択・浮いた選択）。1 回のドラッグ＝1 手、変化のない操作は積まない。上限は **300 手かつ合計 32MB**（古いものから捨てる。直前の 1 手は大きくても残す）。矢印キーでの連続した移動（同じ向き・500ms 以内）は 1 手にまとめる。履歴はペイント画面を閉じると捨て、アプリの履歴には今までと同じ「画像の追加と設定」の 1 手だけが入る。
- 外部のライブラリは使わない。

### 25.3 保存形式（利用者の了承を得て足した）

**C#（ホスト）は変えない**（`IconLibrary` は `options` の中を見ない）。足したのは次の 2 つだけ。

- **`source`**＝描いた絵を**最近傍で整数倍に拡大した PNG**（`image/png`、名前は `<画像名>.png`）。倍率 `k = max(1, ⌊出力の大きさ ÷ キャンバス⌋)`（キャンバス 16 → 出力 32 なら 2 倍、64 なら 4 倍。32 → 32 は 1 倍、32 → 64 は 2 倍、64 → 32 は 64 のまま〈縮小は `process()` に任せる〉）。
- **`options`**＝今までの加工の設定に **`paint: { v: 1, canvas: 16|32|64 }`** を足したもの。**画素は `options` に入れない**（共有フォルダの一覧が重くなるため。`IconLibrary.List()` は全部の `.json` を読む）。

**絵の戻し方と検査**（共有フォルダの値は信用しない）：`readPaintMeta(options, 幅, 高さ)` は、`v` が 1、`canvas` が 16／32／64、元画像が正方形で幅がキャンバスの 1・2・4 倍のときだけ通す。さらに `recoverFromSource` が、k×k のブロックの中がどれも同じ色か（完全に透明な画素は同じ）を画素で確かめる。**どれかが合わなければ `paint` を外して普通の画像として扱う**（焼き込みから始める）。`v` が 2 以上なら「もっと新しい版の Sash で描いた絵です。…描き直しはできません」と知らせて普通の画像にする。

**後方互換**：
- **0.3.1 で読む**：`paint` は知らない鍵としてそのまま運ばれる。元画像は普通の PNG で、加工の設定は中立なので、**見た目は一致する**。ブラウザ上の検証（`ui/scripts/verify-paint.mjs`）で、描いた結果の `source` と `options` を **0.3.1 の `process()` と同じ手順**（切り抜きなし・透過なし・自動カットなし・余白 0・色なし・形なし・バッジなし・シャープ 0）に通し、ブックの画像と**画素が 1 バイトも違わない**ことを、32 の絵・16 の絵（2 倍）で確かめた。0.3.1 は元画像を描き換えないので、0.3.1 で加工し直して保存しても `paint` は残るだけで矛盾しない。ただし 0.3.1 は、ダイアログの中で別のファイルを読み込み直しても `opts`（`paint` を含む）を引き継ぐので、写真に `paint` が付いたまま保存されることがありうる。新しい版は上の検査（ブロックがそろわない・倍率が合わない）で見分ける。見分けられないのは、写真がたまたまキャンバスと同じ大きさ（倍率 1）のときだけで、そのときは元画像をそのまま絵として描き直すだけで害はない。
- **新しい版で古いアイコンを読む**：`paint` がないので、今までどおり。
- **一括取り込み（`bulkImport`）**：今の設定を全部の画像に付けているので、**`paint` を外して**付ける（付けると、取り込んだ写真に「描いた絵」の印が付く）。
- **ライブラリに保存し直したとき**：今の `Add` は上書きしないので、第 1・2 段階は**別のアイコン（名前に `-2`）**になる（利用者の了承済み。上書き保存は第 3 段階で C# に `Replace` を足す）。
- 描いた絵の続き（`options.paint` がある元画像）は、このセッションの間と、ライブラリから開き直したときに描き直せる。ブックを保存して開き直すと画像は PNG だけになる（今の `ImageEntry.edit` の決まりのまま）。

### 25.4 画面とキー操作

- **配置**（1366×700 でも収まる）：上に道具の行（元に戻す／やり直し・拡大率・全体・グリッド・ツールの設定・キャンバスと出力の大きさ）、左にツール（40px の正方形 5 つ）、中央にキャンバス、右に色（前景色・背景色・入れ替え・既定の色・「透明にする」・75 色のパレット・最近使った色・#RRGGBB）と実寸プレビュー（16・32px をライト・ダークの背景で。出力と同じ作り方で変換したもの。背景が不透明のときは一行で案内）、下に状態の行（座標・色・選択の大きさ・ツールの使い方）と［完了］［キャンセル］。ダイアログの本体は `xl`（1366×700 の画面で 1320×668）。見た目は §22.7 のトークンだけ（`color-mix()`・入れ子は使わない。CSS は `paint.css`）。
- **拡大**は整数倍だけ（1・2・3・4・6・8・12・16・24・32）。既定と［全体］は、入る中で一番大きい整数倍（**1366×700 では 32px が 12 倍、64px が 6 倍、16px が 24 倍**。16 倍の 512px は入らない）。ピクセルのグリッドは 6 倍以上で出し、切り替えられる。市松模様は画面の 8px 単位。選択の枠は白黒の点線（`prefers-reduced-motion` のときは止める）。
- **色**：前景色（既定 #424242）・背景色（**既定は透明**）。右クリックは背景色で描く（透明なので消える）。パレットで変えるのは、前景色・背景色のボタンで選んだほう（パレットの部品に右クリックの口がないため、設計書のとおりボタンで切り替える方式にした）。描いた不透明の色は「最近使った色」（8 色。`localStorage` に覚える）に入る。
- **キー操作は、ダイアログの中身（`.paint-editor`）で受ける**（`dialog` や `document` には付けない。付けると `modal.ts` の Enter の処理が先に動いて［完了］が押される）。入力欄・選択欄の中、日本語の変換中は受けない。ボタンの上の Enter・Space はボタンの動きのまま。**キャンバスの上の Enter は、いつも `preventDefault` する**（［完了］が押されない。浮いた選択があれば確定する）。

### 25.6 設計書との違い

- ツールの処理は、設計書の `tools.ts`（ツールごとのオブジェクト）ではなく、1 つの `PaintSession`（`session.ts`。ツール・色・履歴・ポインタとキーを持つ）にまとめた。DOM に触らず、疑似のポインタの並びで試せる点は同じ。
- 焼き込みは、いつも**出力の大きさ（32／64）のキャンバス**で行う。設計書にあった「`process()` に大きさを渡せるようにして 16 を焼き込む」は入れなかった（16 のキャンバスは［新しく描く］からだけ。写真を 16 のドットに直したい要望は聞いていないため）。
- ツールのボタンは `role="radio"` ではなく、`aria-pressed` の切り替えボタンにした（依頼の指定）。
- 設計書で「時間が足りなければ第 2 段階に回してよい」とされたもののうち、Alt＋ドラッグの複製・Shift＋クリックの直線・Ctrl＋ホイールの拡大・ペンの消しゴム側・OS のクリップボードからの貼り付け・初回の手引き・ショートカットの一覧は入れた。**キーボードのカーソルで描くこと（矢印でカーソルを動かして Enter で描く）は入れていない**（第 2 段階に回す。今のキー操作は、ショートカットと、選択範囲の矢印移動まで）。
- 「V（移動）」のツールは作らず、移動は四角形の選択の中のドラッグ・矢印で行う。
- 選択の作成・解除・すべて選択も 1 手として履歴に積む（Ctrl+Z で選択が外れる）。ただし「描いた内容が変わったか」の判定（閉じる前の確認）には数えない。
- ペイント画面の英語の訳は、`i18n/en/paint.ts` を画面の塊が読み込まれたときに足す（設計書は `en/i.ts` に入れる案だったが、起動時の辞書を増やさないため）。アイコンエディタに足した 8 文言だけを `en/i.ts` に置く。
- 描いた絵の PNG への変換に、`canvas.toBlob` ではなく `toDataURL` を使う（Chromium の `toBlob` は、画面が忙しいと 1 秒ほど待たされることを、Playwright で見つけたため）。

### 25.8 第 1 段階の範囲と、次の段階

**第 1 段階（実装済み）**：新しく描く（16／32／64）・取り込んだ画像から描く・鉛筆（太さ 1〜8、四角／丸）・消しゴム・塗りつぶし（許容差、隣接のみ／全体）・スポイト・四角形の選択（移動・Alt で複製・Delete・Esc・Ctrl+A/D・矢印）・コピー／切り取り／貼り付け・元に戻す／やり直し・整数倍の拡大・グリッド・パン・前景色と背景色・75 色のパレットと最近使った色・実寸プレビュー・アイコンエディタへの戻し方・ライブラリへの保存と描き直し。

**第 2 段階**：ブラシ（太さ・硬さ・不透明度）・直線・四角形・楕円・楕円の選択・なげなわ・自動選択・選択の足す／引く・選択範囲の反転と 90° 回転・**選択範囲だけの色の変更**（色相・彩度・明るさ・ある色を別の色に置き換え・単色化）・画像全体の反転と回転・キャンバスの大きさの変更・余白のカット・透明にする色・この絵に使われている色・色の不透明度・OS のクリップボードへのコピー・キーボードのカーソルで描くこと。**第 3 段階**：文字・多角形・グラデーション・選択範囲の自由な拡大縮小と回転・縁取りと影・タッチの 2 本指・ライブラリの上書き保存（C# に `Replace`）。**第 4 段階**（使い方を聞いてから決める）：最小限のレイヤー（`paint.v: 2`）。やらないこと：Photoshop 級の機能・ベジェ・アニメーション・外部の画像編集ソフトとの連携・筆圧・24／48／128 のキャンバスなど（理由は設計書 §6）。

### 25.9 確かめていないこと（Windows 実機）

次はブラウザ（Chromium）の上でだけ確かめた。WebView2 を載せた Windows 実機では確かめていない。下限の Chromium 109 でも確かめていない（`getCoalescedEvents`・`ResizeObserver`・`ImageData` など、109 にある機能だけを使ったつもり）。

- **ペン・タッチ**：ペンの消しゴム側（`buttons & 32`）、`getCoalescedEvents()` による間の点、タッチ 1 本指で描くこと。タッチの 2 本指の拡大とパンは第 3 段階。筆圧は使わない。
- **高 DPI（125%・150%）**：ポインタの位置から画素への換算（`getBoundingClientRect` と拡大率だけを使い、`devicePixelRatio` は描くときだけ）と、グリッドの線がぼけないこと。
- **OS のクリップボード**：ほかのアプリでコピーした画像の貼り付け（`paste` イベントの画像）。テストは、画像を入れたイベントを手で発火して確かめた。
- **WebView2 でのダイアログ**：Enter・Space・Esc・Tab の動き（Chromium では確かめた）、ファイルの背景へのドロップ。
- **Excel が 32px の画像を小さいボタンの 16px に縮めたときの見え方**：2 倍の最近傍で作った 32px は、Excel がどう縮めても 16px の元の絵に近くなるはずだが、実機で確かめていない。
- **16・32px の実寸の見え方（日本語・英語のフォント）**。
