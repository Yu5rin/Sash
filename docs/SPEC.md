# Sash 仕様書 v0.1 — Excelリボンエディタ

2026-11-22

## 1. 概要・目的

xlsm / xlam のカスタムリボン（customUI）を、見たまま組み立てて手で直せる単体デスクトップツールを作る。AI連携は対象外で、リボンの追加と手動編集を快適にすることだけに集中する。Graftとは独立したアプリとする。

解決したいのは、現状のリボン開発にある三つの手間である。XMLをテキストで書くしかなく構造が見えないこと、反映のたびにExcelを閉じて開き直す往復が発生すること、XMLとVBAコールバックの不整合やアイコンの用意に気づきにくいことの三つだ。

対象ユーザーは、VBAで業務ツールやアドインを作るExcelユーザー。まずは作者自身と社内での利用を想定する。対象ファイルは .xlsm / .xlam を必須とし、.xltm / .xlsb は第2弾以降に検討する。

## 2. 既存ツールとの差別化

VBA向けのリボンを現代的なビジュアルエディタで作れるツールは、まだ存在しない。既存のツールはどれも、XMLをテキストで編集するものか、VSTO専用のものだ。本ツールは、キャンバスでの編集、Excelとの即時連携、アイコンの作成で差を付ける。

| ツール | 編集方式 | VBA（xlsm/xlam） | 現状 | 足りないもの |
| --- | --- | --- | --- | --- |
| [Office RibbonX Editor](https://github.com/fernandreu/office-ribbonx-editor) | XMLテキスト（ScintillaNET）＋ツリー | 対応 | WPF / .NETで開発が継続中 | ビジュアル編集、Excel連携、アイコンの加工 |
| [Custom UI Editor（OfficeDev）](https://github.com/OfficeDev/office-custom-ui-editor) | XMLテキスト | 対応 | 2024年6月にアーカイブ済み | 保守。スキーマは2010まで |
| [VS Ribbon Designer](https://learn.microsoft.com/en-us/visualstudio/vsto/ribbon-overview?view=vs-2022) | ビジュアル | 非対応（VSTO専用） | Visual Studioに同梱 | VBAで使えない。コールバックを生成しない |
| RibbonX Visual Designer | ツリー＋フォーム | 対応 | Excelアドイン。UIは2007年代のまま | 現代的なUI、高DPI、ダークモード |

本ツールの柱は次の五つ。

1. キャンバス編集。本物のExcelのリボンに近いプレビュー上に、ドラッグで部品を置く。
2. 賢いインスペクタ。使える属性だけを出し、入力中に検証する。
3. Excelとの即時連携。ワンクリックで反映し、コールバックを同期する。
4. アイコンの作成。画像やicoから加工してそのまま設定できる。
5. 現代的な操作性。コマンドパレット、あいまい検索、ダークモード、日本語UIを備える。

## 3. 動作環境・技術構成

C#（.NET 10）をホストにし、UIはすべてWebView2（HTML / CSS / TypeScript）で描く。リボンのプレビュー、Monacoエディタ、SVGアイコン、ダークモードを少ない労力で現代的に作れるためだ。

| 層 | 担当 | 主な技術 |
| --- | --- | --- |
| UI | キャンバス、ツリー、インスペクタ、XMLエディタ、アイコンエディタ | WebView2、TypeScript、Monaco Editor |
| ホスト | ウィンドウ、ファイルダイアログ、UIとのメッセージ交換 | WinForms（外枠のみ）、WebView2 PostMessage |
| コア | OPC（zip）の読み書き、customUIモデル、XSD検証、Lint | System.IO.Packaging、System.Xml.Schema |
| 画像 | 画像/ico/SVGの読み込み、加工、PNG出力 | System.Drawing / WIC、SVGはブラウザ側でラスタライズ |
| Excel連携 | ブックの制御、VBEの読み書き、imageMsoの取得 | Excel COM（遅延バインド） |

動作環境はWindows 10 / 11（64bit）、Excel 2016以降またはMicrosoft 365。配布はself-containedの単一exeで、インストーラーは使わない。WebView2ランタイムはOS標準のものを使う。設定とアイコンライブラリは `%AppData%\Sash` に保存する。

COMは遅延バインドで呼ぶ。Interopアセンブリを同梱しないため、Excelのバージョンに依存しない。Excelが入っていないPCでも、ファイル編集だけは動くようにする。

UIの技術はWebView2で確定した（WPF、WinUI 3と比較のうえ決定）。

## 4. 画面構成

メインウィンドウは一画面で完結させる。左にパレットとツリー、中央にキャンバスとXMLエディタ、右にインスペクタ、下に問題とコールバックのパネルを置く。どのペインで要素を選んでも、他のペインで同じ要素が選択される。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Sash  集計ツール.xlam（Excelで開いています）   [Ctrl+K コマンド] [反映 F5] │
├──────────────┬───────────────────────────────────────┬───────────────────┤
│ パレット     │ キャンバス（リボンのプレビュー）      │ インスペクタ      │
│ button/toggle│  ファイル ホーム 挿入 [集計ツール]    │ 基本              │
│ menu/split   │ ┌──────┬──────────┬──────┬─────────┐  │  id   btnSummary  │
│ dropDown     │ │[集計]│□CSV出力  │[自動]│ ここに  │  │  label 集計する   │
│ editBox      │ │      │□クリア   │      │ドロップ │  │  size  large      │
│ レシピ       │ │      │□設定     │      │         │  │ 表示              │
├──────────────┤ │ 集計            │モード│         │  │  [□] アイコン編集 │
│ ツリー       │ └─────────────────┴──────┴─────────┘  │ 動作              │
│ tab 集計ツール├───────────────────────────────────────┤  onAction 実装済み│
│  group 集計  │ XMLエディタ（Monaco）                 │  getEnabled なし  │
│   btnSummary │ <tab id="tabTools" label="集計ツール">│                   │
│   btnCsv     │   <group id="grpSum" label="集計">    │                   │
│  group モード│     <button id="btnSummary" ...       │                   │
│   tglAuto    │                                       │                   │
├──────────────┴───────────────────────────────────────┴───────────────────┤
│ 問題 2 ・ コールバック 4（未実装 1） ・ アイコン 3 ・ 差分                 │
└──────────────────────────────────────────────────────────────────────────┘
```

各ペインは幅を変えられ、折りたたむこともできる。XMLを主に使う人向けに、キャンバスとXMLの上下を入れ替えるレイアウトも選べるようにする。アイコンエディタとカタログは、メイン画面の上に重なるダイアログとして開く。

## 5. 編集機能

キャンバス、ツリー、XMLの三つのビューは、一つの内部モデル（customUIのツリー）を共有して常に同期する。どのビューで変更しても、Undo / Redoは一つの履歴にまとめて記録する。

### 5.1 ファイル

- .xlsm / .xlam をドラッグ&ドロップ、または「開く」で読み込む。最近使ったファイルをホーム画面に並べる。
- customUI14.xml（2010以降）と customUI.xml（2007）の両方を扱う。新規作成時はcustomUI14を既定にし、.rels へのリレーション登録も自動で行う。
- 両方がある場合は「2010以降のExcelは14を優先する」と警告し、どちらを編集するか切り替えられるようにする。
- 保存のたびに元のファイルを世代つきでバックアップする（既定は10世代）。customUI以外のパーツ（シート、VBAプロジェクト）には一切触れない。
- リボン定義を `.sash.json` として書き出し・読み込みできるようにする。別のブックへの流用と、Gitでの差分管理に使う。

### 5.2 キャンバス

- Excelのリボンに近い見た目で、タブ、グループ、コントロールを描画する。ライトとダークの両方に対応する。
- 左のパレットからドラッグして配置する。配置できない場所ではドロップ先の表示を出さない（例：グループの外にボタンは置けない）。
- クリックで選択、ドラッグで並べ替え、Ctrl+Dで複製、Deleteで削除。グループをまたいだ移動もできる。
- large・normalのサイズ、ラベルの改行、小ボタンの3段積みを、本物に近い形で再現する。
- 組み込みタブ（ホームなど）にグループを足す場合、組み込み部分はグレーのプレースホルダーで示し、自分で足した部分だけを編集対象にする。
- 対象はリボン、クイックアクセスツールバー、コンテキストメニュー、Backstage。Backstageとコンテキストメニューは第2弾で対応する。

### 5.3 ツリー

- customUIの階層をそのまま表示する。キャンバスでは選びにくい要素（menuの中身、dialogBoxLauncher、非表示の要素）はここで操作する。
- 各ノードには、種類のアイコン、ラベル、id、警告バッジを表示する。

### 5.4 インスペクタ

- 選んだコントロールに使える属性だけを、「基本」「表示」「動作（コールバック）」「詳細」に分けて出す。
- 属性の型に合わせた入力欄を使う。列挙値はドロップダウン、真偽値はトグル、imageMso / idMsoは検索つきピッカー、imageはアイコンエディタの呼び出し。
- 「label」と「getLabel」のような静的値と動的コールバックの組は、1行の切り替えスイッチにまとめる。これで排他の矛盾がそもそも起きない。
- 属性名にホバーすると、日本語の説明と指定例を表示する。
- idはラベルから自動で提案する（例：「集計する」→ btnSummary）。

### 5.5 XMLエディタ

- Monacoを使い、XSDに基づく要素・属性の補完、エラーの波線表示、折りたたみ、整形を備える。
- カーソル位置の要素を、キャンバスとツリーでも選択状態にする（逆方向も同じ）。
- XMLの構文が壊れている間は、他のビューを最後に正しかった状態のまま表示し、上部に「同期停止中」と出す。
- コメントと属性の並び順は、キャンバスで編集してもできるだけ保持する。

### 5.6 検証（Lint）

XSDによる検証に加え、次の独自ルールを入力中に常時チェックする。結果は下部の「問題」パネルに一覧表示し、クリックで該当箇所に飛べる。

| ルール | 重大度 |
| --- | --- |
| id / idMso / idQ の重複、または未指定 | エラー |
| 静的属性と get系コールバックの同時指定 | エラー |
| image が参照する画像がファイル内にない | エラー |
| 存在しない idMso / imageMso | 警告 |
| keytip の重複 | 警告 |
| グループ内のコントロールが多すぎる（狭い画面で畳まれる） | 情報 |
| VBAに存在しないコールバック（Excel連携時） | 警告 |

## 6. アイコン作成・設定機能

手元の画像やicoをドロップすると、リボン向けのPNGに加工してファイルに埋め込む。さらに、コントロールの image 属性への設定までを一つの操作で終える。customUI/images への配置や rels への登録を、利用者が意識する必要はない。

### 6.1 取り込めるもの

| 入力 | 扱い |
| --- | --- |
| PNG / JPG / BMP / GIF / WebP | そのまま読み込む。GIFは最初のフレームを使う |
| ICO | 含まれる全サイズを一覧表示する。出力サイズに最も近く、それ以上の大きさのものを自動で選ぶ。手動での選択もできる |
| SVG | 出力サイズでラスタライズするので、どのサイズでも綺麗に出る |
| EXE / DLL | 埋め込みのアイコンを一覧にして選んで取り出す（社内ツールのアイコンを流用する用途） |
| クリップボード | Ctrl+Vで画像を貼り付ける |
| imageMso | 組み込みアイコンをPNGとして書き出し、色替えなどの加工の元にする |
| アイコン集（Fluent） | 同梱の Fluent UI System Icons（MIT License、24px の線 / 塗り、約2,900個）から、日本語・英語で検索して色を付けて選ぶ。出力サイズで描き直して PNG にし、アイコンエディタで加工できる。Excel は不要 |

### 6.2 アイコンエディタ（加工）

取り込んだ画像は、下記の操作を非破壊で重ねて加工できる。元画像は保持するので、あとから何度でもやり直せる。

- トリミング：余白の自動カット、正方形への手動切り抜き
- 余白：上下左右のパディング（既定はサイズの8%）
- 背景の透過：スポイトで選んだ色を、許容値つきで透明にする（白背景のJPG対策）
- 色：単色化、任意の色への置き換え、明るさの調整
- 形：角丸、円形マスク、バッジ（右下に小さな印）の重ね合わせ
- シャープ化：縮小後の16pxで線がぼけないように補正する

プレビューでは、16pxのnormalボタンと32pxのlargeボタンの実寸表示を、ライトとダークのリボン背景の上に並べる。実際に置いたときの見え方を、反映する前に確認できる。

### 6.3 出力と設定

- 出力は32×32の透過PNGを既定にする。高DPI向けに64×64も選べる。Excelが表示サイズに合わせて縮小する前提だが、実際の見え方は実機で検証する。
- 保存先は `customUI/images/<名前>.png`。`customUI/_rels/customUI14.xml.rels` に画像リレーションを登録し、そのIdを image 属性に設定する。
- 画像名はコントロールのidから自動で付ける（例：`img_btnSummary`）。あとから変更もできる。
- キャンバス上のボタンに画像ファイルを直接ドロップすると、アイコンエディタが開き、確定でそのボタンに設定される。
- どのコントロールからも参照されていない画像は「未使用」と表示し、一括で削除できる。
- フォルダをドロップすると、中の画像を同じ加工設定で一括して取り込む。

### 6.4 アイコンライブラリ

加工済みのアイコンは `%AppData%\Sash\icons` に、加工設定ごと保存する。保存したアイコンは、別のブックでも検索して使い回せる。タグ付けとお気に入り登録にも対応する。社内で共有したい場合に備えて、ライブラリの場所を共有フォルダに変えられるようにする。

## 7. Excel連携・反映

「反映」ボタン（F5）を押すと、Excelで開いているブックにも、閉じる・書き込む・開き直すを自動で行ってリボンを更新する。編集してからExcelで確認するまでを、数秒に縮めるのが狙いだ。

### 7.1 反映の流れ

1. 対象のブックが開いているかを、実行中のExcelをすべて調べて判定する（フルパスで照合）。
2. 開いていなければ、ファイルに書き込んで終了する。
3. 開いていて未保存の変更があれば、「保存して反映」か「中止」を選ばせる。勝手には保存しない。
4. ブックを保存して閉じる。xlamの場合は、アドインとして読み込まれているかどうかも記録しておく。
5. バックアップを取ってから、customUIパーツと画像を書き込む。
6. 同じExcelインスタンスで開き直す。アドインだったxlamは、アドインとして読み込み直す。開き直したときは、作成したタブをアクティブにする。
7. 成功か失敗かをトーストで表示する。失敗したらバックアップから戻せるようにする。

### 7.2 連携のその他の機能

- リボンエラーの表示：Excelのオプション「アドインのユーザーインターフェイスエラーを表示する」がオフなら、初回の反映時に有効にするよう案内する。設定は勝手には変えない。
- 開いているブックから開く：Excelで開いているxlsm / xlamを一覧から選んで、エディタに読み込める。
- 保護ビューとマクロの無効化：開き直したときにこれらで止まったら、その旨を表示して利用者の操作を待つ。セキュリティ設定には触れない。
- Excelがない環境：連携機能をグレーアウトし、ファイル編集だけを使えるようにする。

## 8. コールバック管理

XMLに書いたコールバック名と、VBA側のSubを突き合わせて一覧にする。そのうえで、足りないSubは正しいシグネチャで生成する。リボンが動かない原因で一番多いのは、名前の不一致とシグネチャの間違いだ。この二つを仕組みとして起きなくする。

### 8.1 シグネチャの生成

コントロールの種類と属性から、正しい引数を自動で決める。主なものは次のとおり。

| 属性（対象） | 生成する引数 |
| --- | --- |
| onLoad（customUI） | ribbon As IRibbonUI |
| onAction（button） | control As IRibbonControl |
| onAction（toggleButton / checkBox） | control As IRibbonControl, pressed As Boolean |
| onAction（dropDown / gallery） | control As IRibbonControl, id As String, index As Integer |
| onChange（editBox / comboBox） | control As IRibbonControl, text As String |
| getLabel / getEnabled / getVisible / getPressed / getImage など | control As IRibbonControl, ByRef returnedVal |
| getItemCount（dropDown / gallery） | control As IRibbonControl, ByRef count |
| getItemLabel / getItemID（dropDown / gallery） | control As IRibbonControl, index As Integer, ByRef returnedVal |
| getContent（dynamicMenu） | control As IRibbonControl, ByRef content |

### 8.2 一覧と同期

- 「コールバック」パネルに、名前、使っているコントロール、VBAでの状態を並べる。状態は「実装済み」「未実装」「引数が不一致」「VBA側にしかない（未使用）」の四つ。
- VBAの読み取りは、Excelでブックを開いているときだけ、VBEのCOM経由で行う。「VBAプロジェクト オブジェクト モデルへのアクセスを信頼する」がオフなら、その旨を表示して一覧は空のままにする。
- 未実装のSubは、「コピー」か「モジュールに挿入」を選んで生成する。挿入先は既定で標準モジュール `modRibbon` とし、なければ作る。既存のコードは書き換えず、末尾に追加するだけにする。
- インスペクタでコールバック名を変えたときは、VBA側のSub名も変えるかを確認する。変える場合は宣言行だけを書き換える。
- 名前は既定で `Ribbon_<id>_<属性>`（例：`Ribbon_btnSummary_onAction`）とし、命名規則は設定で変えられる。複数のコントロールで1つのSubを共有し、`control.id` で振り分ける書き方も選べる。

### 8.3 onLoadとInvalidateの雛形

getEnabled などの動的属性を使うときは、onLoad で受け取った IRibbonUI を保持して Invalidate を呼ぶ必要がある。VBAでエラーが起きて変数がリセットされると、この参照が消える。そこで、参照をセルや名前定義に退避して復元する定番のコードを、雛形として挿入できるようにする。32bit、64bitの両方のOfficeに対応させる（LongPtr、PtrSafe）。

## 9. カタログ・レシピ・操作性

「名前がわからない」「書き方を忘れた」を、ツールの中だけで解決できるようにする。

### 9.1 idMso / imageMso カタログ

- Microsoftが公開しているExcelのコマンドID一覧をもとに、組み込みのタブ・グループ・コマンドのidを内蔵する。日本語の表示名でも検索できるようにする。
- imageMsoは、初回起動時にExcelの GetImageMso で全アイコンを取得してキャッシュする。Excelがない環境では名前だけを表示する。
- ギャラリー表示であいまい検索し、クリックで選択中のコントロールに設定する。最近使ったものとお気に入りを先頭に出す。

### 9.2 レシピ（テンプレート）

XMLとコールバックのVBAをセットにして挿入する。最初に用意するものは次のとおり。

- 独自タブ＋グループ＋ボタン3つ
- ホームタブの末尾に自分のグループを追加
- 状態を保持するトグルボタン（getPressed と Invalidate）
- 条件で有効・無効を切り替えるボタン（getEnabled）
- シート名などから中身を作る dynamicMenu
- 選択肢をVBAで組み立てる dropDown
- 特定のシートでだけ表示するタブ（getVisible）

自分で作った構成を選択して「レシピとして保存」し、あとから使い回せるようにもする。

### 9.3 操作性

- Ctrl+Kのコマンドパレットから、すべての操作を名前で呼べる。
- 主なショートカット：F5 反映、Ctrl+S 保存、Ctrl+Z / Ctrl+Y 元に戻す・やり直し、Ctrl+D 複製、Ctrl+1 / 2 / 3 でキャンバス・ツリー・XMLに移動。
- 保存済みの状態との差分を、XMLの対比表示で確認できる。

| コールバックの一覧 | VBE からモジュールを読み、Sub の宣言（行継続とコメントを考慮）を解析して「実装済み」「未実装」「引数が不一致」「VBA側にしかない」に分ける。型を書いていない引数は一致とみなし、値を返す引数の ByVal と Private の Sub は不一致として理由を出す |

### 13.2 決めたこと

- レシピの VBA の識別子は、id を単語の区切り（英数字以外）で囲む形にそろえる（例：`m_tglAuto`）。id を振り直したときに、変数名や定数名も一緒に置き換わるようにするため。
- 加工し直すための元画像と設定は、メモリ上にだけ持つ。ファイルを開き直すと、加工し直せない（ブックに独自の情報を書き込まないため）。保存して使い回す仕組みは、第3弾のアイコンライブラリで扱う。
- 「特定のシートでだけ表示するタブ」と「条件で有効・無効を切り替えるボタン」のレシピは、ThisWorkbook のイベントを使うので xlsm 向け。xlam でほかのブックのシートに反応させるには、アプリケーションイベントのクラスが必要になる。

2026-11-22 時点。Linux 上でのビルドとテスト、ブラウザでの画面操作までを確認した。フォルダ選択・保存ダイアログなどホスト側の操作は Windows 実機での確認がまだ。

### 14.1 実装したもの

| 項目 | 内容 |
| --- | --- |
| Backstage | backstage / tab / firstColumn / secondColumn / group / primaryItem / topItems / bottomItems / taskGroup / taskFormGroup / category / task と、button・checkBox・editBox・dropDown・comboBox・radioGroup・hyperlink・labelControl・imageControl・groupBox・layoutContainer・menu を編集できる。キャンバスの［ファイル］タブで、左のメニューと列・グループを本物に近い形で表示し、ドラッグで配置・並べ替えできる |
| 保存済みとの差分 | Monaco の差分エディタで、保存済みの XML と編集中の XML を比べる。追加・削除する画像も一覧で出す |
| .sash.json | リボン定義を画像込みで書き出し、別のブックで読み込める（元に戻すで取り消せる）。XML は1行ずつの配列で持ち、Git の差分が行単位で読める |

| 英語UI | 設定で日本語 / English を切り替える。画面の文言、Lint のメッセージ、属性の説明、ホスト側のダイアログとエラーメッセージが対象 |

### 14.2 決めたこと

- Backstage の要素は、tab や group などがリボンと同じ名前で中身が違う。そこでスキーマを別の表で持ち、要素が backstage の中にあるかどうかで引き分ける。インスペクタ、Lint、XML補完、パレットはすべてこの判定に従う。
- アイコンライブラリは、1つのアイコンを「json・png・元画像」の3ファイルで持ち、全体の目録ファイルは作らない。共有フォルダで複数人が同時に追加しても壊れにくくするため。お気に入りは人ごとの設定に持つ。
- 英語UIは、日本語の文言そのものを辞書のキーにする（gettext と同じ方式）。辞書にない文言は日本語のまま表示されるので、訳し漏れがあっても画面が壊れない。言語を切り替えたときは画面を読み込み直し、開いていたファイルを開き直す。
- レシピの XML と VBA の中身（ラベルやメッセージ）は、英語UIでも日本語のまま挿入する。利用者のブックに入る内容なので、画面の言語とは切り離した。

| 右クリックメニュー | キャンバスとツリーで、切り取り・コピー・貼り付け・複製・削除・前に挿入・子を追加・移動・XML で表示・ID をコピー。挿入できるのはスキーマで置けるものだけ |

| インスペクタ | 属性は日本語名と生の属性名を並べ、基本・表示・画像・コールバック・詳細で折りたためる。真偽値は「既定 / はい / いいえ」、静的と動的は「固定 / VBA」で切り替え、切り替える前の値を覚えておく。入力は Enter か欄を離れたときに確定し、Esc で戻す。保存・反映・閉じる・終了の前には、入力中の欄を確定してから進む。確定を断られた（構文エラー中など）・取りやめた（コールバック名の変更でキャンセル）ときは、欄を元の値に戻す |
| 通知 | 最大 3 件まで積む。あふれたら、いま出したもの以外で古いものから消す（エラーはなるべく残し、すべてエラーならいちばん古いエラーを消す）。エラーは閉じるまで残し、それ以外は数秒で消える。削除の通知には「元に戻す」を付け、そのあとに別の編集・元に戻す・やり直しがあったら閉じる |
| ダイアログ | フォーカスをダイアログの中に閉じ込め、Esc は一番上だけを閉じる。同じダイアログは二重に開かない。更新の入れ替え中は閉じられない |
| 閉じるときの確認 | 閉じる（Ctrl+W）・別のファイルを開く・終了・ウィンドウを閉じるときに、未保存なら「保存する / 保存しない / キャンセル」を聞く。ウィンドウの × で聞いてキャンセルされたら、UI がホストに `app.closeCancelled` を送り、次の × をすぐ受け付ける。確認の途中で × を続けて押しても、確認は二重に出さない |
| デザイン | 色・余白・文字・高さ（28 / 24 / 32px）を CSS の変数にまとめ、ライトとダークを一か所で定義する。文字と枠の濃さは WCAG AA を満たす |

### 17.2 データを守るための決まり

- **XML に構文エラーがある間は、キャンバス・ツリー・インスペクタからの編集を断る。** 書きかけの XML が上書きされて消えないようにするため。断ったことは通知で知らせる。
- **何も変わらない編集は履歴に残さない。** 元に戻すを押しても何も起きない、という状態を作らないため。
- **保存する画像は、ディスク上の状態との差分で決める。** 削除→元に戻す、読み込み→元に戻すなどで画像が失われないようにするため。保存を始めた時点の内容を控えておき、保存中に加えた編集は未保存のまま残す。
- **保存・反映・開くは同時に一つだけ。** 実行中の操作は待ってもらう。
- **子要素の順序と個数を検証する。** customUI（commands → ribbon → backstage → contextMenus）、ribbon（officeMenu → qat → tabs → contextualTabs）、group の dialogBoxLauncher は最後に一つ、splitButton はボタン一つとメニュー一つ、など。挿入・移動・複製・貼り付けも、この規則で置ける位置に収める。
- **id と Sub 名には日本語などの Unicode の文字を使える。**
- **レシピの VBA には、モジュールの先頭に置く宣言を使わない。** 既存のモジュールの末尾に足すとコンパイルエラーになるため。状態は Static 変数を持つ Function で保つ。ThisWorkbook の既存のイベントと名前が重なるときは足さずに、足すべき行を示す。

### 17.3 ファイルとバックアップ

- 保存は一時ファイルに書いてから `File.Replace` で置き換える（置き換えられない環境ではコピーで上書きする。NAS・Samba・WebDAV などで `File.Replace` が IOException になったときもコピーに切り替えるが、共有違反・ロック違反は切り替えずにそのまま失敗として返す）。読み取り専用・暗号化（パスワード付き）・ほかで開かれているファイルは、理由を示して断る。
- バックアップのフォルダは `<ファイル名>_<フルパスの SHA256 の先頭 8 桁>` とし、元のフルパスを `source.txt` に書く。別のフォルダにある同じ名前のブックのバックアップが混ざらないようにするため。中身が最新のバックアップと同じなら新しく作らない。
- **バックアップから復元（ファイル メニュー）。** 一覧（新しい順）から選んで戻す。戻す前に今のファイルもバックアップする。そのブックのバックアップ以外は受け付けず、Excel でブックが開かれているときは断る。以前の形式（`<ファイル名>` だけのフォルダ）のバックアップは一覧に出ない。
- 設定とレシピのファイルが壊れていたら `.bak` に退避して既定に戻す。読めないときは上書きしない。

### 17.4 Excel 連携

- OneDrive / SharePoint 上のブックは、Excel が返す URL を同期フォルダのローカルのパスに直して照合する。
- Excel が忙しくて呼び出しを断ったときは、100ms 間隔で 10 秒までやり直し、それでもだめなら「Excel が応答しない」と知らせる。
- アドインの読み直しは、Installed の切り替えではなく、閉じて開き直す。
- 反映のやり直しでは、バックアップは最初の一回だけ取り、書き込みだけをやり直す。

### 17.5 更新

- GitHub が確認先のときは、「新しい版あり」と知らせる前に照合値ファイルを取得する。取れなければ（リリースが下書きのうちなど）最新として扱う。
- 確認は 30 秒、ダウンロードはデータが 60 秒届かなければ打ち切る。
- 開発用のビルドでは、自分自身の入れ替えをしない。

### 17.6 Windows 実機で確かめていないこと

WebView2 での表示と操作、Excel 連携（COM の呼び出しのやり直し、OneDrive のパスの変換、アドインの読み直し）、VBE へのコード挿入、レシピの VBA と `modRibbonCore` の 32bit / 64bit での動作、OS のクリップボードと IME の実際の入力、バックアップからの復元は、Linux 上のビルドとテスト、ブラウザでの確認までしか行っていない。

### 17.7 Excel の組み込みアイコン（imageMso）の取り込み

Office のアイコンは Microsoft の著作物で、Sash（MIT）には同梱できない。そこで**利用者の PC の Excel から一度だけ取り出し、その PC の中（`%AppData%\Sash\cache\imageMso`）にだけ保存する**。取り込んだ後は、Excel を起動しなくても（Excel がなくなっても）キャッシュから表示する。

| 項目 | 内容 |
| --- | --- |
| 取り出し方 | `CommandBars.GetImageMso(名前, 大きさ, 大きさ)` の戻り値（IPictureDisp）を、次の順に PNG にする。① QueryInterface で `IPicture` を取り、`SaveAsFile` で HGLOBAL のストリームに BMP を書かせて読む。② `IPersistStream.Save` で同じように書かせる（先頭の `lt\0\0` と長さを飛ばす）。③ `IPicture` を取れなかったときだけ、`Handle`（HBITMAP）を `GetDIBits` で読む（大きさが合うときだけ）。GDI のハンドルはプロセスごとのもので、Excel は別のプロセスで動くのがふつう。HBITMAP を先に試すと、別のプロセスのハンドルの値がたまたまこのプロセスの 32x32 のビットマップを指していたときに、違う画像をキャッシュに書いてしまうため、最後に回す。1 件の BMP が壊れていても（`BmpDecoder` は壊れた入力では `FormatException` だけを出す）その名前だけを「画像にできなかった」にし、まとまり全体は止めない。BMP は Sash.Core の `BmpDecoder`（1/4/8/16/24/32bpp、BI_RGB / BI_BITFIELDS、上下どちらの並びも）で読み、アルファがすべて 0 なら不透明、そうでなければ乗算済みをストレートに戻す |
| 一括の取り込み | 初めての起動で、Excel があり未取り込みなら、ホーム画面を出した後に裏で始める（編集は止めない）。カタログ（`excelControls.json`）から画像を持ちうる名前（タブ・タブの組・右クリックメニューを除く）を送り、**32px だけ**を取り出す。キャンバスもアイコンの一覧も 32px の画像を縮めて描く（小さいボタンも 32px を 16px に縮める）ので、16px は使われないため取らない（`sizes` で指定すれば取れる）。利用者の Excel を何千回も呼ばないよう、**取り込み専用の見えない Excel を起動し、終わったら閉じる**。50 件ずつに分けて COM のスレッドに積み、その合間に反映や VBA の操作が割り込めるようにする |
| 取り込み専用の Excel の片付け | 取り込みの最中に利用者がブックをダブルクリックすると、Windows がこの見えない Excel に開かせることがある。まとまりごとに `Workbooks.Count` を見て、ブックがあればその Excel は見えるようにして（`Visible`・`UserControl`・`DisplayAlerts` を戻して）利用者に引き渡し（Quit しない）、新しい見えない Excel で続ける。起動の途中で失敗しても（起動直後の設定で例外など）後片付けは必ず呼び、起動しかけた Excel を残さない。アプリを閉じるときは、COM のスレッドに片付けを必ず積んでから閉じ（起動の途中でも後ろに積まれて走る）、終了処理に入った後は新しい Excel を起動しない |
| 進み具合 | 右下の通知に「Excel のアイコンを取り込んでいます… 1,234 / 2,081」と「中止」を出す。書き換えは 500ms に 1 回までにし、書き換えるのは文言だけ（ボタンは作り直さない。押している最中にボタンが入れ替わってクリックにならない・フォーカスや読み上げがやり直しになる、を防ぐため）。× で閉じたら出し直さない。終わったら完了を知らせ、表示中のアイコンを描き直す。中止したら次の起動では自動で始めない（設定から始められる）。取り込み直しを中止すると前の manifest が残って状態は `done` になるので、ホストは `cancelled: true` を添え、UI は中止を先に見て「中止しました」と出す |
| 失敗の記録 | 失敗（Excel を起動できない、100 件続けて画像にできず打ち切った、など）は `prefetch-failed.json`（Excel の版・日時・理由）に残す。次の起動でも、同じ版の Excel なら状態を `failed` として返し、UI は中止したときと同じく自動では始めない（起動のたびに見えない Excel を起動して失敗し、エラーを出し続けないため）。Excel の版が変わっていれば（どちらの版も分かっていて違うとき）記録は当てはまらないとして、もう一度自動で試す。設定画面からの手動の取り込みはいつでもでき、成功したら記録を消す |
| キャッシュ | `<大きさ>\<名前>.png`。0 バイトや PNG の署名で始まらないファイルはキャッシュにないものとして扱い、消して取り直させる（残すと「取り込み済み」とみなされ、二度と取り直されないため）。Excel に存在しない名前は大きさごとの `missing.json` に記録し、Excel がない PC でも「存在しない imageMso」の警告を正しく出す。取り込みを終えたら `manifest.json`（Excel の版、大きさ、件数、日時）を書き、次の起動からは取り込み済みとして Excel を起動しない |
| 取り込み直し | 自動ではしない。Excel の版（`EXCEL.EXE` のファイルの版から Excel を起動せずに読む）が manifest と違えば、設定画面で取り込み直しを勧める。manifest の版（取り込んだ Excel の `Version` と `Build`）とファイルの版は形が違いうるので、どちらも「メジャー.マイナー.ビルド」にそろえて記録し、比べる（取り込み直した後も「Excel が更新されています」が出続けないように） |
| 1 件ずつの取得 | `excel.imageMso` はまずキャッシュを（COM のスレッドの外で）引き、ないものだけを起動中の Excel（なければ見えない Excel）から取る。存在しない名前は null、一時的に取れなかった名前は結果に含めない（UI は 60 秒後に取り直す）。Excel がない PC ではキャッシュだけを引く。**一括の取り込みの最中はキャッシュだけで答え**、ないものは結果に含めない（要求のたびに見えない Excel を起動・終了すると、取り込みと COM のスレッドを取り合って両方が遅くなるため）。取り込みが終わったら UI がすべて取り直す |
| 打ち切り | 100 件続けて 1 件も画像にできなければ、変換の方法がその PC で動いていないとみなして打ち切り、失敗として理由を見せる |
| 記録 | 取り出しの失敗は理由（例外の型と HRESULT）ごとに最初の 1 回だけ `%AppData%\Sash\logs\app.log` に書く。どの方法で取れたか（BMP の形式）も最初の 1 回だけ書く |
| 画面 | 設定の「アイコン」に状態（取り込み済み・件数・Excel の版・日付）と「取り込む / 取り込み直す」「中止」、アイコンはこの PC の Excel から取り出しこの PC にだけ保存すること（Microsoft の著作物で同梱しないこと）を示す。imageMso のカタログでは、アイコンを出せないときに理由と「アイコンを取り込む」を出す |

ホストとの要求は `icons.prefetchStatus`・`icons.prefetchStart { names, sizes?, force? }`・`icons.prefetchCancel`、進み具合はホストからの知らせ `{ event: 'iconPrefetch', state, done, total, … }`（形は `ui/src/bridge.ts` の `IconPrefetchStatus`）。状態は `none`（未取り込み・中止）・`running`・`done`・`failed`（今回か、同じ版の Excel での前回の失敗）・`unavailable`（Excel がなくキャッシュもない）。直前の取り込みが中止で終わったときは `cancelled: true` を添える。

**Windows 実機で確かめていないこと：** 別のプロセスの Excel から `IPicture` / `IPersistStream` を取れるか（プロキシの有無）、`SaveAsFile` が 32bpp のアルファを保った BMP を書くか、取り込み専用の Excel の起動と終了（アプリを閉じたときの片付け、ブックを開かれたときの引き渡しを含む）、所要時間は、Linux 上のビルドと BMP の読み込みなどの単体テスト、ブラウザでの確認までしか行っていない。

## 18. 配る前の確かめと幅の確認（2026-11-23 追加）

作ったリボンを配る前に「狭い画面でどう見えるか」「押して動くか」「直し忘れがないか」を、Sash の中で確かめられるようにした。
この章は三つの持ち場で作った。§18.1〜§18.8 はホストと画面の外枠（メニュー・ダイアログ・Excel 連携）、§18.9 はキャンバスの幅のプレビュー、§18.10 はツリー・インスペクタ・Lint の分。

### 18.1 Excel のウィンドウの幅を合わせる（`excel.setWindowWidth`）

| 項目 | 内容 |
| --- | --- |
| 要求 | `excel.setWindowWidth { width, scale, path? }`。width は拡大率をかける前の画面の幅（物理 px。例：1920）、scale は Windows の拡大率（1.5 = 150%。10 以上なら % とみなすので 150 でもよい。プレビューが % で持つため）。応答は `{ points, logicalWidth, workAreaWidth, workbook, actualWidth?, expectedWidth? }`（前の三つは論理 px、後の二つは物理 px）。path が空（サンプル）なら「指定なし」とみなす |
| 換算 | アプリから見える幅（論理 px、96 dpi を 1 倍とする単位）は width / scale。`Application.Width` はポイント（1/72 インチ）で、論理 px は 1/96 インチなので、**拡大率に関係なく 論理 px × 0.75**。拡大率は「1 インチを何物理 px で描くか」を変えるだけで、論理 px とポイントの比は変えないため（例：1920 幅・150% → 1280 論理 px → 960pt） |
| 対象 | path のブックを開いている Excel。普通のブックはそのウィンドウを前にしてから合わせる（Excel 2013 以降はブックごとにウィンドウがあり、`Application.Width` はアクティブなウィンドウに効くため）。アドイン（xlam）はウィンドウを持たないので、その Excel のいま前にあるウィンドウを使う。path がない・開かれていなければ、起動中の最初の Excel |
| 手順 | まず収まるかを確かめ（下の「断るとき」）、収まるときだけブックのウィンドウを前に出す（断るときに利用者のアクティブなブックを変えないため。確かめるモニターは、Excel 2013 以降の `Window.Hwnd` で取ったそのブックのウィンドウのもの）。`WindowState = xlNormal（-4143）` にしてから `Width` を入れる（最大化のままでは効かない）。入れた後に `GetWindowRect` で幅を測り、期待の幅（論理 px × モニターの dpi / 96）と 2px より大きくずれていたら、差の分だけ 1 回だけ `Width` を直す。それでも合わなければ、測った幅を応答（`actualWidth`・`expectedWidth`、物理 px）に入れ、UI は「ただし実際の幅は N px でした」と添える（**要確認**：実機で `Width` と枠の分のずれ方を確かめていない）。最後に、ウィンドウが作業領域からはみ出したら、はみ出した分だけ `Left` を動かす |
| 断るとき | 論理 px にした幅が、Excel のあるモニターの作業領域より広いとき（Windows がウィンドウを縮めてしまい、測りたい幅にならないため）。作業領域は `MonitorFromWindow` と `GetMonitorInfo` の `rcWork`（物理 px）を、`GetDpiForMonitor`（MDT_EFFECTIVE_DPI）で論理 px に直して比べる。座標を物理 px で受け取るよう、呼び出しの間だけ COM のスレッドを Per-Monitor V2 にする（Sash のプロセスは PerMonitorV2）。0.5px までの差は収まるものとみなす。幅は 320〜10000、拡大率は 50%〜500% の外なら断る |
| 計算の置き場 | 換算と判定・ずれの直し方（`ExpectedPhysicalWidth`・`CorrectionPoints`）は `Sash.Core/Excel/ExcelWindowSizing.cs`（COM に触らないので単体テストする）、COM の呼び出しは `Sash.Excel/ExcelService.SetWindowWidthAsync` |
| メニュー | 表示 メニューの「Excel をプレビューの幅にする」（プレビューの幅が「自由」のときは無効）。キャンバスの見出しの「表示 ▾」にも同じ名前で置く。どちらも `ui/src/views/excelWidth.ts` の `fitExcelToPreview` を呼ぶ |

`Application.Width` の値には、ウィンドウの枠の幅も入る。リボンが使える幅は、それより枠と左右の余白の分だけ狭い。

### 18.2 配布前チェック（ツール メニュー・コマンドパレット）

配る前に見ておくべきことを分類ごとに件数つきで並べ、押すとその場所へ移る（要素を選ぶ、またはコールバック・アイコンの一覧を開く）。集計は `ui/src/distributionCheck.ts`（純粋な関数）、画面は `ui/src/dialogs/distributionDialog.ts`。開いている間に問題・VBA の照合・キャンバスの見積もりが変わったら描き直す（直しながら見られるように）。

| 分類 | 重さ | 中身 |
| --- | --- | --- |
| VBA にない・引数の合わないコールバック（照合できていないとき） | 要確認（未確認） | コールバックがあるのに VBA と照合できていなければ、この分類を一番上に出し、件数の代わりに「未確認 N」（N はコールバック名の数）と出す |
| エラーと警告 | 要確認 | Lint のエラーと警告。キーヒント・ラベルの長さ・VBA との照合の警告は、それぞれの分類に回して二度数えない |
| VBA にない・引数の合わないコールバック | 要確認 | 照合の結果が「未実装」「引数が不一致」のもの。**VBA と照合していなければ数えず、理由を出す** |
| チェックする画面の幅で畳まれる・収まらないグループ | 収まらない＝要確認、畳まれる・畳んだときのアイコンがない＝見直し | キャンバスが測った結果（§18.9）。まだ測っていなければ「キャンバスで幅を選ぶと確認できます」。畳んだときのアイコンがないものは、グループごとではなく「N グループで畳まれたときのアイコンが未設定です」の 1 行にまとめる（押すと最初のグループを選ぶ。汎用のアイコンで出るだけなので、並べると大事な項目が埋もれるため） |
| キーヒントの重複 | 要確認 | Lint の keytip の問題（重複・4 文字以上） |
| 長いラベル | 見直し | Lint のラベルの長さの警告（§18.10） |
| 使っていない画像 | 見直し | ファイルに入っているが、どの image 属性からも使われていない画像。VBA の getImage / loadImage で使っていればそのままでよいと添える |
| ヒント（screentip）のないボタン | 見直し | 自作（id / idQ）の button・toggleButton・menu・dynamicMenu・gallery で、リボンのグループに（box・buttonGroup・splitButton を通して）直接置いたもの。組み込み（idMso）は Excel が自分のヒントを持つので、メニューの中の項目はヒントが出ないので除く |
| アイコンのないボタン | 見直し | 同じ範囲で image / imageMso / getImage がなく、showImage="false" でもないもの |
| VBA で決まるラベル・文言 | 参考 | getLabel・getScreentip・getSupertip・getDescription・getKeytip・getText・getTitle・getHelperText・getAltText・getItemLabel。キャンバスには中身を出せないので、Excel で確かめてもらう |

見出しは、コールバックがあるのに VBA と照合できていなければ「VBA と照合できていません（コールバック N 件は未確認）」（ほかに要確認があれば「。ほかに M 件の確認が必要です」を続ける）。照合できていて「要確認」の件数が 0 なら「配ってよい状態です」、そうでなければ「N 件の確認が必要です」。照合できていないのに「配ってよい」と言うと、配った先で「マクロが見つかりません」になりうるため。「見直すとよいもの N 件」を添える。分類は 照合できていないコールバック → 要確認を含むもの → 見直し → 参考 → 0 件 の順に並べる。

### 18.3 コントロール一覧の書き出し（ファイル メニュー）

- 「コントロール一覧」▸「CSV ファイルに書き出す…」と「クリップボードにコピー」。列は タブ・グループ・種類・ラベル・id・マクロ・ヒント・キーヒント・画像。
- 行にするのはコントロール（スキーマの isControl）だけ。box・buttonGroup・区切り線・dialogBoxLauncher・dropDown などの item（選択肢）は行にしない（中のコントロールは出す）。右クリックメニューはタブの列に「右クリック：<idMso>」、クイックアクセス・Backstage もその名前を書く。
- VBA で決まる値は「（VBA：<Sub 名>）」。マクロの列には表示用（getLabel・getImage など）以外のコールバックを並べ、onAction は名前だけ、ほかは「名前 (属性)」。画像は image の Id、imageMso は「imageMso:<名前>」。
- **CSV は BOM 付きの UTF-8・CRLF。** BOM がないと、日本語版の Excel はダブルクリックで開いたときに Shift_JIS として読んで文字化けするため。値は , " 改行・前後の空白を含むときだけ "" で囲む（RFC 4180）。書き込みは `file.exportText`（ホストは BOM なしの UTF-8 で書くので、UI が先頭に U+FEFF を付ける）。
- 数式に見える値（= + - @ で始まるもの）に ' は付けない。自分のリボンの定義を書き出すもので、付けると値そのものが変わってしまうため。
- クリップボードには TSV（BOM なし）で入れ、Excel のセルにそのまま貼り付けられるようにする。値の中のタブと改行は空白にする（貼り付けで表が崩れないように）。
- 純粋な処理は `ui/src/controlList.ts`。

### 18.4 試しに押す（マクロを Excel で試す）

- キャンバス・ツリーの右クリックメニュー、ツール メニュー、コマンドパレットの「マクロを Excel で試す」。選んだコントロールの onAction を、開いているブックで `Application.Run "'<ブック名>'!<モジュール.>Sub"` で実行する（ブック名を付けるのは、同じ名前の Sub がほかのブックやアドインにあっても、開いているブックのものを実行するため）。要求は `excel.runMacro { path, macro, controlId?, argument? }`。
- **呼べる形**：引数のない Sub はそのまま呼ぶ。引数が 1 つで、型が IRibbonControl（Office. 付きも）・Object・Variant（型なしを含む）の Sub は、**control に Nothing を渡して**呼ぶ（`Application.Run name, New DispatchWrapper(Nothing)` に当たる。C# では `new DispatchWrapper(null)`。ただの null は VT_EMPTY＝引数の省略になり、「マクロを実行できません」になるため）。それ以外（引数が 2 つ以上・配列・ParamArray・String などほかの型）は理由を添えて断る（toggleButton・checkBox の onAction は引数が 2 つなので断る）。代わりのオブジェクトを差し込むコードをブックに足すことはしない（利用者のブックを書き換えないため）。**要確認**：実機の Excel で Nothing がこの形で渡るかは確かめていない。
- 押す前の知らせ：control に Nothing を渡すときは、確認のダイアログで「control 引数には Nothing を渡します。Sub の中で control.Id などを使うと実行時エラーになります」と知らせ、「実行する / キャンセル」を選んでもらう。
- 確かめ方：UI は照合済みの VBA（§8.2）の宣言から、読めていなければ XML のコールバックの形（`callbackSignature`）から呼び方を決め、呼べない形なら押す前に断る（`ui/src/vbaReveal.ts` の `checkRunnable`・`macroArgument`）。右クリックメニューでは、無効のときに項目の下に理由を出す（無効の項目にはツールチップが出ない環境があるため）。ホストは、VBA を読めれば（信頼の設定がオン）宣言から決め直し、読めなければ UI の `argument`（`none` / `control`）に従う。宣言の解析と呼び方の判定は `Sash.Core/Excel/VbaProcedureLookup.cs`（`FindParameters`：行継続 " _"・既定値の中の入れ子の括弧 `Array(1, 2)`・文字列の中の括弧に対応。`SplitParameters`・`Classify`）。
- 名前の確かめ：VBA を読めないときも、モジュール名と Sub 名が VBA の識別子（文字で始まり、文字・数字・_ だけ、255 文字まで。`VbaProcedureLookup.IsVbaIdentifier`）であることを必ず確かめる（Application.Run に渡す名前は Sash が組み立てるので、記号の混ざった名前は通さない）。
- マクロが MsgBox などを出しても Sash の後ろに隠れないよう、実行の前に Excel のウィンドウを前に出す。
- **実行中**：マクロが MsgBox やエラーのダイアログで止まると、閉じるまで COM のスレッドがふさがる。そこで UI は実行中ずっと「Excel でマクロを実行中です（Excel 側でメッセージやエラーを閉じると戻ります）」の通知を出したままにし（終わったら結果に差し替える）、ホストは `ExcelService` に実行中の印（`IsMacroRunning`。Run の前に立て、終わったら下ろす）を持つ。実行中は、Excel を使うほかの要求（`excel.apply`・`vba.read`・`vba.insert`・`vba.replaceLine`・`vba.reveal`・`excel.setWindowWidth`・`icons.prefetchStart`）を、COM のスレッドに並べずに入り口（`MessageRouter`）ですぐに同じ理由で断る。`excel.imageMso` は Excel に取りに行かずキャッシュだけで答える。二つ目のマクロも断る。`excel.labels` は並べる（起動時に一度だけ読むもので、断ると表示名がその間ずっと取れなくなるため）。

### 18.5 コールバック一覧から VBE の該当の Sub へ移る

- 要求は `vba.reveal { path, module, procedure }`。VBE を表示し（`VBE.MainWindow.Visible = True`）、`CodePane.Show` の後に宣言の行をまるごと `SetSelection(行, 1, 行, 行の長さ + 1)` で選び、少し上の行から表示する。行は `CodeModule.ProcBodyLine(name, vbext_pk_Proc)` で取る（`ProcStartLine` は Sub の前のコメント行から数えるため、宣言そのものの行にならない）。VBE のウィンドウを前に出す。
- どのモジュールにあるかは、照合のときに読んだ VBA から UI が決める（`ui/src/vbaReveal.ts` の `revealInVbe(name)`）。照合できていない・VBA にないときは理由を知らせる。
- 入口は、コールバック一覧の各行のボタン（下部パネル）、要素の右クリックメニューの「VBE で <名前> を表示」、コマンド「選択中のコントロールのコールバックを VBE で表示」。

### 18.6 操作の履歴（編集 メニュー）

- 「操作の履歴…」で、元に戻す・やり直しの一覧を古い順に並べる。先頭は「記録の始まり」（開いたとき、または上限の 200 件でそれより前が消えたところ）。押すと、その操作の直後の状態へまとめて移る。移った後もダイアログは残し、ダイアログの中で Ctrl+Z（元に戻す）・Ctrl+Y / Ctrl+Shift+Z（やり直し）を押しても位置が動く（モーダルの間はアプリのショートカットが届かないので、ダイアログが自分で受ける）。やり直せる（取り消した）操作は薄く・取り消し線で示す。
- ストアに `history(): { labels, index }`（labels は古い順の操作の名前、index は適用済みの操作の数）と `goTo(index)` を足した。goTo は元に戻す・やり直しを続けて行うのと同じ結果になるが、途中で XML を読み直さず、通知は最後の 1 回だけにする（何十件も戻るときに描き直しを繰り返さないため）。範囲の外は端に丸める。

### 18.7 表示 メニューの幅のプレビューと、左右のペインを畳む

- 表示 メニューに「画面の幅」▸ 自由（キャンバスの幅）/ 1280 / 1366 / 1920 / 2560、「拡大率」▸ 100% / 125% / 150%、「表示のしかた」▸ 全体を表示 / 実寸、「キーヒントを表示」、「Excel をプレビューの幅にする」を置く（キャンバスの見出しと同じ言葉にそろえた）。コマンドパレットからも同じものを呼べる。設定の持ち主はキャンバス（`views/ribbonPreview.ts`）で、メニュー（`shell/previewCommands.ts`）はキャンバスの `setPreviewWidth` / `setPreviewScale` / `setFitMode` / `toggleKeytips` を直接呼ぶ（先に設定だけを書き換えてから知らせると、キャンバスが「変わっていない」とみなして一時的に広げたグループを畳み直さず、描き直しも二度になるため）。window の `sash:preview` はほかから切り替えるための入り口として残す。
- 「左右のペインを一時的に畳む」：パレット・ツリー（左）とインスペクタ（右）を畳み、「元に戻す」付きの通知を出す。大きさは保存しない（次の起動では元に戻る）。元に戻すときは、その間に利用者が自分で開き直したペインはそのままにする。キャンバスからは window の `sash:collapseSidePanes` で頼まれる。

### 18.8 幅の試験用リボン（レシピ）と、畳まれる順番の測り方

レシピ「幅の試験用リボン」は、Excel が狭い画面でグループを畳む順番を実機で測るためのタブ（`tabWidthTest`）を入れる。グループは 7 つで、すべてにグループの画像（畳んだときに出る）を付ける。

| グループ | 中身 |
| --- | --- |
| 大きいボタン | 大きいボタン 4 つ（ラベル 4・6・8・10 文字） |
| 小さいボタン（autoScale） | 小さいボタン 6 つ（4・6・8・10・4・6 文字） |
| 空白入り | 大きいボタン 2 つ（「月次 集計」「シートを 新しく 作る」）、小さいボタン 1 つ。空白で 2 行に分かれる位置を見る |
| 入力 | dropDown（項目 3 つ）、editBox（sizeString="00000"）、comboBox |
| 混在（autoScale） | 大きいボタン、toggleButton、checkBox、区切り線、小さいボタン 2 つ |
| アイコンだけ | showLabel="false" のボタン 3 つ |
| 自動調整（autoScale） | 大きいボタン 2 つ（8・10 文字）と小さいボタン 3 つ |

ボタンはすべて共通の `Ribbon_WidthTest_onAction`（押した id を MsgBox で出す）、toggleButton と checkBox は `Ribbon_WidthTest_onToggle` を呼ぶ。10 文字の大きいボタンはわざと長くしてあり、ラベルの長さの警告が出る。

**測り方**

1. 新しいブック（xlsm）に「幅の試験用リボン」を入れ、VBA も入れて保存し、Excel へ反映する。
2. 表示 メニューの「リボンの幅」と「拡大率」を、1280 / 1366 / 1536 / 1920 のそれぞれに（拡大率は実機の設定に合わせて）切り替え、「Excel のウィンドウをプレビューの幅に合わせる」で Excel のウィンドウを同じ幅にする。1536 は選択肢にないので、キャンバスの「カスタム…」で入れる。
3. 幅ごとに、Excel のリボン（「幅の試験」タブ）とキャンバスのスクリーンショットを撮る。ファイル名は `<幅>_<拡大率>_excel.png` / `<幅>_<拡大率>_sash.png` とする。
4. 各グループが「大きいまま / 小さくなる / ラベルが消える / 畳まれる」のどれかを表にし、畳まれた順番を記録する。キャンバスの見積もり（`views/ribbonFit.ts`）と違うところを、見積もりの係数を直す材料にする。
5. Excel の版・ビルド、Windows の拡大率、モニターの解像度、フォントの設定を一緒に記録する。

この測定はまだ行っていない（Windows 実機が必要）。

### 18.9 キャンバスの幅のプレビュー（キャンバスの持ち場）

キャンバスの幅は既定のペイン（左 248px・右 300px）で、1920 幅の画面でも 1370px（Excel のリボンの約 7 割）しかない。そのため、狭い画面でグループが畳まれることに配る前に気づけるよう、リボンを決まった幅で描けるようにした。

| 項目 | 内容 |
| --- | --- |
| 見出しは 1 行 | 見出しは 1 行に収める：表示の切り替え［リボン / Backstage / コンテキストメニュー］・画面の幅・拡大率・［全体を表示 / 実寸］・状態の文字・「表示 ▾」・「?」（キー操作の説明はツールチップ）。2 段・3 段にすると、既定の高さ（260px）のキャンバスでリボンが見出しの下に隠れるため。1 行なので上に貼り付けたまま（sticky）にする。見出しが狭い（コンテナークエリで 820px 以下。1280・1366 幅の既定のペイン）ときは「画面の幅」「拡大率」の文字を隠し（選択肢の aria-label と title は残す）、「コンテキストメニュー」を「右クリック」と短く出し、間を詰める。状態の文字は残りの幅に入るだけ出して「…」で切り、全文（畳まれる・収まらないグループの名前と「目安」の断りを含む）はツールチップに出す。毎回は使わない切り替え（2つの幅を比べる・キーヒントを表示・未設定も表示・VBA で変わる表示を試す…・チェックする画面の幅…・Excel をプレビューの幅にする）は「表示 ▾」のメニューにまとめた。1280・1366・1920 幅（既定のペイン）で 1 行に収まることをブラウザで確かめた |
| 画面の幅・拡大率 | キャンバスの見出しに「画面の幅［自由 / 1280 / 1366 / 1920 / 2560 / カスタム…］」「拡大率［100 / 125 / 150%］」。**Excel から見た幅 = 画面の幅 ÷ 拡大率**（例：1920・125% → 1536px。画面に出す言葉は「Excel から見た幅」、仕様書とコードでは「実効の幅」とも書く）。「自由」は従来どおりキャンバスの幅いっぱいに描く（既定）。選んだ値は localStorage（`sash.preview`）に覚え、使えない環境ではその画面の間だけ覚える |
| 表示のしかた | 「全体を表示」（幅を選んだときの既定。枠に収まるよう縮小）と「実寸」（実物の大きさで横スクロール）。見出しの状態の文字に「64% で表示・Excel から見た幅 1536px」と出す（狭いと「…」で切れるので、縮小率を先に書く）。縮小が 50% を下回ったら、状態の文字の横に小さなリンク「ペインを畳む」を出す（window に `sash:collapseSidePanes` を投げ、外枠が畳む。実寸にするには隣の［実寸］を押す） |
| 縮小の方法 | CSS の `zoom`（transform ではない）。transform だと、ポップアップ（position:fixed）の基準が縮小した枠に変わるため。Chromium（128 以降の標準の zoom）では、`getBoundingClientRect` は縮小後の画面上の値、`offsetWidth`・`scrollHeight`・`clientHeight`・`scrollTop` は縮小前の値、zoom の中の fixed の `top`・`left` は縮小率を掛けて置かれる。そこでポップアップの置き場所（`placePopups`）とポップアップの中のスクロール（`revealInPopup`）は画面上の値で計算し、書き込むときに `currentCSSZoom` で割る。ドロップ位置の線は縮小しない枠（`#canvas`）に置くので、画面上の値のまま使える。選択・ドラッグ＆ドロップ・F2・右クリック・ポップアップの位置は、縮小 57% と 100% でブラウザで確かめた |
| 枠と目盛り | 実効の幅の枠の上に、1280 / 1366 / 1536（1920 の 125%）/ 1920 の目盛り。目盛りはリボンの左端をウィンドウの左端とみなして測る。枠の右端の `RIBBON_RESERVED_PX`（40px：本体の枠と余白、表示オプションのボタン）はグループを置けない幅とする（**目安**）。はみ出したグループは隠さずに枠の外に描き、赤の斜線で示す（隠すと編集できなくなるため） |
| タブの「＋」 | タブだけを横スクロールの欄に入れ、「＋」は欄の外の右端に置く（1280 幅でタブがあふれても隠れないように） |
| はみ出しの判定 | 自作のタブのグループを、状態ごと（書いたとおり・小さく・ラベルなし・畳んだ形）に描いて DOM で幅を測る（縮小の外で測り、すぐ外す。XML・言語・試し表示が同じなら控えを使う）。組み込みのグループの幅は再現していないので、組み込みタブでは見積もらず、状態の文字に「組み込みグループの幅は再現していません」と出す（ツールチップで「表示 ▾」の［Excel をプレビューの幅にする］を勧める）。visible="false" と試し表示で隠したグループは数えない |
| 畳まれ方の模擬（目安） | `views/ribbonFit.ts` の `simulateFit`。**右のグループから**、まず autoScale="true" のグループを large → small（大きいボタンを小さくして 3 段に積む）→ ラベルなし の順に一段ずつ縮め（全部を small にしてからラベルを消す）、それでも入らなければ右から一つずつ「グループのアイコン（image / imageMso、なければ汎用のアイコン）＋ラベル＋▼」の大きいボタンに畳む。畳んでも入らないものは「収まらない」。幅が減らない段は飛ばす。Excel の実際の縮め方は公開されておらず、これは **実機で確かめていない仮定**。画面には「目安（実機の Excel と異なる場合があります）」と添える |
| 畳んだグループの編集 | 選ぶと Excel と同じように中身をポップアップで開き、その中で選択・編集・ドロップができる。ダブルクリックか「展開して編集」で、その場に一時的に広げる（「畳む」かダブルクリックで戻す。幅や拡大率を変えたら畳み直す） |
| チェックする画面の幅 | 既定は 1920 と 1366（localStorage の `sash.fit.checkWidths`）。見出しの「表示 ▾」の「チェックする画面の幅…」で変える。`getCheckWidths()` / `setCheckWidths()`（変えると `sash:fitsettings` を投げる）。拡大率は見出しで選んだものを使う |
| 見積もりの受け渡し | `getFitReport(): { width, scale, effective, checkedWidths, overflowing: { path, id, label, tab, collapsedAt?, clippedAt?, noIcon }[] }`。チェックする画面の幅とプレビューの幅で、畳まれる（collapsedAt：畳まれる幅のうち最も広いもの）・収まらない（clippedAt）グループ。中身が変わったときだけ window に `sash:fitreport`（detail は同じもの）を投げる。`fitProblems()` で問題の一覧の形（「1366 幅で［モード］が畳まれます（目安）」＝参考、「1366 幅で［モード］が収まりません（目安）」＝警告、「N グループで畳まれたときのアイコンが未設定です」＝参考で 1 行にまとめ、押すと最初のグループ）にし、下部パネルの問題の一覧に足す（クリックでグループを選ぶ）。配布前の確認（§18.2）も同じものを使う |
| 2つの幅を比べる | 編集する枠の下に、別の幅（既定 1366）で描いた枠を読み取り専用（`inert`、data-path を外す）で並べる。両方を広いほうに合わせた同じ縮小率で描く |
| Excel をプレビューの幅にする | 「表示 ▾」の項目。`excel.setWindowWidth { width, scale, path }`（§18.1）。Excel がないとき・幅が「自由」のときは理由を添えて無効にする |
| ヒントの試し表示 | コントロールにマウスを乗せて 0.5 秒待つと、Excel に近いヒント（太字の見出し＝screentip、なければラベル、本文＝supertip、下に id）を出す。getScreentip / getSupertip は「VBA で決まります」。コントロールの title（id）は二重に出ないよう外した |
| キーヒントを表示 | タブ・コントロール・畳んだグループにキーヒントを重ねる。出すのは書いた keytip（重なりは赤）と getKeytip の「VBA」だけ。keytip を書いていないものの灰色の「自動」（Excel が自動で割り当てます）は、「表示 ▾」の「未設定も表示」（既定はオフ、`sash.preview` の `keytipsAll`）のときだけ出す（全部に付くと、書いたものが埋もれるため）。タブは組み込みタブ（ホーム H・挿入 N・ページ レイアウト P・数式 M・データ A・校閲 R・表示 W・開発 L・ヘルプ Y2・ファイル F。**実機で確かめていない**）と、コントロールは表示中のタブの中（メニューの中身は除く）で、大文字小文字を区別せずに重なりを赤で示す |
| VBA で変わる表示を試す | 「表示 ▾」の「VBA で変わる表示を試す…」で開くメニューに、getVisible / getEnabled / getLabel を持つ要素を並べ、表示する・有効・ラベルの例を仮に決めて見え方を試す（隠したものは場所も取らない）。保存せず、ファイルを開き直すと消える。インスペクタの「キャンバスで試す」は window に `sash:dynamicSim`（detail は `{ path }`）を投げ、キャンバスはその要素の行を目立たせてメニューを開く |
| 表示 メニューから | 外枠の表示 メニューは canvas.ts の `setPreviewWidth` / `setPreviewScale` / `setFitMode` / `toggleKeytips` を直接呼ぶ（§18.7）。`getPreviewState` も export する。`sash:preview`（detail は `{ width?, scale?, mode?, keytips? }`）も受ける |
| タブの欄 | 描き直してもタブの欄の横スクロールの位置を保つ。表示するタブが変わったときだけ、そのタブを欄の中で見える位置へ送る（欄の中だけを動かし、キャンバスの枠は動かさない）。ファイルを開き直したら先頭に戻す。自作のタブ（insertAfterMso などがないもの）は書いた順に並べる（以前は逆順になっていた） |
| 見積もりの控え | 測った幅の控えの鍵に、言語・試し表示に加えて Excel の表示名の数を混ぜ、表示名（`excel.labels`）が届いたら控えを捨てて描き直す（`catalog.ts` の `onLabelsLoaded`。idMso のコントロールは表示名で描くので、届く前の幅で見積もらないため） |
| グループを縮ませない | `.rb-group` は `flex-shrink: 0`。「自由」の幅で枠が狭いと、グループが押しつぶされて中のボタンが重なり、隣を押してしまうため（あふれた分は横スクロール） |
| 外枠の列 | `.center` は `grid-template-columns: minmax(0, 1fr)`・`min-width: 0`。指定しないと中身（リボン）の幅が列の最小幅になり、ペインを戻したり窓を狭めたりしてもキャンバスが縮まず、リボンがインスペクタの下に隠れ、「全体を表示」の縮小率も測り直されない。畳む→元に戻す、窓 1920→1366 で縮小率が測り直されることをブラウザで確かめた |
| ボタンの大きさ | 大きいボタンの高さを 66px（アイコン 32px）、小さいボタンを 22px にした（Excel と同じ）。大きいボタンのラベルの折り返し（幅 76px・2 行まで・文字単位で折る）は canvas.ts の `LARGE_LABEL_WRAP` で、**日本語の折り返し位置は実機で確かめていない**。centerVertically="true" はグループの中を縦の中央にそろえる |
| その他 | 自分のタブがないときの案内に「レシピから始める」を置いた。操作の説明（矢印キー・Enter・右クリック）は見出しの「キー操作」のツールチップに移した |

### 18.10 ツリー・インスペクタ・Lint（ツリーとインスペクタの持ち場）

| 項目 | 内容 |
| --- | --- |
| ツリーの絞り込み | ツリーの上の欄で絞り込む（ツリーの中で Ctrl+F、表示 メニューの「ツリーを絞り込む」でも移れる）。欄の中の案内は既定の幅で切れないよう「絞り込み」とだけ書き、対象はツールチップに出す。対象はラベル・id・idMso・idQ・imageMso・image・コールバック名。全角と半角、大文字と小文字は区別しない |
| ID の一括置換 | ツール メニューの「ID の一括置換…」。先頭だけ / 含まれるところすべて を選べる。変えるのは id 属性だけで、idMso と idQ は変えない。コールバック名は命名規則どおりのものだけを変え、VBA の Sub 名も変えるかは選べる。一度の編集（元に戻す 1 回で戻る）で行う。**VBA との関係**：VBA を読めていれば、古い id と同じ中身の文字列リテラル（`Case "btnRun"`・`InvalidateControl "btnRun"` など。コメントは除く）を探し、一覧の下に「VBA で直す必要がある箇所」（モジュール:行）として出す（`idReplace.ts` の `findIdLiteralsInVba`。一括置換は VBA の中の文字列を変えないため）。読めないときは、共有の Sub では Select Case control.Id の Case と InvalidateControl に古い id が残ることを強く知らせる。VBA を書き換えられないときは「コールバック名も変える」を既定で切り、入れたままなら見出しに「VBA 側の Sub 名は変わりません（XML とずれます）」と出す。VBA の Sub 名を変えたときは、完了の知らせに「元に戻しても VBA は戻りません」を添える |
| はじめての方へ・サンプル | ホーム画面の「はじめての方へ」と、同梱のサンプル（ファイル メニューの「サンプルを開く」）。サンプルはファイルがない（パスが空の）セッションで、保存も反映もできない（押すと理由を知らせる）。「バックアップから復元…」「VBAを再読み込みして照合」「マクロを Excel で試す」は理由を添えて無効にし、空のパスで `vba.*`・`backup.*`・`excel.apply`・`excel.runMacro` を送らない（`excel.setWindowWidth` はパスを付けずに送る）。ホストも空のパスを利用者向けの文言で断る（`MessageRouter.RequirePath`）。閉じるときの確認は「サンプルへの変更は保存できません。破棄しますか？」（破棄する / キャンセル）。変更したまま言語を切り替えるときは「保存してください」ではなく「サンプルへの変更は破棄されます」と確かめる。言語を切り替えた後に開き直す対象にもしない。ファイル名の欄には「サンプル」と出す |
| 「動的」の印 | getVisible / getEnabled が設定されている要素に付ける（キャンバスでは常に表示・有効として描くため、実際には変わることを示す） |
| ラベルの長さの警告 | 大きいボタンは全角を 2、半角を 1 と数えて 16 を超えたとき（2 行目で切れる可能性）。小さいボタンは 20 文字を超えたとき（グループの幅が広がり、狭い画面で畳まれやすい）。グループ・box・buttonGroup に直接置いたものだけを見る。showLabel="false" と getShowLabel のもの（splitButton の中は splitButton 側も）は見ない（ラベルを出さない・VBA で決まるので、長さで幅が変わらないため）。**どちらも実機の Excel で確かめていない目安** |
| アイコンの候補 | インスペクタで、ラベルや id からアイコンの候補を出す。アイコン集（Fluent UI System Icons）のデータは、候補を出すときに初めて読み込む（起動を遅くしないため） |

### 18.11 Windows 実機で確かめていないこと

`excel.setWindowWidth`（`Application.Width` が換算どおりの幅になるか、SDI でのウィンドウの選び方、複数モニター・DPI の違うモニターでの作業領域と `Left` の動かし方、ウィンドウの枠の分）、`excel.setWindowWidth` の測り直し（`GetWindowRect` の幅と期待の幅のずれ方、1 回の直しで合うか、ブックを前に出す前の `Window.Hwnd` でのモニターの決め方）、`excel.runMacro`（`Application.Run` の名前の書き方、`DispatchWrapper(null)` で control に Nothing が渡るか、アドインのマクロ、Excel を前に出す動き、実行中の印で他の要求をすぐに断る動き）、`vba.reveal`（VBE の表示・宣言の行をまるごと選ぶ動き・前に出す動き）、CSV を Excel で開いたときの文字化けしないこと、§18.8 の測定は、Linux 上のビルドと単体テスト、ブラウザ（モック）での確認までしか行っていない。
