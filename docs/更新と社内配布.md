# 更新と社内配布

Sash は、新しい版が出たら知らせ、利用者が同意したときだけダウンロード・照合・入れ替えを行います。会社のネットワークでも更新できるよう、次の三つの確認先に対応しています。

| 確認先 | 設定の値 | 向いている環境 |
| --- | --- | --- |
| GitHub のリリース（既定） | 空欄 | インターネットに出られる PC。社内のプロキシ経由でもよい |
| 社内の共有フォルダ | `\\fileserver\tools\Sash` など | インターネットに出られない PC。管理者が新しい版を置く |
| 社内の Web サーバー | `https://intra.example.com/tools/sash/latest.json` など | 共有フォルダを使わない社内配布 |

## 利用者の操作

- 起動時に新しい版があると、タイトルバーに「新しい版 x.y.z があります」と出ます。押すと内容を確認して「今すぐ更新」を選べます。
- 設定 →「更新」で、起動時の確認のオン・オフ、確認先の変更、「今すぐ確認」ができます。コマンドパレット（Ctrl+K）の「更新を確認」でも確認できます。
- 更新では exe だけを入れ替えます。設定・アイコンライブラリ・レシピ・バックアップ（`%AppData%\Sash`）には触れません。
- 入れ替えの前に、未保存の変更があれば保存するかを確認します。入れ替えが終わると Sash が再起動し、「x.y.z に更新しました」と知らせます。

## 会社のネットワークで通るようにした工夫

同じ作者の Graft・Pane が、社内の共有回線で実際に踏んだ不具合への対策に倣っています。

- **GitHub API を使わない。** API には未認証で1時間60回・IPアドレス単位の上限があり、社内の共有回線では他の人の通信で先に使い切られます。新しい版の確認は上限の対象外の Atom フィード（`releases.atom`）で行い、配布物の URL は規則どおりに組み立てます。
- **照合値は添付ファイルから取る。** リリースに `Sash-<版>-win-x64.exe.sha256` を添付し、通常のダウンロードで取ります。照合値が取れないときや一致しないときは入れ替えません。
- **プロキシに従う。** Windows のプロキシ設定（PAC を含む）に従い、認証が必要なプロキシにはサインイン中の Windows の資格情報で応答します。プロキシを経由したかどうかは `%AppData%\Sash\logs\update.log` に残ります（資格情報の中身は残しません）。
- **書き込めない場所では入れ替えない。** `Program Files` など exe のフォルダに書き込めない場合は、配布元のページ（共有フォルダ）を開く案内だけを出します。

## 管理者向け：社内の共有フォルダから配る

1. GitHub のリリースから `Sash-<版>-win-x64.exe` をダウンロードする。
2. `tools/Publish-Internal.ps1` で共有フォルダに置く。exe・照合値ファイル・`latest.json` の三つができる。

   ```powershell
   .\tools\Publish-Internal.ps1 -Exe .\Sash-0.2.0-win-x64.exe -Destination \\fileserver\tools\Sash -Notes "変更内容"
   ```

   スクリプトを使わない場合は、リリースに添付されている `latest.json` と exe と `.sha256` の三つを、そのまま共有フォルダにコピーしても構いません。
3. 利用者の Sash の確認先を、その共有フォルダにする。方法は次のどちらか。
   - 利用者が設定 →「更新」→「確認先」に `\\fileserver\tools\Sash` を入れる。
   - **管理者がまとめて決める**：配る `Sash.exe` の横に `Sash.update.json` を置く。ここで決めた値は利用者の設定より優先され、設定画面では変更できなくなる。

     ```json
     {
       // 社内の共有フォルダから更新する
       "source": "\\\\fileserver\\tools\\Sash",
       "checkOnStartup": true
     }
     ```

     更新を止めたい場合は `{ "disabled": true }` にする。このファイルが壊れているときも、意図しない確認先へ行かないよう更新を止める。

`latest.json` の形式：

```json
{
  "version": "0.2.0",
  "file": "Sash-0.2.0-win-x64.exe",
  "sha256": "64桁の16進",
  "notes": "変更内容（任意）"
}
```

`file` には `latest.json` と同じ場所にあるファイルの名前だけを書きます。別のフォルダや別のホストを指すものは、確認先を書き換えられたときに別の配布物を入れられないよう、受け付けません。確認先に `http://` は使えません（`https://` か共有フォルダ）。

## 開発者向け：リリースの作り方

[リリース手順.md](リリース手順.md) を参照してください。`v*` のタグを push すると、`.github/workflows/release.yml` が `Sash-<版>-win-x64.exe`・`.sha256`・`latest.json` を添付したリリースを下書きで作り、内容を確かめて公開するのは人が行います。利用者の Sash が新しい版を見つけるのは、公開したあとです。
